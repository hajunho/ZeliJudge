# 펜윅 트리 (Fenwick Tree / Binary Indexed Tree, BIT)

### 1. 왜 펜윅 트리인가?
일반 배열에서:
- 특정 원소 값 변경: $O(1)$
- 구간 합 계산: $O(N)$
누적 합(Prefix Sum) 배열에서:
- 구간 합 계산: $O(1)$
- 특정 원소 값 변경 시 이후 모든 누적 합 갱신: $O(N)$

수열의 값이 실시간으로 계속 변경되는 동적 환경에서, 세그먼트 트리와 펜윅 트리는 두 연산을 모두 **$O(\log N)$**에 수행합니다.
특히 펜윅 트리는 세그먼트 트리보다 **구현 코드가 4배 이상 짧고 메모리를 원본 배열 크기만큼만 사용($O(N)$)**하는 극도의 효율성을 자랑합니다.

### 2. $i \mathrel{\&} (-i)$ 비트 연산의 마법
2의 보수 표현법에서 음수 $-i$는 `~i + 1`입니다.
따라서 `i & -i`는 $i$의 이진수 표현에서 **가장 마지막으로 켜져 있는 1의 비트(LSB, Least Significant Bit)** 값만을 남깁니다.
- `tree[i]`는 구간 `(i - (i & -i), i]`의 부분합을 저장합니다.
- 누적 합 $S(i) = A_1 + \dots + A_i$를 구할 때는 `i -= (i & -i)`를 반복하여 조상으로 거슬러 올라갑니다.
- 특정 원소 $A_i$가 변했을 때는 `i += (i & -i)`를 반복하여 영향받는 상위 노드들만 갱신합니다.
