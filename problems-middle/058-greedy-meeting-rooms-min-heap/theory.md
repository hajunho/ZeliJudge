# 최소 회의실 배정과 우선순위 큐(Min-Heap)

### 1. 활동 선택(028번)과의 차이점
- **활동 선택 문제(028번)**: 회의실이 1개뿐일 때 겹치지 않게 '최대 몇 개의 회의를 할 수 있는가?' (종료 시간 기준 정렬)
- **최소 회의실 문제(본 문제)**: 모든 회의를 다 해야 할 때 '최소 몇 개의 방이 필요한가?' (시작 시간 기준 정렬 + 힙)

---

### 2. 탐욕 알고리즘과 최소 힙의 조화
1. **시작 시간 순 정렬**: 먼저 시작하는 회의부터 차례대로 배정합니다.
2. **최소 힙(Min-Heap)**: 현재 사용 중인 각 회의실의 **종료 시간**을 힙에 담아 관리합니다.
   - 새 회의의 시작 시간 $s$가 가장 일찍 끝나는 회의실의 종료 시간(`heap[0]`)보다 크거나 같다면 $\to$ 그 방이 비었으므로 이어 씁니다 (`heappop`).
   - 그렇지 않다면 $\to$ 새 회의실을 하나 더 개설해야 합니다!
   - 새 회의의 종료 시간 $e$를 힙에 넣습니다 (`heappush`).
3. 모든 회의를 처리한 후 **힙에 남아있는 원소의 개수가 곧 필요한 최소 회의실 수**가 됩니다!
