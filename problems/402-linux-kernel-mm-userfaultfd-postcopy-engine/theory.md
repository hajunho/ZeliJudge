# 402: 리눅스 커널 메모리 관리 — userfaultfd 포스트 카피(Post-Copy) 마이그레이션과 사용자 공간 폴트 처리 이론

## 1. 실시간 가상 머신 마이그레이션의 패러다임 전환

가상 머신 마이그레이션 기법은 크게 **프리 카피(Pre-Copy)** 와 **포스트 카피(Post-Copy)** 로 나뉩니다:

### 1.1 프리 카피의 한계 (Pre-Copy Non-Convergence)
프리 카피는 소스 호스트에서 게스트 VM을 멈추지 않고 백그라운드로 메모리를 반복 복사합니다. 그러나 게스트 VM이 메모리를 수정하는 속도(Dirtying Rate)가 네트워크 전송 대역폭(Network Transfer Rate)보다 빠를 경우:
$$	ext{Dirty Rate} > 	ext{Transfer Bandwidth}$$
남은 더티 페이지 수가 줄어들지 않아 마이그레이션이 영원히 수렴하지 못하고 실패합니다.

### 1.2 포스트 카피의 절대적 수렴성 (Deterministic Convergence)
포스트 카피는 vCPU의 실행을 즉시 대상 호스트로 넘깁니다:
1. 소스 호스트는 전체 메모리를 백그라운드로 순차 전송(Background Pushing)합니다.
2. 대상 호스트의 vCPU가 아직 전송되지 않은 페이지를 읽으려 하면, 하드웨어 페이지 폴트가 발생합니다.
3. 대상 호스트는 해당 페이지를 소스에 네트워크로 즉각 요구(On-Demand Paging)하여 수신받습니다.
모든 페이지는 네트워크를 통해 단 한 번만 전송되므로, 워크로드의 쓰기 강도와 무관하게 **전체 전송 시간은 $T = 	ext{RAM Size} / 	ext{Bandwidth}$로 확정(Deterministic)** 됩니다.

## 2. userfaultfd (`fs/userfaultfd.c`)의 아키텍처

전통적인 유닉스 커널에서 페이지 폴트는 무조건 커널 공간 내부의 가상 메모리 관리자(`handle_mm_fault()`)만이 처리할 수 있었습니다. 만약 매핑되지 않은 페이지에 접근하면 커널은 프로세스에 `SIGSEGV` 시그널을 보내 즉시 강제 종료시켰습니다.

### 2.1 커널-유저 공간 폴트 위임 (Fault Delegation)
안드레아 아르칸젤리(Andrea Arcangeli)가 고안한 `userfaultfd`는 특정 VMA 범위를 등록(`UFFDIO_REGISTER`)하면, 해당 주소에서 발생하는 페이지 폴트를 프로세스 종료 대신 파일 디스크립터 이벤트(`UFFD_EVENT_PAGEFAULT`)로 변환하여 유저 공간으로 위임합니다:
- **스레드 블로킹**: 폴트를 일으킨 스레드는 커널 내 대기 큐에서 안전하게 슬립(Sleep) 상태로 대기합니다.
- **원격 페이징**: 유저 공간 데몬(QEMU)은 분산 네트워크, 원격 스토리지(NFS/RDMA), CXL 패브릭 등 임의의 소스로부터 데이터를 가져옵니다.
- **원자적 주입**: `UFFDIO_COPY`를 통해 유저 공간의 버퍼 데이터를 게스트 페이지에 원자적으로 복사하고, PTE 권한을 설정한 뒤 대기 스레드를 즉시 깨워 재개합니다.

### 2.2 사용자 공간 쓰기 보호 (`UFFDIO_WRITEPROTECT`)
`UFFD_FEATURE_PAGEFAULT_FLAG_WP` 플래그를 활성화하면 사용자 공간에서 임의의 페이지를 쓰기 금지할 수 있습니다. 스레드가 해당 페이지에 쓰기를 시도하면 커널이 이를 가로채 유저 공간에 알립니다.
이는 하이퍼바이저의 더티 페이지 추적, 데이터베이스의 변경 로그(WAL) 생성, 애플리케이션 체크포인팅(CRIU)을 커널 코드 수정 없이 유저 공간에서 고속으로 구현할 수 있는 토대가 됩니다.

---

## 3. 결론

userfaultfd는 커널의 전유물이었던 가상 메모리 페이징 메커니즘을 유저 공간으로 개방한 현대 운영체제의 가장 유연하고 강력한 프리미티브입니다.
본 시뮬레이터는 이러한 누락 페이지 가로채기, 동시 대기 스레드 일괄 기상, 제로 페이지 매핑, 쓰기 보호 상태 전이의 핵심 규칙을 100% 충실하게 모델링합니다.
