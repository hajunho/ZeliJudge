# 📘 [CS 이론 #011] 지웠는데 왜 건너뛰어?: 반복문 중 원소 삭제와 인덱스 시프트

> **"리스트를 돌면서 remove()로 지웠는데 왜 나란히 있던 단어는 안 지워지고 건너뛸까?"**  
> 배열(Array)의 연속 메모리 구조와 '기차 좌석' 비유로 이해하는 인덱스 시프트(Index Shift)의 비밀.

---

## 1. 전 세계 초보자가 100% 겪는 미스터리

파이썬을 배운 지 얼마 안 된 주니어 개발자나 AI 코딩 도구는 리스트에서 특정 원소들을 걸러낼 때 무의식적으로 다음과 같은 코드를 짭니다:

```python
words = ["좋은글", "스팸", "스팸", "감사합니다"]

for w in words:
    if w == "스팸":
        words.remove(w)

print(words)  # 결과: ['좋은글', '스팸', '감사합니다'] ──► 어?! 스팸이 왜 남아있지?!
```

"모든 원소를 검사해서 스팸이면 지워라"라는 너무나 명확한 명령인데, **왜 두 번째 '스팸'은 버젓이 살아남았을까요?**

컴퓨터가 고장 난 것이 아닙니다.  
**배열(Array)이 메모리에 저장되는 물리적 방식과 `for` 문의 커서(인덱스 포인터)가 움직이는 타이밍** 때문입니다.

---

## 2. 기차 좌석 비유: 인덱스 시프트(Index Shift)의 실체

컴퓨터 메모리에서 리스트는 **중간에 빈 의자를 허용하지 않는 일렬로 연결된 '기차 좌석'**과 같습니다:

```
[ 초기 상태 ]
좌석 번호:   [ 0번 칸 ]       [ 1번 칸 ]       [ 2번 칸 ]       [ 3번 칸 ]
앉은 승객:    "좋은글"         "스팸1"          "스팸2"         "감사합니다"
커서 위치:   ▲ (0번 검사: 스팸 아님, 통과!)
```

### 1단계: 커서가 1번 칸으로 이동
`for` 문의 커서는 다음 순서인 **1번 칸**을 검사합니다.
* 1번 칸에 `"스팸1"`이 앉아 있습니다. 스팸이 맞으므로 `words.remove("스팸1")`을 실행합니다.

```
좌석 번호:   [ 0번 칸 ]       [ 1번 칸 ]       [ 2번 칸 ]       [ 3번 칸 ]
앉은 승객:    "좋은글"        [ 빈자리! ]       "스팸2"         "감사합니다"
커서 위치:                    ▲ (1번 검사 완료, 삭제!)
```

### 2단계: 뒤쪽 승객들이 앞으로 당겨 앉음 (인덱스 시프트!)
배열은 중간에 구멍이 뚫리는 것을 허용하지 않습니다.  
따라서 빈 1번 자리를 메우기 위해 **뒤에 앉아있던 모든 승객이 한 칸씩 앞으로 당겨 앉습니다(Shift Left)**:

```
좌석 번호:   [ 0번 칸 ]       [ 1번 칸 ]       [ 2번 칸 ]
앉은 승객:    "좋은글"         "스팸2"         "감사합니다"  (뒤에서 1칸씩 앞으로 당겨짐!)
```
**주목하세요! 2번 칸에 있던 `"스팸2"`가 이제 `1번 칸`으로 자리를 옮겼습니다!**

### 3단계: 커서는 무자비하게 다음 자리(2번 칸)로 전진!
`for` 문은 방금 1번 칸을 검사했으니, 기계적으로 다음 순서인 **2번 칸**으로 커서를 옮깁니다:

```
좌석 번호:   [ 0번 칸 ]       [ 1번 칸 ]       [ 2번 칸 ]
앉은 승객:    "좋은글"         "스팸2"         "감사합니다"
커서 위치:                                     ▲ (2번 칸 검사: 스팸 아님, 종료!)
```

결과가 보이시나요?  
**1번 자리로 당겨 앉은 `"스팸2"`는 커서의 검사를 단 한 번도 받지 못하고 투명인간처럼 쏙 건너뛰어진 것(Skipped)입니다!**

이 현상을 컴퓨터 과학에서는 **'인덱스 시프트(Index Shift)로 인한 반복문 건너뛰기 버그'**라고 부릅니다.

---

## 3. `list.remove()`의 또 다른 비극: $O(N^2)$ 성능 재앙

이 방식은 버그만 있는 것이 아닙니다. 성능 면에서도 최악의 재앙입니다:

1. `words.remove(w)`를 호출하면 파이썬은 해당 단어를 찾기 위해 **리스트 맨 앞부터 다시 훑습니다 ($O(N)$ 탐색)**.
2. 단어를 찾아서 지우면 **뒤에 있는 모든 원소를 앞으로 1칸씩 복사하며 당깁니다 ($O(N)$ 메모리 복사)**.
3. 이것을 $N$번 반복하면 전체 시간 복잡도는 **$O(N^2)$**이 됩니다!

10만 개의 단어 리스트에서 이 짓을 하면 **100억 번의 연산**이 발생하여 컴퓨터가 수 분 동안 멈춰버립니다.

---

## 4. 올바른 엔지니어링 해결책 2가지

### 해결책 A: "지우지 말고, 남길 것만 새 바구니에 담아라!" (가장 추천!)
실무에서 가장 빠르고, 파이썬다운 정석 방법은 기존 리스트를 지우려 애쓰지 말고 **"살릴 단어만 골라 새 리스트에 담는 것(List Comprehension)"**입니다:

```python
# [정석 코드: 단 1줄, 100% 안전, O(N) 초고속]
clean_words = [w for w in words if w != "스팸"]
```
* 기존 리스트의 자리를 바꾸지 않으므로 건너뛰기 버그가 물리적으로 일어날 수 없습니다.
* $N$개의 단어를 딱 1번만 훑고 지나가므로 시간 복잡도는 완벽한 **$O(N)$ (0.01초 만에 완료)**입니다.

### 해결책 B: 제자리(In-place) 수정이 꼭 필요하다면? "뒤에서부터 거꾸로 지워라!"
메모리가 극도로 부족하여 기존 리스트 자체를 수정해야 한다면, **맨 뒤 인덱스부터 거꾸로 역순 순회(Reverse Iteration)**해야 합니다:

```python
# 뒤에서부터 지우면 앞쪽 인덱스가 흔들리지 않습니다!
for i in range(len(words) - 1, -1, -1):
    if words[i] == "스팸":
        del words[i]
```
뒤쪽 의자를 치워도 앞쪽에 앉아있는 승객들의 번호는 전혀 바뀌지 않으므로, 어떤 단어도 건너뛰어지지 않습니다.

---

## 💡 AI 바이브 코더를 위한 실무 체크리스트
1. **`for x in my_list:` 안에서 `my_list.remove(x)`나 `del my_list[i]`를 절대 쓰지 마세요.** 100% 원소 건너뛰기 버그가 발생합니다.
2. **필터링이 필요할 땐 무조건 리스트 컴프리헨션 `[x for x in list if 조건]`을 쓰세요.** 가장 읽기 쉽고, 가장 안전하며, 가장 빠릅니다.
3. **딕셔너리도 마찬가지입니다.** `for k in my_dict:` 안에서 딕셔너리 키를 삭제하면 파이썬은 즉시 `RuntimeError: dictionary changed size during iteration` 에러를 던지며 멈춥니다.
