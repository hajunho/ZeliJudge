# 📘 [CS 이론 #010] 복사했는데 왜 둘 다 바뀌어?: 얕은 복사(Shallow Copy)와 참조

> **"b = a.copy()로 분명 복사했는데, 왜 b를 바꿨더니 a까지 같이 바뀌었을까?"**  
> AI 바이브 코더가 가장 먼저 멘붕을 겪는 파이썬 제1의 미스터리, 변수와 메모리 참조의 진실.

---

## 1. 초보자의 가장 큰 착각: "변수는 상자(Box)다?"

코딩을 처음 배울 때 많은 입문서와 AI는 변수를 설명하며 이렇게 비유합니다:
> *"변수는 데이터를 담아두는 '상자'입니다. `a = [10, 20]`은 a 상자 안에 10과 20을 넣은 것입니다."*

**이 설명 때문에 수많은 바이브 코더들이 피눈물을 흘립니다.**  
컴퓨터 메모리의 실제 동작은 상자와 완전히 다릅니다!

### 변수의 진짜 정체: "포스트잇 (메모리 주소 스티커)"
컴퓨터 안에서 실제 데이터(리스트, 딕셔너리, 객체)는 광활한 램(RAM) 메모리의 특정 주소(예: `100번지`)에 만들어집니다.  
그리고 변수 `a`는 그 데이터를 담고 있는 상자가 아니라, **"저기 100번지에 데이터가 있다"고 가리키는 포스트잇(참조, Reference)**에 불과합니다.

```
[ 컴퓨터 메모리 (RAM) ]
메모리 100번지:  [ 10, 20 ]  ◄── 포스트잇 'a' 가 붙어있음!
```

---

## 2. `b = a`를 했을 때 일어나는 비극

AI에게 *"a를 복사해서 b를 만들어줘"*라고 했더니 `b = a`를 써주었다면 무슨 일이 벌어질까요?

```python
a = [10, 20]
b = a          # 복사한 걸까?
b[0] = 99
print(a)       # [99, 20]  <- a도 바뀌어 있음!
```

컴퓨터는 새로운 리스트를 만들지 않았습니다!  
그저 **100번지 데이터에 포스트잇 'b'를 하나 더 붙였을 뿐**입니다:

```
[ 컴퓨터 메모리 (RAM) ]
메모리 100번지:  [ 99, 20 ]  ◄── 포스트잇 'a' 와 'b' 가 둘 다 붙어있음!
```

`b[0]`을 바꾼 것은 **100번지 집에 찾아가서 가구를 바꾼 것**이므로, `a` 포스트잇을 보고 찾아가도 바뀐 가구가 보이는 것은 너무나 당연합니다.

## 3. 얕은 복사(Shallow Copy)의 은밀한 배신: 껍데기만 복사!

*"아, 그래서 `copy()` 함수를 써야 하는 거구나!"*  
지민이는 AI의 조언대로 `b = a.copy()` 또는 `b = a[:]`를 썼습니다.

1차원 숫자 리스트(`[1, 2, 3]`)에서는 잘 동작합니다.  
하지만 게임 인벤토리, 장바구니, 표 데이터처럼 **리스트 안에 또 리스트나 딕셔너리가 들어있는 2차원 구조**가 되는 순간 지옥문이 열립니다:

```python
a = [ [101, 10], [102, 5] ]  # 2차원 인벤토리
b = a.copy()                 # 얕은 복사!

b[0][1] = 999                # b의 0번 슬롯 수량을 변경

print(a[0][1])               # 999  <- 어?! a도 바뀌어버렸다!
```

### 왜 `copy()`를 썼는데도 원본이 오염될까요?
이것이 바로 **얕은 복사(Shallow Copy)**의 본질입니다:
* `b = a.copy()`는 **가장 바깥쪽 큰 껍데기 리스트만 새로 만듭니다.** (새로운 200번지 할당)
* 하지만 그 안에 담긴 **알맹이 슬롯 `[101, 10]`의 메모리 주소(300번지)는 그대로 복사해서 새 껍데기에 집어넣습니다!**

```
[ a의 서랍 ] ──► 0번 칸: [300번지 주소] ──┐
                                          ├──► [메모리 300번지: 101번 아이템 10개]
[ b의 서랍 ] ──► 0번 칸: [300번지 주소] ──┘
```

결국 큰 서랍(`a`, `b`)은 2개로 분리되었지만, **서랍 안의 내용물은 여전히 똑같은 300번지 물건을 함께 쳐다보고 있었던 것**입니다!

## 4. 해결책: 진짜 복사, 깊은 복사(Deep Copy)

내부의 모든 자식 요소까지 완전히 독립된 새로운 메모리 공간으로 복제하는 것을 **깊은 복사(Deep Copy)**라고 합니다.

### 방법 1: `copy.deepcopy()` 모듈 사용 (가장 간단)
```python
import copy
b = copy.deepcopy(a)  # 껍데기부터 알맹이까지 전부 재귀적으로 새 메모리에 복제!
```
이제 `b[0][1] = 999`를 수정해도 `a`는 완벽하게 안전합니다.

### 방법 2: 리스트 컴프리헨션 복제 (실무 초고속 테크닉)
`copy.deepcopy()`는 매우 안전하지만, 내부적으로 객체 타입을 일일이 검사하느라 **연산 속도가 상당히 느립니다.**  
실무에서 2차원 리스트나 딕셔너리 리스트를 빠르게 복제할 때는 **리스트 컴프리헨션**을 사용하는 것이 **10배 이상 빠릅니다**:

```python
# 내부 슬롯까지 각각 독립 복사: O(N) 초고속
b = [slot.copy() for slot in a]
# 또는
b = [[item_id, count] for item_id, count in a]
```

## 5. 파이썬 객체의 가변(Mutable) vs 불변(Immutable) 총정리

내가 다루는 데이터가 복사할 때 안전한지 위험한지는 이 표 하나로 끝납니다:

| 종류 | 자료형 | 복사 시 특성 |
|---|---|---|
| **불변 객체 (Immutable)** | `int`, `float`, `str`, `tuple`, `bool` | 값이 바뀔 수 없으므로 `b = a`로 주소만 복사해도 **100% 안전**함 (수정 시도시 새 객체 생성) |
| **가변 객체 (Mutable)** | `list`, `dict`, `set`, 사용자 정의 클래스 | 내용이 언제든 바뀔 수 있으므로 주소 복사 시 **원본 오염 위험! 반드시 복사 방식 주의** |

## 💡 AI 바이브 코더를 위한 실무 체크리스트
1. **리스트나 딕셔너리를 백업할 때 절대 `b = a`를 쓰지 마세요.** 그것은 복사가 아니라 별명(Alias)을 하나 더 붙인 것에 불과합니다.
2. **2차원 배열이나 객체 리스트는 `copy()`나 `[:]`로 안 됩니다.** 내부 원소까지 독립시키려면 `[x.copy() for x in a]`나 `copy.deepcopy()`를 쓰세요.
3. **함수의 기본 인자(Default Argument)로 빈 리스트 `def fn(items=[]):`를 절대 쓰지 마세요.** 모든 호출자가 동일한 리스트 메모리 주소를 공유하는 초대형 참사가 일어납니다. (대신 `items=None` 사용)
