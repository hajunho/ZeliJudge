# 010. 복사했는데 왜 둘 다 바뀌어?: 얕은 복사(Shallow Copy)와 참조의 덫

* **난이도**: Lv.1 (초심자 필독 / 바이브 코더 필수)
* **카테고리**: 메모리 참조(Reference), 포인터, 얕은 복사(Shallow Copy) vs 깊은 복사(Deep Copy), 가변 객체
* **시간 제한**: 1.0초
* **메모리 제한**: 256 MB
* **핵심 CS 이론**: [theory.md 읽으러 가기](theory.md)

## 📖 실무 버그 시나리오

비전공자로 AI 코딩 도구를 활용해 RPG 모바일 게임을 만들던 주니어 개발자 지민이는 "아이템 강화 시뮬레이터"를 개발했습니다.

유저가 비싼 장비를 강화하기 전에, 가상으로 강화 확률과 능력치를 미리 테스트해 볼 수 있는 기능이었습니다.  
지민이는 AI에게 다음과 같이 요청했습니다:

> *"유저의 현재 인벤토리 데이터를 복사해서 임시 가상 인벤토리를 만들고, 거기서 수량을 조작해 본 뒤 유저가 '적용'을 누르면 원본에 반영하고, '취소'를 누르면 그냥 버리도록 해줘."*

AI는 지민이에게 다음과 같은 파이썬 코드를 작성해 주었습니다:

```python
# AI가 작성해 준 코드
def simulate_upgrade(inventory):
    # 인벤토리 복사본 만들기
    sim_inventory = inventory.copy() # 또는 list(inventory)
    
    # 0번 슬롯 아이템의 수량을 1개 소모하고 강화 시도
    sim_inventory[0][1] -= 1
    
    # 유저가 '취소'를 눌렀다면?
    # 아무것도 안 하고 함수를 끝내면 원본 inventory는 그대로겠지?
    return "CANCELED"
```

지민이는 안심하고 유저가 강화를 취소했을 때 원본 인벤토리를 확인했습니다.  
그런데 경악할 일이 벌어졌습니다:

> **"분명 강화를 '취소'했는데, 왜 원본 인벤토리의 0번 슬롯 아이템 수량까지 같이 깎여있는 거지?!"**

지민이는 자신이 실수를 했나 싶어 `sim_inventory = inventory[:]`로 슬라이싱 복사도 해보고, `sim_inventory = list(inventory)`로 형변환도 해보았지만, **복사본의 내부 값을 바꿀 때마다 원본까지 귀신 들린 것처럼 똑같이 바뀌었습니다.**

지민이는 "파이썬이 고장 났나?"라며 밤을 새웠습니다.

도대체 지민이의 코드에는 무슨 문제가 있었던 걸까요?

AI는 `copy()`나 `[:]` 같은 문법을 알려주었지만, **컴퓨터가 데이터를 저장하는 원리인 '메모리 주소(참조, Reference)'와 껍데기만 복사하는 '얕은 복사(Shallow Copy)'의 치명적인 함정**을 전혀 설명해 주지 않았던 것입니다.

## 🎯 문제 설명

게임 인벤토리의 슬롯 개수 $N$개가 주어집니다.
각 슬롯 $i$는 `[item_id, count]` 형태의 2차원 리스트로 구성됩니다. (슬롯 번호는 $0$번부터 $N-1$번까지입니다)

초기 원본 인벤토리 상태가 주어지고, 이어서 $M$개의 인벤토리 관리 명령어가 순차적으로 주어집니다:

1. **`FORK`**:
   * 현재 원본 인벤토리를 바탕으로 **독립적인 가상 시뮬레이션 인벤토리**를 하나 생성합니다. (기존에 작업 중이던 가상 인벤토리가 있다면 덮어씁니다)
   * **⚠️ 주의**: 이때 가상 인벤토리를 조작하더라도 **원본 인벤토리는 절대 영향을 받아서는 안 됩니다.**
2. **`MODIFY slot count`**:
   * 현재 작업 중인 **가상 시뮬레이션 인벤토리**의 `slot` 번호 아이템 수량에 `count`를 더합니다. (음수면 감소)
   * `count`를 더한 후 수량이 $0$ 미만이 되면 $0$으로 고정합니다.
3. **`COMMIT`**:
   * 현재 가상 시뮬레이션 인벤토리의 모든 슬롯 상태를 **원본 인벤토리에 최종 반영(덮어쓰기)**하고 가상 세션을 종료합니다.
4. **`ROLLBACK`**:
   * 현재 가상 시뮬레이션 인벤토리의 모든 변경 사항을 **취소하고 버립니다.** (원본 인벤토리는 원래 상태 그대로 유지되어야 합니다)

모든 $M$개의 명령어를 처리한 후, **최종 원본 인벤토리**의 모든 슬롯 상태를 $0$번 슬롯부터 $N-1$번 슬롯까지 출력하세요.

---

## 📥 입력 형식 (Input)

* **첫째 줄**: 인벤토리 슬롯 수 $N$과 명령어 수 $M$이 공백으로 구분되어 주어집니다. ($1 \le N \le 10,000$, $1 \le M \le 100,000$)
* **둘째 줄부터 $N$개의 줄**: 각 줄에 $i$번째 슬롯의 초기 `item_id`와 `count`가 공백으로 구분되어 주어집니다. ($0 \le \text{item\_id}, \text{count} \le 1,000,000$)
* **그 다음 줄부터 $M$개의 줄**: 각 줄에 명령어가 주어집니다.
  * `FORK`
  * `MODIFY slot count` ($0 \le slot < N$, $-1,000,000 \le count \le 1,000,000$)
  * `COMMIT`
  * `ROLLBACK`

---

## 📤 출력 형식 (Output)

* 최종 원본 인벤토리의 각 슬롯의 `item_id`와 `count`를 $0$번 슬롯부터 $N-1$번 슬롯까지 한 줄에 하나씩 공백으로 구분하여 총 $N$줄에 걸쳐 출력합니다.

## 💡 예제 1

### 입력
```text
3 6
101 10
102 5
103 20
FORK
MODIFY 0 -3
ROLLBACK
FORK
MODIFY 1 10
COMMIT
```

### 출력
```text
101 10
102 15
103 20
```

### 힌트
* 초기 원본: `[[101, 10], [102, 5], [103, 20]]`
* `FORK` $\rightarrow$ 가상 인벤토리 복제 생성
* `MODIFY 0 -3` $\rightarrow$ 가상 인벤토리의 0번 슬롯이 `[101, 7]`로 변경됨.
  * *(만약 얕은 복사를 했다면 원본 0번 슬롯까지 7로 오염됩니다!)*
* `ROLLBACK` $\rightarrow$ 취소! 원본은 원래대로 `101 10`이어야 함.
* `FORK` $\rightarrow$ 다시 가상 인벤토리 복제 생성
* `MODIFY 1 10` $\rightarrow$ 가상 인벤토리의 1번 슬롯 수량이 `5 + 10 = 15`로 변경됨.
* `COMMIT` $\rightarrow$ 최종 반영! 원본 1번 슬롯이 15로 확정됨.
* 최종 출력: 0번은 10, 1번은 15, 2번은 20.

---

## 🔍 채점 엣지케이스 안내
1. 얕은 복사(`copy()`, `[:]`)를 사용하여 `ROLLBACK` 이후에도 원본 데이터가 오염되는 버그 저격
2. `copy.deepcopy()`를 너무 무식하게 루프마다 호출하여 시간 초과(TLE)가 발생하는 케이스 방어
3. `MODIFY` 시 수량이 음수가 되지 않고 0으로 정상 클램핑되는지 여부
