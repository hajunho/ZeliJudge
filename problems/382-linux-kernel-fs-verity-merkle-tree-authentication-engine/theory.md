# Linux 커널 스토리지 및 보안: fsverity 파일 무결성 및 머클 트리 아키텍처

## 1. 개요 및 배경

현대 운영체제 보안(Security Architecture)에서 가장 중요한 요구사항 중 하나는 **신뢰 체인(Chain of Trust)**을 부트로더에서 커널, 그리고 사용자 공간 바이너리와 애플리케이션으로 이어가는 것입니다.

기존 Linux 환경에서는 두 가지 주요 무결성 솔루션이 사용되었습니다:
1. **`IMA(Integrity Measurement Architecture)`**:
   - 파일이 `open()`되거나 `execve()`될 때 파일 전체를 처음부터 끝까지 읽어 SHA-256 해시를 계산합니다.
   - 단점: 1GB 크기의 안드로이드 게임 APK나 5GB 크기의 AI 가중치 파일을 실행할 때마다 전체 해시를 계산하느라 시스템이 멈추는 실행 지연이 발생하며, 파일이 메모리에 로드된 후 디스크 블록이 조작되는 런타임 변조를 방지하지 못합니다.
2. **`dm-verity`**:
   - 디바이스 매퍼(Device Mapper) 계층에서 블록 단위로 머클 트리를 검증합니다.
   - 단점: 개별 파일이 아닌 전체 블록 디바이스(파티션)를 통째로 읽기 전용 이미지로 묶어야 하므로, 개별 앱 설치나 동적 모듈 업데이트가 불가능합니다.

Linux 커널 5.4에서 도입된 **`fsverity`**(`fs/verity/`)는 이 두 방식의 장점만을 결합하여, **일반 읽기/쓰기 파일시스템(ext4, f2fs, btrfs) 위에서 개별 파일 단위로 상주하면서도, 4KB 페이지 온디맨드 검증을 수행하는 혁신적인 VFS 계층 무결성 아키텍처**를 완성했습니다.

## 2. 머클 트리(Merkle Tree) 구조 및 온디맨드 검증 원리

### 2.1 트리 구조와 Arity 계산
- 파일 데이터는 $4096\text{ 바이트}$ 블록 단위로 분할됩니다.
- SHA-256 해시의 크기는 $32\text{ 바이트}$이므로, 하나의 4KB 해시 페이지에는 정확히 $4096 / 32 = 128\text{개}$의 자식 해시가 수용됩니다. 즉, 트리의 분기율(Arity)은 $128$입니다.
- 레벨 $0$: 파일 데이터의 각 4KB 블록에 대한 해시 배열.
- 레벨 $1$: 레벨 $0$의 해시들을 128개씩 묶어 다시 해시한 상위 해시 배열.
- 최상위 레벨: 단일 $32\text{ 바이트}$ 해시인 **루트 해시(Root Hash)**.

$$\text{Total Overhead} \approx \sum_{k=1}^{\infty} \left(\frac{1}{128}\right)^k = \frac{1/128}{1 - 1/128} = \frac{1}{127} \approx 0.787\%$$
이처럼 파일 크기가 아무리 커져도 머클 트리가 차지하는 저장 공간 오버헤드는 원본 파일의 $0.8\%$ 미만으로 극히 미미합니다.

### 2.2 페이지 캐시와 PageChecked 플래그
- 유저 프로세스가 `read()` 또는 메모리 매핑(`mmap`)을 통해 특정 4KB 데이터 페이지를 요청하면:
  1. 파일시스템은 디스크에서 해당 4KB 데이터 블록을 읽어 페이지 캐시(Page Cache)에 적재합니다.
  2. 커널은 해당 페이지 구조체(`struct page`)의 `PageChecked` 플래그를 검사합니다.
  3. 플래그가 이미 설정되어 있다면 이전에 이미 검증이 완료된 페이지이므로 **해시 계산을 완전히 생략하고 0ns 지연시간으로 즉시 반환**합니다.
  4. 플래그가 꺼져 있다면, 데이터 블록의 SHA-256 해시를 계산하고 머클 트리의 상위 부모 해시와 일치하는지 대조합니다.
  5. 검증에 통과하면 `SetPageChecked(page)`를 마킹하고 데이터를 유저 버퍼로 복사합니다.
  6. 만약 디스크 결함이나 변조로 인해 해시가 불일치하면, 커널은 즉시 `-EIO` 에러를 반환하고 커널 감사 로그(audit log)에 보안 경고를 기록합니다.

## 3. 내장 서명(Built-in Signatures)과 커널 키링 연동

`fsverity`는 파일의 루트 해시를 공개키 암호화 방식으로 전자서명(PKCS#7 / X.509)할 수 있는 내장 서명 기능을 지원합니다:
- `fsverity enable` 명령 실행 시 서명 파일(`file.sig`)을 함께 전달합니다.
- 커널의 `fs/verity/signature.c`는 시스템 부팅 시 로드된 **`.fs-verity` 신뢰 키링(Keyring)**의 인증서 목록을 조회합니다.
- 루트 해시 서명이 신뢰할 수 있는 인증 기관(CA)의 개인키로 생성되었는지 검증하며, 유효하지 않은 서명이거나 알 수 없는 키인 경우 파일 잠금 활성화를 `-EKEYREJECTED` 또는 `-ENOKEY`로 즉각 거부합니다.
- 이를 통해 공격자가 임의의 변조된 파일에 대해 자체적으로 머클 트리를 새로 계산하여 루트 해시를 교체하더라도, OS의 신뢰 루트에 의해 서명 검증 단계에서 원천 차단됩니다.

## 4. 실무 응용 사례

1. **Android APEX & APK 보호**:
   - Google Play 스토어에서 다운로드된 앱과 시스템 런타임 모듈은 `fsverity`로 보호되어, 기기가 루팅되거나 악성 앱이 루트 권한을 탈취하더라도 시스템 코드를 임의 수정할 수 없습니다.
2. **systemd 확장 이미지 (`systemd-sysext`)**:
   - 불변(Immutable) 리눅스 배포판에서 런타임 바이너리를 안전하게 마운트하고 실행합니다.
3. **AI 대규모 모델 가중치 무결성 수호**:
   - 70B 이상의 거대 언어 모델(LLM) 파일이 체크포인트 복원 또는 추론 시 디스크 사일런트 비트 부패(Silent Bit-rot)로 인해 잘못된 응답을 생성하는 이상 현상을 조기에 차단합니다.
