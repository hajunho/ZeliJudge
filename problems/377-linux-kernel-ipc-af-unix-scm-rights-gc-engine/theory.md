# 리눅스 커널 UNIX 도메인 소켓 (AF_UNIX) SCM_RIGHTS와 unix_gc 가비지 컬렉션 아키텍처

## 1. 서론: AF_UNIX와 SCM_RIGHTS 파일 디스크립터 전달

리눅스 및 POSIX 운영체제에서 **UNIX 도메인 소켓(AF_UNIX / AF_LOCAL)**은 로컬 머신 내부에서 실행되는 프로세스 간 통신(IPC)의 핵심 표준입니다. 네트워크 인터페이스 카드(NIC)와 TCP/IP 프로토콜 스택(체크섬, 슬라이딩 윈도우, 패킷 캡슐화)을 우회하고 커널 가상 메모리 버퍼(`sk_buff`)를 통해 데이터를 직접 전달하므로, 극도로 낮은 지연 시간과 높은 대역폭을 제공합니다.

AF_UNIX의 가장 강력한 특징 중 하나는 `sendmsg(2)`와 `recvmsg(2)`를 이용한 **보조 제어 데이터(Ancillary Data / Control Message, `struct cmsghdr`) 전송**입니다. 그중에서도 **`SCM_RIGHTS`** 프로토콜 레벨은 송신 프로세스가 소유한 열린 파일 디스크립터(`struct file *`)의 참조를 수신 프로세스에게 전송할 수 있게 합니다.
- 수신 프로세스가 `recvmsg()`를 호출하면, 커널은 수신 프로세스의 파일 디스크립터 테이블(FDT)에 미사용 중인 가장 낮은 정수 번호를 할당하고, 송신된 파일 객체(`struct file *`)를 바인딩합니다.
- 이는 특권 데몬(예: systemd, 디스플레이 서버)이 하드웨어 디바이스나 네트워크 포트를 연 뒤, 비특권 샌드박스 프로세스에게 해당 FD만 안전하게 넘겨주는 최소 권한 원칙(Principle of Least Privilege)의 토대가 됩니다.

## 2. 순환 참조의 함정: SCM_RIGHTS와 인플라이트(In-Flight) 소켓 누수

일반적인 파일(일반 파일, 디바이스, 파이프)을 전달할 때에는 참조 카운트 기반(`fput()`)의 즉시 해제가 완벽하게 작동합니다. 그러나 **전달되는 파일 객체 자체가 또 다른 UNIX 도메인 소켓**인 경우, 커널 참조 그래프에 치명적인 순환 사이클이 형성될 수 있습니다.

### 2.1 순환 참조 생성 시나리오
1. 프로세스가 두 개의 UNIX 도메인 소켓 $S_1$과 $S_2$를 생성합니다.
2. $S_1$을 통해 $S_2$의 파일 디스크립터를 전송합니다 (`sendmsg(S1, SCM_RIGHTS=[S2])`). $S_2$의 파일 참조는 $S_1$의 수신 버퍼 큐에 보관됩니다.
3. $S_2$를 통해 $S_1$의 파일 디스크립터를 전송합니다 (`sendmsg(S2, SCM_RIGHTS=[S1])`). $S_1$의 파일 참조는 $S_2$의 수신 버퍼 큐에 보관됩니다.
4. 프로세스가 $S_1$과 $S_2$의 사용자 공간 FD를 모두 닫습니다 (`close(S1); close(S2);`).

### 2.2 표준 참조 계수기의 실패
- 사용자 공간에서는 $S_1$과 $S_2$를 가리키는 FD가 전혀 없습니다 (`external_refs = 0`).
- 그러나 $S_1$은 $S_2$의 수신 큐에 들어있는 패킷에 의해 참조되고 있고(`inflight_refs = 1`), $S_2$는 $S_1$의 수신 큐에 들어있는 패킷에 의해 참조되고 있습니다(`inflight_refs = 1`).
- 두 소켓의 파일 구조체 `f_count`는 여전히 1 이상이므로, 커널은 어느 소켓도 해제하지 못합니다.
- 결과적으로 사용자 공간에서는 접근할 수 없으면서 커널 메모리를 영원히 점유하는 **인플라이트 순환 가비지(In-Flight Circular Garbage)**가 발생합니다.

## 3. 리눅스 커널의 해결책: unix_gc() 가비지 컬렉터 (`net/unix/garbage.c`)

리눅스 커널은 이 치명적인 자원 누수 공격(CVE-2013-4312 등)을 방지하기 위해 UNIX 도메인 소켓 전용 가비지 컬렉터인 **`unix_gc()`**를 구현하고 있습니다.

### 3.1 인플라이트 소켓 목록 관리 (`unix_inflight`)
- 소켓 파일 디스크립터가 `SCM_RIGHTS` 메시지에 담겨 전송 큐에 들어갈 때, 커널은 `unix_inflight()` 함수를 호출하여 해당 소켓(`struct unix_sock`)을 전역 인플라이트 리스트(`gc_inflight_list`)에 등록하고 카운터를 증가시킵니다.
- 반대로 `recvmsg()`로 수신되거나 소켓이 파괴될 때 `unix_notinflight()`를 호출하여 리스트에서 제거합니다.

### 3.2 3단계 가비지 컬렉션 알고리즘
`unix_gc()`가 호출되면(주기적 타이머 또는 새 소켓 할당 시 인플라이트 소켓 수가 임계치를 초과할 때) 다음 단계로 죽은 사이클을 색출합니다:

```
                  ┌────────────────────────────────────────┐
                  │ 1. 루트(Root) 집합 식별:               │
                  │    external_refs > 0 인 살아있는 소켓   │
                  └───────────────────┬────────────────────┘
                                      │
                                      ▼
                  ┌────────────────────────────────────────┐
                  │ 2. 도달 가능성(Reachability) BFS 순회: │
                  │    루트 소켓의 rcv_queue 내부 FDs부터  │
                  │    연쇄 도달 가능한 모든 소켓을 마킹   │
                  └───────────────────┬────────────────────┘
                                      │
                                      ▼
                  ┌────────────────────────────────────────┐
                  │ 3. 고립된 순환 가비지(Cycle) 확정:     │
                  │    external_refs == 0 이면서 마킹되지   │
                  │    못한 모든 소켓의 수신 큐를 강제 폐기 │
                  │    및 소켓 메모리 일괄 해제            │
                  └────────────────────────────────────────┘
```

1. **후보군 분리**:
   - `external_refs > 0`인 소켓은 유저스페이스 프로세스가 여전히 쥐고 있으므로 절대 가비지가 될 수 없는 **루트(Roots)**입니다.
2. **도달 가능성 전파 (Reachability Propagation)**:
   - 루트 소켓의 수신 대기 큐(`sk_receive_queue`)에 담긴 모든 `SCM_RIGHTS` 파일 객체들을 순회하며 도달 가능한 소켓 집합(`reachable`)을 확장합니다.
   - 도달된 소켓의 큐에 담긴 FD들도 재귀적으로 큐를 통해 추적합니다.
3. **가비지 파기 (Purging Dead Cycles)**:
   - 탐색이 완료된 후, 인플라이트 상태(`external_refs == 0`)이면서 `reachable` 집합에 포함되지 못한 소켓들은 **외부에서 결코 접근할 수 없는 고립된 순환 사이클**로 판정됩니다.
   - 커널은 이 소켓들의 수신 큐에 들어있는 `sk_buff`들을 강제로 파기(`skb_queue_purge`)하여 물려있던 다른 소켓들의 `inflight_refs`를 끊고, 최종적으로 `free_socket()`을 호출하여 메모리를 안전하게 회수합니다.

## 4. 수신 버퍼 백프레셔 (Backpressure) 및 안전 제어

소켓의 수신 버퍼(`sk->sk_rcvbuf`)는 무한하지 않습니다.
- 송신 프로세스가 수신 프로세스의 읽기 속도보다 빠르게 메시지를 쏟아부으면 버퍼 오버플로우가 발생합니다.
- 리눅스 커널은 `sk->sk_wmem_alloc`과 `sk->sk_rmem_alloc`을 추적하여, 수신 버퍼 한도를 초과할 경우 `EAGAIN`을 반환하거나 송신 프로세스를 블로킹 대기 상태(`TASK_INTERRUPTIBLE`)로 전환하여 시스템 안정성을 수호합니다.
