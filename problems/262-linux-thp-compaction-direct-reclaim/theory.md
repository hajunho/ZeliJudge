# [이론 및 배경] Linux Transparent Huge Pages(THP)와 메모리 컴팩션 서브시스템 아키텍처

## 1. TLB 미스와 2MB 거대 페이지의 양날의 검

현대 CPU는 가상 주소를 물리 주소로 변환하기 위해 하드웨어 페이지 테이블(Page Table)을 조회하며, 빈번한 메모리 조회의 오버헤드를 줄이기 위해 **TLB(Translation Lookaside Buffer)**라는 고속 캐시를 사용합니다.
- 표준 4KB 페이지 체계에서 64GB 크기의 메모리를 매핑하려면 $16,777,216$개의 페이지 테이블 엔트리(PTE)가 필요하며, 수 기가바이트의 데이터베이스 워크로드에서는 TLB 캐시 미스율이 급증하여 메모리 접근 병목이 심화됩니다.
- 반면 2MB 거대 페이지(Huge Page)를 사용하면 동일한 64GB를 불과 $32,768$개의 엔트리로 커버할 수 있어 TLB 히트율이 99% 이상으로 상승하고, 주소 변환에 소모되는 CPU 사이클을 최대 30%까지 절감할 수 있습니다.

그러나 2MB 거대 페이지는 물리 메모리 상에서 **반드시 512개의 연속된 4KB 페이지(Order-9)이자 2MB 정렬(2MB-aligned)**이어야 한다는 엄격한 제약 조건을 갖습니다.

---

## 2. 외부 단편화(External Fragmentation)와 버디 시스템의 한계

리눅스 커널의 물리 메모리 할당자인 **버디 할당자(Buddy Allocator)**는 $2^0$ (4KB)부터 $2^{10}$ (4MB)까지 2의 거듭제곱 단위(Order 0~10)로 프리 리스트(Free List)를 유지합니다.
서버가 장시간 가동되며 수많은 파일 캐시, 네트워크 버퍼, 사용자 프로세스 힙이 할당 및 해제되면, 메모리 공간 곳곳에 4KB~64KB 크기의 빈 구멍들이 흩어지는 **외부 단편화(External Fragmentation)**가 필연적으로 발생합니다.

```
[4KB Free] [Kernel Slab (Unmovable)] [4KB Free] [Page Cache (Movable)] ...
```

이 상태에서는 시스템 전체에 수십 기가바이트의 여유 메모리가 남아 있더라도, 2MB(512개 연속) 크기의 단일 청크는 단 1개도 존재하지 않게 됩니다.

---

## 3. 메모리 컴팩션(Memory Compaction)의 동작 원리

외부 단편화로 인해 고차수(High-order) 할당이 실패할 때, 흩어져 있는 페이지들을 한쪽으로 밀어 모아 연속된 거대 페이지 공간을 창출하는 메커니즘이 **메모리 컴팩션(Compaction)**입니다 (`mm/compaction.c`).

리눅스 커널은 **양방향 투-포인터 스캐너(Two-Pointer Scanner)** 알고리즘을 사용합니다:
1. **마이그레이션 스캐너(Migration Scanner)**: 존(Zone)의 낮은 PFN에서 시작하여 높은 쪽으로 전진하며, 다른 곳으로 이주시킬 수 있는 `MOVABLE` 페이지(익명 메모리, 페이지 캐시)를 탐색합니다.
2. **프리 스캐너(Free Scanner)**: 존의 가장 높은 PFN에서 시작하여 낮은 쪽으로 후진하며, 마이그레이션된 페이지를 받아줄 `FREE` 슬롯을 탐색합니다.
3. 두 스캐너가 중간에서 만날 때까지 `MOVABLE` 페이지의 내용을 `FREE` 슬롯으로 복사(Copy)하고, 프로세스 페이지 테이블의 매핑을 갱신한 후 TLB를 플러시(Flush)합니다.

### 치명적 병목: 이동 불가 페이지(Unmovable Pages)
커널 슬랩 메모리(dentry, inode 캐시), DMA 버퍼, 물리 주소에 고정된 드라이버 메모리 등 `UNMOVABLE` 플래그를 가진 페이지가 2MB 블록 내에 단 1개라도 박혀 있으면, 해당 512개 블록은 아무리 컴팩션을 수행해도 거대 페이지로 병합될 수 없습니다.

## 4. 직접 회수(Direct Reclaim)와 워터마크 압박

리눅스 커널은 메모리 고갈을 방지하기 위해 존마다 세 개의 수위선(Watermark)을 관리합니다:
- **$W_{\text{high}}$**: 여유 공간이 충분한 안전 구간.
- **$W_{\text{low}}$**: 백그라운드 스왑 데몬인 `kswapd`가 기상하여 비동기적으로 페이지를 회수하기 시작하는 임계점.
- **$W_{\min}$**: 여유 메모리가 위험 수준으로 고갈된 상태.

여유 메모리가 $W_{\min}$ 이하로 떨어지거나 동기 할당에 실패하면, 커널은 백그라운드 데몬을 기다리지 않고 **할당을 요청한 사용자 프로세스의 스레드를 직접 차출하여 동기식 페이지 회수(Direct Reclaim)**를 강제합니다.
이때 `MOVABLE_DIRTY` 페이지를 만나면 즉시 디스크 I/O를 발생시키는 페이지 플러시(Writeback)가 발생하여 스레드 지연시간이 마이크로초 단위에서 수백 밀리초(ms) 단위로 폭증하게 됩니다.

---

## 5. 프로덕션 데이터베이스의 THP 재앙과 최적 튜닝

Redis, MongoDB 등 실시간 데이터베이스 운영 환경에서 THP가 켜져 있을 때 발생하는 스톨(Stall) 현상은 바로 이 **직접 컴팩션과 직접 회수가 쿼리 처리 워커 스레드의 크리티컬 패스에서 동기적으로 실행되기 때문**입니다.

### 핵심 시스템 파라미터 튜닝 지침
1. `/sys/kernel/mm/transparent_hugepage/enabled`:
   - `always` $\implies$ `madvise` 또는 `never`: 불필요한 모든 백그라운드 메모리에 대해 THP 할당 시도를 차단.
2. `/sys/kernel/mm/transparent_hugepage/defrag`:
   - `always` $\implies$ `defer` 또는 `madvise`: THP 할당 실패 시 사용자 스레드가 멈추어 직접 컴팩션을 수행하지 않고, 비동기 `kcompactd`에 위임한 뒤 즉시 4KB 기본 페이지로 폴백.
3. `vm.watermark_scale_factor` 및 `vm.min_free_kbytes`:
   - 워터마크 간격을 넓혀 사용자 스레드가 $W_{\min}$에 도달하기 전에 백그라운드 `kswapd`가 미리 메모리를 확보하도록 유도.
