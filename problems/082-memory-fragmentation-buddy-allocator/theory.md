# 메모리 외부 단편화와 리눅스 커널 버디 할당자 (Buddy Allocator)

## 1. 메모리의 보이지 않는 함정: 외부 단편화 (External Fragmentation)

### 1.1 100칸 주차장과 4칸짜리 관광버스의 비극
총 100대의 승용차를 댈 수 있는 대형 주차장이 있습니다.  
현재 주차장에 50대의 승용차가 주차되어 있고, 주차 관리 시스템에는 **"잔여 빈자리: 50칸"**이라고 초록색 불이 켜져 있습니다.

그때 단체 관광객 40명을 태운 대형 버스 1대가 주차장에 들어왔습니다.  
버스는 4칸의 연속된 주차 공간이 필요합니다.

```text
[주차장 실제 현황]
[차][빈][차][빈][차][빈][차][빈][차][빈] ... [차][빈]
(차량들이 1칸씩 띄엄띄엄 주차되어 있음)
```

주차장 관리원이 난처한 표정으로 버스 기사에게 말합니다:  
> **"기사님 죄송합니다. 빈자리는 50칸이나 되지만, 연속으로 4칸 비어있는 곳이 한 군데도 없어서 주차하실 수 없습니다!"**

버스 기사는 분통을 터뜨립니다:  
> **"빈자리가 50칸이나 있는데 왜 주차를 못 해?!"**

결국 버스는 주차하지 못하고 쫓겨납니다(할당 실패, Out of Memory).

이 비극이 바로 운영체제(OS), 저수준 C/C++/Rust 엔진, GPU VRAM 관리, JVM Netty Direct Buffer에서 끊임없이 발생하는 **외부 단편화 (External Fragmentation)**입니다.

## 2. 외부 단편화 vs 내부 단편화

| 구분 | 발생 원인 | 결과 | 해결 전략 |
|:---|:---|:---|:---|
| **내부 단편화<br>(Internal Fragmentation)** | 요청된 크기보다 더 큰 고정 블록을 할당하여 블록 내부 공간이 낭비됨 (예: 5바이트 요청에 8바이트 블록 할당 $\to$ 3바이트 낭비) | 블록 내부 자투리 메모리 누수 | 적절한 슬랩(Slab) 크기 분할 |
| **외부 단편화<br>(External Fragmentation)** | 메모리의 할당과 해제가 반복되면서 작은 여유 블록들이 군데군데 흩어져, **총 여유 메모리는 충분하지만 요청 크기만큼의 연속된 블록이 존재하지 않음** | 대용량 연속 메모리 할당 실패 (OOM) | **버디 할당자 (Buddy Allocator)**, 메모리 컴팩션(Compaction) |

### 2.1 외부 단편화율 공식
$$\text{Fragmentation Ratio} = \left(1 - \frac{\text{Max Contiguous Free Block}}{\text{Total Free Memory}}\right) \times 100\%$$
- 여유 공간이 아무리 많아도, 최대 연속 블록이 작아지면 단편화율이 80%~90% 이상으로 치솟으며 시스템이 마비됩니다.

## 3. 리눅스 커널의 구원투수: 버디 할당자 (Buddy Allocator)

리눅스 커널의 물리 페이지 할당자(Page Frame Allocator)는 이 문제를 해결하기 위해 1963년 해리 마코위츠(Harry Markowitz)가 고안한 **버디 시스템 (Buddy System)**을 사용합니다.

```
[초기 전체 메모리 (1,024 KB)]
┌───────────────────────────────────────────────────────────┐
│                          1024 KB                          │
└───────────────────────────────────────────────────────────┘
               ▼ 256 KB 요청 시 (분할 Split)
┌───────────────────────────┬───────────────────────────────┐
│          512 KB           │          512 KB (Free)        │
└───────────────────────────┴───────────────────────────────┘
  ┌──────────────┬──────────┐
  │ 256 KB(사용)  │256KB(Free│
  └──────────────┴──────────┘
```

### 3.1 2의 거듭제곱 ($2^k$) 블록 분할 (Recursive Split)
1. 메모리 풀 전체 크기는 $2^K$ (예: 1,024 KB)입니다.
2. 어떤 크기 $S$의 할당 요청이 들어오면, $S$를 수용할 수 있는 최소 2의 거듭제곱 크기 $2^k \ge S$를 계산합니다. (예: 180 KB 요청 $\to$ 256 KB 블록).
3. 프리 리스트에 $2^k$ 크기의 블록이 없다면, 그보다 큰 최소 블록을 찾아 **정확히 절반(Half)으로 재귀적으로 쪼갭니다(Split).**
4. 쪼개져 남은 반쪽 블록(Buddy)은 프리 리스트에 반환됩니다.

### 3.2 짝꿍(Buddy)의 마법: $O(1)$ 비트 XOR 연산
버디 할당자의 가장 경이로운 점은, 어떤 블록의 주소 $A$와 크기 $S = 2^k$가 주어졌을 때 그 블록의 유일한 쌍둥이 짝꿍(Buddy) 주소를 **비트 XOR 연산 단 1번**으로 알아낼 수 있다는 것입니다!

$$\text{buddy\_addr} = A \oplus S$$

예를 들어, 크기가 4인 블록들의 짝꿍:
- 주소 `0`의 짝꿍: $0 \oplus 4 = 4$
- 주소 `4`의 짝꿍: $4 \oplus 4 = 0$
- 주소 `8`의 짝꿍: $8 \oplus 4 = 12$
- 주소 `12`의 짝꿍: $12 \oplus 4 = 8$

### 3.3 재귀적 짝꿍 병합 (Coalescing)
메모리가 해제(`FREE`)될 때 버디 할당자는 즉시 짝꿍을 검사합니다:
1. $B = A \oplus S$ 주소의 짝꿍 블록이 **현재 비어있고(Free), 크기가 동일한가?**
2. 그렇다면 두 블록을 즉시 하나로 합쳐(Merge) 크기 $2S$인 상위 블록으로 재합성합니다!
   - 합쳐진 새 블록의 시작 주소: $\min(A, B)$
3. 다시 그 상위 블록의 짝꿍을 검사하여 비어있다면 연쇄적으로 계속 병합합니다.
4. 이 과정을 통해 쪼개졌던 자투리 메모리들이 **실시간으로 거대한 단일 메모리 블록으로 자동 복원**되므로 외부 단편화가 완벽하게 치유됩니다!

## 4. 실무 프로덕션 엔지니어링 팁

1. **Jemalloc & Netty Direct Arena**:
   - 고성능 네이티브 메모리 할당자(Jemalloc, Netty)는 버디 시스템의 원리를 바탕으로 청크(Chunk, 4MB)와 런(Run) 계층 구조를 구현하여 멀티스레드 락 경합 없는 초고속 메모리 할당을 달성합니다.
2. **단편화 모니터링 (`/proc/buddyinfo`)**:
   - 리눅스 서버에서 `cat /proc/buddyinfo`를 실행하면 각 메모리 존(Zone)별로 $2^0 \sim 2^{10}$ 페이지 크기의 가용 블록 개수를 실시간으로 확인할 수 있습니다.
   - 고차원(High-order, $2^9, 2^{10}$) 블록이 바닥나면 드라이버 DMA나 점보 프레임 할당이 실패할 수 있습니다.
