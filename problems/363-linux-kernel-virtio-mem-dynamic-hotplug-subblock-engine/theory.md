# Linux Kernel virtio-mem 서브블록 메모리 관리 심층 이론

## 1. 가상 머신 메모리 오버커밋(Overcommit)과 벌루닝의 태생적 한계

하이퍼바이저(KVM, VMware ESXi 등)는 게스트 VM들이 선언한 총 메모리 합계가 호스트 물리 DRAM보다 큰 상황에서 메모리를 동적으로 재배분하는 오버커밋 기법을 사용합니다.

### 1.1 `virtio-balloon`의 작동과 문제점
- **작동**: 게스트 커널에 드라이버 모듈로 삽입되어, 호스트가 메모리를 회수하려 할 때 게스트 버디 할당자로부터 페이지를 할당(`alloc_pages(GFP_HIGHUSER)`)받아 잠근 뒤 하이퍼바이저에 GPA를 통보하여 호스트 물리 메모리를 `madvise(MADV_DONTNEED)`로 해제합니다.
- **문제점 1: 버디 할당자 파편화 (Fragmentation)**:
  - 4KB 단위의 무차별 할당은 커널의 고차 버디 블록(Order-9, 2MB HugePages)을 산산조각 냅니다. 게스트의 성능이 급격히 저하됩니다.
- **문제점 2: 돌발 OOM 붕괴 (OOM Trap)**:
  - 게스트 내부의 워크로드가 급증할 때 벌루너가 페이지를 신속히 뱉어내지 못하면 게스트 커널이 OOM 패닉을 일으킵니다.

### 1.2 ACPI DIMM 핫플러그의 한계
- 물리 서버의 DIMM 슬롯 추가/제거를 모방하여 가상 ACPI 테이블을 통해 메모리를 추가합니다.
- 최소 단위가 거대(1GB 이상)하며, 무엇보다 커널의 SLAB이나 페이지 테이블 같은 비이동성(Unmovable, `ZONE_NORMAL`) 페이지가 단 하나라도 박히면 해당 DIMM 전체의 언플러그가 불가능합니다.

## 2. virtio-mem 아키텍처: 서브블록(Sub-Block) 기반의 세밀한 제어

`drivers/virtio/virtio_mem.c`는 벌루닝의 세밀함과 DIMM 핫플러그의 물리적 청정함을 결합한 아키텍처입니다.

### 2.1 사전 예약 연속 GPA 윈도우 (Preallocated GPA Window)
- 부팅 시 하이퍼바이저는 게스트에게 거대한 단일 가상 물리 주소 창(예: 16GB)을 부여합니다.
- 초기에는 호스트 DRAM이 전혀 매핑되지 않아 호스트 메모리 소비량은 0입니다.

### 2.2 메모리 블록(Memory Block)과 서브블록(Sub-Block) 2계위 분할
- **메모리 블록**: 리눅스 커널의 메모리 핫플러그 기본 단위 (x86_64 기준 보통 128MB).
- **서브블록**: `virtio-mem`이 실제로 조작하는 최소 단위 (보통 2MB 또는 4MB).
- 128MB 메모리 블록 내부에 속한 모든 2MB 서브블록들이 독립적으로 플러그/언플러그될 수 있습니다.

### 2.3 역순 언플러그 (Reverse Order Hotunplug) 및 연속성 유지
- 메모리를 축소할 때, `virtio-mem`은 항상 높은 GPA 주소(오른쪽)부터 역순으로 스캔합니다.
- 이는 게스트 버디 할당자가 일반적으로 낮은 주소부터 페이지를 할당하므로, 높은 주소에 위치한 서브블록들이 비어 있을 확률이 압도적으로 높기 때문입니다.

## 3. 페이지 격리(Page Isolation)와 비이동성 고정(Pinning)

### 3.1 `alloc_contig_range()`와 `MIGRATE_ISOLATE`
서브블록(2MB)을 언플러그하기 위해:
1. 해당 서브블록 범위의 모든 페이지 블록을 `MIGRATE_ISOLATE`로 설정하여 새로운 할당을 차단합니다.
2. 이미 사용 중인 사용자 익명/파일 페이지는 다른 메모리 블록으로 마이그레이션(`migrate_pages()`)합니다.
3. 모든 페이지가 비워지면 커널 버디 할당자에서 서브블록을 완전히 분리하고, 호스트에 `VIRTIO_MEM_REQ_UNPLUG`를 송신하여 호스트 물리 RAM을 즉시 환원합니다.

### 3.2 고정 페이지(Pinned Pages) 우회 전략
만약 커널 DMA 버퍼나 드라이버 구조체로 인해 페이지 마이그레이션이 불가능한 경우(`PINNED`):
- `virtio-mem`은 기존 ACPI 방식처럼 포기하지 않고, 해당 2MB 서브블록만 건너뛰고 앞선 다른 서브블록들을 계속해서 회수합니다.
- 이를 통해 클라우드 하이퍼바이저는 게스트 성능 훼손 없이 99% 이상의 높은 메모리 회수 성공률을 보장받습니다.
