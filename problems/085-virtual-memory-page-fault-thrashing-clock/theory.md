# 가상 메모리 페이지 폴트(Page Fault)와 스래싱(Thrashing) & 시계(Clock) 알고리즘

## 1. 수험생의 비극: 좁은 책상과 거대한 책장

### 1.1 책상에 책 3권 올려놓고 10과목 공부하려다 밤샌 비극
공시생 철수의 원룸 책상을 상상해 봅시다. 📚📖  
철수의 책상(물리 메모리 RAM)은 너무 좁아서 책을 딱 **3권(3 프레임)**만 올려놓을 수 있습니다.  
하지만 철수가 오늘 공부해야 할 수험서는 국어, 영어, 한국사, 행정법, 행정학 등 총 **10권(가상 메모리 Virtual Memory)**입니다.

철수는 책상에 없는 책을 볼 때마다 일어나서 베란다 책장(하드디스크/SSD 스왑 영역)으로 가야 합니다.
- **책상에 있는 책 읽기 (Page Hit)**: 손만 뻗으면 되므로 **1초** 소요.
- **책장에 가서 책 바꿔오기 (Page Fault & Disk Swap)**: 베란다까지 걸어가서 책을 찾고 가져오느라 **10초** 소요.

```text
[철수의 공부 순서 (페이지 참조 스트림)]
국어 -> 영어 -> 한국사 -> 국어 -> 영어 -> 행정법 -> 국어 -> 영어 -> 행정학 ...
```

철수는 1시간 동안 공부를 5분밖에 못 했습니다.  
왜냐고요? 55분 동안 책상과 베란다 책장 사이를 왔다 갔다 하며 **책을 뺐다 꽂았다 하느라 체력이 방전(Thrashing)**되었기 때문입니다!

이것이 바로 현대 운영체제(Windows, Linux, macOS)에서 크롬 탭을 30개 띄우거나 대용량 프로그램을 여러 개 실행했을 때,  
**CPU 사용률은 100%를 찍고 팬이 굉음을 내는데 컴퓨터는 마우스 커서조차 굳어버리는 '스래싱(Thrashing, 가상 메모리 지옥)'**의 정체입니다.

## 2. 가상 메모리 요구 페이징과 스래싱의 원리

### 2.1 요구 페이징 (Demand Paging)과 지연 비용
운영체제는 물리 RAM(예: 16GB)보다 훨씬 큰 프로그램(예: 64GB)을 실행할 수 있도록, 메모리를 고정 크기 블록인 **페이지(Page, 보통 4KB)**로 나누고, 실제로 CPU가 접근할 때만 디스크에서 RAM(Page Frame)으로 퍼 올리는 **요구 페이징**을 사용합니다.
- **Page Hit (메모리 적중)**: CPU가 원하는 페이지가 이미 RAM 프레임에 존재함 $\to$ 지연 시간 수십 나노초(ns).
- **Page Fault (페이지 부재)**: 원하는 페이지가 RAM에 없음 $\to$ CPU에 하드웨어 인터럽트 발생 $\to$ OS가 디스크 스왑 영역에서 해당 페이지를 RAM으로 로드(Swap-In), 기존 페이지를 디스크로 방출(Swap-Out) $\to$ 지연 시간 수 밀리초(ms, **RAM보다 10만 배 느림!**).

### 2.2 스래싱 (Thrashing, 디스크 I/O 스왑 폭풍)
각 프로세스가 활발하게 사용하는 페이지들의 집합을 **작업 집합(Working Set)**이라고 합니다.  
실행 중인 프로세스들의 작업 집합 크기의 총합이 물리 메모리(RAM) 크기를 초과하는 순간:
1. 페이지를 하나 적재하자마자 다른 프로세스의 필수 페이지를 쫓아내야 합니다.
2. 쫓겨난 프로세스는 실행되자마자 다시 페이지 폴트를 일으켜 방금 올린 페이지를 쫓아냅니다.
3. **결과**: CPU가 실제 애플리케이션 코드를 실행하는 시간(Throughput)은 거의 0%로 추락하고, **하루 종일 디스크 I/O 페이징 스왑만 처리하느라 시스템 전체가 완전히 벽돌(Freeze)**이 됩니다.

## 3. 페이지 교체 알고리즘: FIFO의 한계 vs Clock 알고리즘

RAM 프레임이 꽉 찼을 때 어떤 페이지를 쫓아낼 것인가?

### 3.1 FIFO (First-In, First-Out)
- 가장 먼저 메모리에 들어온 페이지를 희생자(Victim)로 쫓아냅니다.
- **치명적 한계**: 프로그램 시작 시 로드되어 하루 종일 쓰이는 **핵심 전역 변수나 루프 코드**도 "가장 오래 머물렀다"는 이유만으로 쫓겨나 즉시 페이지 폴트를 유발합니다 (벨레디의 모순 Belady's Anomaly 발생).

### 3.2 시계 알고리즘 (Clock Algorithm / Second-Chance, 리눅스 커널 표준)
이상적인 알고리즘인 LRU(Least Recently Used)는 매 메모리 접근마다 타임스탬프를 기록해야 하므로 오버헤드가 너무 큽니다.  
리눅스 커널은 이를 **하드웨어 참조 비트(Reference Bit, 1비트)와 원형 시계 바늘**로 초고속 근사한 **시계 알고리즘**을 사용합니다.

```
       [Clock Algorithm 원형 큐]
             Frame 0: [P1, bit=1]
                 ^
                 │ (시계 바늘 Hand)
Frame 2: [P3, bit=1]   Frame 1: [P2, bit=0]
```

1. **페이지 적중(Hit) 시**: 해당 프레임의 참조 비트를 `bit = 1`로 세팅 (매우 가벼운 1비트 쓰기).
2. **페이지 부재(Fault) 발생 시 (교체 대상 탐색)**:
   - 시계 바늘이 가리키는 프레임을 검사합니다.
   - 만약 `bit == 1`: **기회를 한 번 더 줌(Second Chance)!** `bit = 0`으로 내리고 시계 바늘을 다음 프레임으로 전진시킵니다.
   - 만약 `bit == 0`: 최근에 참조된 적이 없는 페이지이므로 **이 페이지를 희생자(Victim)로 즉시 축출(Evict)**합니다!
   - 새 페이지를 적재하고 `bit = 1`로 설정한 뒤, 시계 바늘을 다음 위치로 전진시키고 종료합니다.

- **장점**: 최근에 참조된 인기 페이지는 `bit=1` 덕분에 축출을 면하고, 오랫동안 참조되지 않은 페이지만 골라서 방출하므로 **FIFO 대비 페이지 폴트 발생률을 50% 이상 절감하여 스래싱을 강력하게 억제**합니다.
