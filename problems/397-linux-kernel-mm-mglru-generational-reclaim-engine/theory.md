# 397: 리눅스 커널 메모리 관리 — Multi-Gen LRU(MGLRU) 아키텍처와 세대별 페이지 교체 이론

## 1. 전통적 2-리스트 LRU의 구조적 한계와 퇴출 병목

리눅스 커널은 메모리 부족 상황에서 페이지를 회수하기 위해 오랫동안 **Active/Inactive 2-리스트 LRU** 알고리즘을 사용해 왔습니다.
- **Active List**: 최근에 접근된 페이지.
- **Inactive List**: 퇴출 후보 페이지.

### 1.1 2-리스트 모델의 병리 현상
1. **LRU Spinlock 경합 (`lru_lock`)**:
   모든 페이지의 리스트 삽입, 이동, 삭제가 단일 스핀락 하에서 수행되므로 CPU 코어 수가 64~128개 이상인 서버에서 심각한 확장성 병목이 발생합니다.
2. **스캔 오염 (Scan Pollution)**:
   데이터베이스 백업이나 대용량 파일 스트리밍 등 일회성 순차 I/O가 발생하면, 수백만 개의 비활성 페이지가 인액티브 리스트를 단시간에 밀어내어 기존의 중요한 워킹 세트가 디스크로 쫓겨나는 캐시 스래싱(Cache Thrashing)이 발생합니다.
3. **참조 카운팅의 부재**:
   단순히 '참조됨'과 '참조 안 됨'의 1비트 불리언 상태만 기록하므로, 100번 접근된 페이지와 1번 접근된 페이지가 동일하게 취급됩니다.

## 2. Multi-Gen LRU (MGLRU)의 설계 원리

리눅스 커널 6.1에 도입된 MGLRU는 페이지 교체 알고리즘을 **시간 기반 다세대(Multi-Generational)** 모델로 전면 재설계했습니다.

### 2.1 세대 인덱스 링 버퍼 (`min_seq` & `max_seq`)
- 페이지들은 물리적 리스트 대신 세대 번호(Generation Sequence Number)로 태깅됩니다.
- $	ext{min\_seq}$: 현재 퇴출 스캐너가 순회 중인 가장 오래되고 차가운 세대.
- $	ext{max\_seq}$: 새로운 페이지 할당 및 최근 접근된 페이지가 머무는 가장 젊고 뜨거운 세대.
- 전체 세대 수 $\Delta = 	ext{max\_seq} - 	ext{min\_seq} + 1$는 사전에 정의된 상한 $	ext{MAX\_NR\_GENS}$ (일반적으로 4세대)로 억제됩니다.

### 2.2 다중 티어(Tier) 보호
각 세대 내부에서 페이지는 최근 접근 빈도에 따라 4단계 티어(Tier 0 ~ Tier 3)로 세분화됩니다:
- 일회성 스트리밍 페이지는 Tier 0으로 진입하여 퇴출 1순위가 됩니다.
- 반복 접근된 핫 페이지는 Tier 1, 2, 3으로 승격되어, 퇴출 스캐너가 방문하더라도 즉시 버려지지 않고 1단계씩 Tier가 강등되는 보호(Grace Period)를 받습니다.

### 2.3 2차 기회(Second Chance)와 지연된 승격
퇴출 프론트인 $	ext{min\_seq}$에서 스캐너가 페이지를 검사할 때 하드웨어 참조 비트(`referenced == True`)가 발견되면, 커널은 해당 페이지를 절대 스왑아웃하지 않고 즉시 최신 세대인 $	ext{max\_seq}$로 재승격시킵니다. 이를 통해 실제 활성 워킹 세트가 디스크로 유출되는 것을 100% 방지합니다.

---

## 3. 결론

Multi-Gen LRU는 안드로이드 스마트폰부터 수 테라바이트급 클라우드 서버에 이르기까지 메모리 압박 상황에서의 페이지 폴트 발생률을 20%~40% 감소시키고 OOM 킬러 발동을 극적으로 줄이는 현대 리눅스 커널 메모리 관리의 최고봉입니다.
