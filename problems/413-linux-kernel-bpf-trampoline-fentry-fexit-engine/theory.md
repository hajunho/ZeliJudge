# 이론 문서 413: Linux 커널 eBPF 트램펄린(bpf_trampoline) 및 JIT 직접 호출 아키텍처 심층 분석

## 1. 개요 및 배경: 리눅스 커널 추적 기술의 진화와 kprobe의 성능 한계

리눅스 커널 내부의 동작을 런타임에 동적으로 가로채어 분석하는 추적(Tracing) 기술은 지난 20년간 비약적으로 발전해 왔습니다:

```
+--------------------------------------------------------------------------------------------------+
| Evolution of Dynamic Tracing in Linux Kernel                                                     |
|                                                                                                  |
| [ 1세대: Kprobes (Linux 2.6) ]                                                                   |
|   Target Func Entry ---> int3 Breakpoint Trap ---> Exception Frame Push ---> Page Fault / Handler|
|   ---> Single-Step Instruction ---> iret Return                                                  |
|   * 지연 시간: 150ns ~ 200ns per Call! CPU 집약적 함수에서 20%~30% 성능 저하                      |
|                                                                                                  |
| [ 2세대: Ftrace MCOUNT / CALL (Linux 3.x) ]                                                      |
|   Target Func Entry ---> call __fentry__ ---> Generic Ftrace Trampoline                          |
|   * 지연 시간: 30ns ~ 50ns per Call (범용 레지스터 스태킹 오버헤드 여전히 잔존)                     |
|                                                                                                  |
| [ 3세대: eBPF Trampoline (Linux 5.5+, Alexei Starovoitov) ]                                      |
|   Target Func Entry ---> direct call <jit_trampoline> ---> Direct Argument Passing               |
|   ---> Run BPF Prog ---> Run Original Func ---> Run Exit BPF ---> ret                            |
|   * 지연 시간: 1ns ~ 2ns per Call! Native C 함수 호출과 동일한 속도 (100배 가속!)                  |
+--------------------------------------------------------------------------------------------------+
```

### 1.1 Kprobe의 구조적 병목 원인
- `kprobe`는 커널 텍스트 세그먼트의 첫 번째 명령어를 x86 `int3`(0xCC) 1바이트 소프트웨어 인터럽트 명령어로 교체합니다.
- CPU가 `int3`을 실행하면 하드웨어 인터럽트 게이트를 통해 IDT(Interrupt Descriptor Table)의 `do_int3()` 핸들러로 트랩됩니다.
- 커널은 모든 범용 레지스터를 커널 스택(`struct pt_regs`)에 일일이 푸시하고, CPU EFLAGS 레지스터의 트랩 플래그(TF)를 세팅하여 단일 스텝 모드로 전환한 후 원래 명령어를 에뮬레이션합니다.
- 이 전체 과정은 L1 명령어 캐시 무효화, 분기 예측기 오염, 파이프라인 플러시를 수반하므로 마이크로초 단위의 I/O 패스에서 용납할 수 없는 성능 저하를 초래했습니다.

## 2. eBPF 트램펄린(bpf_trampoline)의 어셈블리 레벨 아키텍처

리눅스 커널 5.5에 도입된 **eBPF Trampoline (`kernel/bpf/trampoline.c`, `arch/x86/net/bpf_jit_comp.c`)**은 각 커널 함수마다 완전히 독립된 맞춤형 기계어 스텁(Stub)을 동적으로 JIT 컴파일합니다:

```assembly
/* Dynamic x86-64 Trampoline Image Generated by arch_prepare_bpf_trampoline() */
trampoline_vfs_read:
    push    %rbp
    mov     %rsp, %rbp
    sub     $0x30, %rsp              /* Allocate Stack Frame for Args */
    
    /* 1. Save Caller-Saved Registers (x86-64 System V ABI) */
    mov     %rdi, 0x00(%rsp)        /* Arg 1: struct file *file */
    mov     %rsi, 0x08(%rsp)        /* Arg 2: char __user *buf */
    mov     %rdx, 0x10(%rsp)        /* Arg 3: size_t count */
    
    /* 2. Execute FENTRY BPF Programs Directly! */
    call    bpf_prog_fentry_1
    
    /* 3. Execute FMOD_RET (Modify Return) Programs */
    call    bpf_prog_fmod_ret_1
    test    %rax, %rax
    jnz     skip_orig_func           /* Non-zero return? Override & Bypass! */
    
    /* 4. Call Original Function */
    call    vfs_read_orig
    mov     %rax, 0x28(%rsp)        /* Save Return Value */

skip_orig_func:
    /* 5. Execute FEXIT BPF Programs (Access to Args + Return Value) */
    call    bpf_prog_fexit_1
    
    /* 6. Restore Return Value & Return to Caller */
    mov     0x28(%rsp), %rax
    leave
    ret
```

- 함수 진입점의 5바이트 NOP을 `text_poke_bp()`를 통해 트램펄린 주소로 원자적으로 패칭합니다.
- 패킷이나 레지스터를 재패키징하는 일체의 오버헤드 없이, CPU 레지스터에 이미 적재되어 있는 인자들을 BPF 프로그램의 첫 번째 인자 포인터로 직통 전달합니다.

## 3. 3대 트램펄린 BPF 프로그램 타입

1. **`BPF_TRACE_FENTRY`**:
   - 함수 진입 시점에 트리거됩니다.
   - 인자값 검사, 접근 카운팅, 호출 시작 시각 타임스탬프 기록 등에 최적화되어 있습니다.
2. **`BPF_MODIFY_RETURN` (fmod_ret)**:
   - 보안 모니터링(BPF LSM) 및 장애 주입(Fault Injection)을 담당합니다.
   - BPF 프로그램이 0을 반환하면 일반 흐름을 유지하지만, `-EPERM`(-1) 또는 `-EACCES`(-13)과 같은 음수 에러 코드를 반환하면 커널 함수 자체를 실행하지 않고 즉시 호출자에게 에러를 반환시킵니다.
   - 악의적인 파일 접근 차단(`do_unlinkat`), 불법적인 네트워크 연결 차단(`security_socket_connect`)을 0ns 오버헤드로 구현합니다.
3. **`BPF_TRACE_FEXIT`**:
   - 함수가 성공적으로 완료되거나 `fmod_ret`에 의해 조기 종료된 후 실행됩니다.
   - 입력 인자뿐만 아니라 함수의 최종 반환값(`ret_val`)과 소요 시간(`latency`)을 단일 프로그램 내에서 완벽하게 결합하여 관측할 수 있습니다.

## 4. Per-CPU 재귀 방어 (`bpf_prog_active`)와 안정성 보장

eBPF 프로그램 내부에서 BPF 헬퍼 함수를 호출하거나 커널 서브시스템을 참조할 때, 해당 서브시스템 내부에서 동일한 커널 함수가 다시 호출되는 **중첩 재귀(Mutual Recursion)**가 발생할 수 있습니다.

이를 차단하기 위해 리눅스 커널은 각 CPU마다 고유한 **`bpf_prog_active`** 원자적 카운터를 유지합니다:
- 트램펄린 진입 시 해당 CPU의 `bpf_prog_active`가 0보다 크면, 이미 현재 CPU 컨텍스트에서 BPF 프로그램이 실행 중임을 감지합니다.
- 재귀가 감지된 경우 추가 BPF 프로그램의 실행을 안전하게 생략(`RECURSION_SUPPRESSED`)하여 무한 재귀에 따른 커널 스택 오버플로우 및 시스템 커널 패닉을 완벽하게 차단합니다.
