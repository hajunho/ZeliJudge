# 이론적 배경: 전송 계층의 패러다임 전환: TCP 재전송 모호성과 QUIC RFC 9002 손실 감지 아키텍처

## 1. TCP의 40년 묵은 결함: 재전송 모호성 (Retransmission Ambiguity)

### 1.1 카른 알고리즘(Karn's Algorithm)의 태생적 한계
전통적인 TCP에서 패킷 손실이 발생하여 송신자가 바이트 시퀀스 번호 $SEQ$를 재전송했을 때, 이후 도착한 $ACK$는 원본 패킷에 대한 것인지 재전송 패킷에 대한 것인지 알 수 없습니다:
- **경우 A**: 원본 패킷이 긴 네트워크 큐 지연(Bufferbloat)을 겪고 뒤늦게 도착하여 발생한 $ACK$. (실제 RTT는 매우 긺)
- **경우 B**: 원본 패킷은 진짜 유실되었고 재전송 패킷이 즉시 도착하여 발생한 $ACK$. (실제 RTT는 매우 짧음)

필 카른(Phil Karn, 1987)은 잘못된 RTT 측정값이 RTO를 오염시키는 것을 막기 위해 다음 규칙을 제안했습니다:
> *"재전송된 세그먼트에 대한 왕복 시간(RTT) 측정치는 RTT 추정에 결코 반영하지 않는다."*

이로 인해 심한 손실이나 버퍼블로트 발생 시 TCP는 최신 RTT 정보를 전혀 업데이트하지 못하고, RTO 지수 백오프($2 \times RTO$)에만 의존하여 수 초 동안 연결이 멈추는(Stall) 심각한 성능 저하를 겪었습니다.

## 2. QUIC의 근본적 혁신: 단조 증가 패킷 번호 (Monotonic Packet Numbers)

QUIC (RFC 9000 / RFC 9002)은 데이터 스트림 오프셋(Stream Offset)과 패킷 전송 식별자(Packet Number)를 완전히 분리했습니다:
- **Stream Offset**: 수신 애플리케이션이 데이터를 올바른 순서로 조립하기 위한 바이트 위치 (TCP의 $SEQ$ 역할).
- **Packet Number (PN)**: 네트워크 경로 상에서 개별 UDP 패킷의 전송 순서를 식별하는 단조 증가 정수 ($0, 1, 2, \dots$).

```
[ 패킷 전송 시점 ]
  Stream Data [0..1199] ───► Packet Number (PN: 0)  [유실 발생!]
  Stream Data [0..1199] ───► Packet Number (PN: 5)  [재전송: 완전히 새로운 PN!]

[ ACK 수신 시점 ]
  수신자: "ACK: PN 5 확인 완료"
  송신자: "PN 5의 송신 시간과 ACK 수신 시간의 차이로 RTT를 100% 정확히 측정!" (모호성 제로)
```

이 혁신 덕분에 QUIC은 재전송된 패킷에 대해서도 **단 1회의 예외 없이 모든 패킷에서 완벽하게 RTT를 측정**할 수 있습니다.

## 3. RFC 9002 2단계 손실 감지 (Loss Detection) 알고리즘

### 3.1 패킷 임계값 손실 감지 (Packet Threshold)
IP 네트워크에서는 라우터의 멀티패스 라우팅(ECMP)이나 무선 인터페이스 핸드오버로 인해 소량의 패킷 역전(Packet Reordering)이 흔히 발생합니다.
- QUIC은 확인된 최대 패킷 번호(`largest_acked`)를 기준으로 재정렬 허용 윈도우 $kPacketThreshold = 3$을 둡니다.
- 만약 $PN \le \text{largest\_acked} - 3$인 미확인 패킷이 존재한다면, 그 패킷 뒤에 송신된 패킷 3개 이상이 이미 수신자에게 안전하게 도착했음을 의미하므로, 이 패킷은 단순 지연이 아니라 **물리적으로 유실된 것으로 확정**합니다.

### 3.2 시간 임계값 손실 감지 (Time Threshold)
비행 중인 패킷 수가 적거나(Window가 작을 때) 꼬리 패킷(Tail Loss)이 유실된 경우, $kPacketThreshold = 3$의 갭이 형성되지 못할 수 있습니다.
- RFC 9002는 최신 RTT 측정치를 반영한 적응형 시간 임계값을 적용합니다:
  $$\text{loss\_delay} = \frac{9}{8} \times \max(latest\_rtt, smoothed\_rtt)$$
- 송신된 지 $\text{loss\_delay}$ 이상 경과한 패킷은 패킷 번호 차이가 1~2에 불과하더라도 즉시 손실로 판정하여 재전송을 가속화합니다.

## 4. 탐색 타임아웃(PTO)과 지수 백오프

### 4.1 RTO와의 차이점: 파괴적이지 않은 능동 탐색 (Active Probing)
TCP의 RTO는 연결이 완전히 끊어졌음을 가정하고 혼잡 윈도우를 초기화하지만, QUIC의 PTO(Probe Timeout)는 연결이 살아있는지 확인하기 위해 **새로운 패킷 번호에 새로운 프레임 또는 미확인 데이터를 실어 1~2개의 탐색 패킷(Probe Packet)을 선제적으로 발송**합니다.
- 이를 통해 불필요한 연결 재수립(0-RTT 핸드셰이크 재시도)을 막고, 손실 복구 지연 시간을 P99 기준 최대 80% 단축시킵니다.
