# 395: 리눅스 커널 메모리 관리 — DAMON(Data Access Monitoring) 및 DAMOS(선제적 조작 기법)의 아키텍처와 수리적 배경

## 1. 배경: 전통적 가상 메모리 스캐닝의 구조적 한계

운영체제 가상 메모리 관리자(VMM)는 프로세스의 상주 세트(Resident Set Size: RSS) 중 실제 활발하게 사용되는 **작업 세트(Working Set Size: WSS)** 와 장기간 접근되지 않는 비활성(Cold) 페이지를 구별하여, 한정된 물리 RAM 자원을 최적 분배해야 합니다.

### 1.1 전통적 접근 추적 방식의 오버헤드
- **페이지 테이블 접근 비트(`PTE_ACCESSED`) 전수 조사**:
  커널 페이지 회수 데몬(`kswapd`)이나 `/proc/PID/smaps`는 프로세스의 페이지 테이블 트리를 최상위 PGD(Page Global Directory)부터 하위 PTE까지 워킹(Page Table Walk)하며 접근 비트를 읽고 클리어합니다.
  - 가상 메모리 크기 $V$와 페이지 크기 $P$에 대해 $N = V / P$개의 PTE를 스캔해야 하므로 시간 복잡도는 $O(N)$입니다.
  - 1TB 가상 메모리(4KB 페이지 기준 2.6억 개 페이지)를 탐색할 경우 수 기가바이트의 메모리 트래픽과 수 초간의 CPU 코어 점유가 발생하여 실시간 모니터링이 원천적으로 불가능합니다.
- **페이지 폴트 기반 추적 (`mprotect(PROT_NONE)`)**:
  페이지 보호 비트를 조작하여 메모리 접근 시 발생하는 소프트웨어 트랩을 후킹하는 기법은 치명적인 컨텍스트 스위칭 및 TLB 플러시 오버헤드를 유발합니다.

## 2. DAMON 아키텍처와 적응형 모니터링

AWS의 박성재에 의해 설계된 **DAMON(Data Access Monitoring Framework)** 은 다음의 3대 핵심 원칙을 통해 $O(1)$의 일정한 CPU 오버헤드로 주소 공간을 모니터링합니다:

### 2.1 영역 기반 추상화 (Region-based Monitoring)
DAMON은 개별 페이지 단위 대신, 연속된 주소 공간 범위를 나타내는 **영역(Region)** 단위로 메모리를 관리합니다.
영역의 총 개수 $M$은 관리자가 지정한 범위 $[N_{min}, N_{max}]$ 내로 엄격히 제한됩니다:
$$N_{min} \le M \le N_{max} \quad (	ext{기본값: } 10 \le M \le 1000)$$
따라서 샘플링 루프의 연산 복잡도는 메모리 크기 $V$와 완전히 무관하게 $O(M) = O(1)$로 보장됩니다.

### 2.2 적응형 영역 병합 및 분할 (Adaptive Regions Adjustment)
메모리 접근이 균일한 대형 영역과 접근이 불균일한 소형 영역을 동적으로 식별하기 위해 적응형 조정 알고리즘을 사용합니다:
1. **병합 (Merging)**: 인접한 영역들의 접근 빈도 $\Delta 	ext{nr\_accesses} \le 	heta_{	ext{merge}}$인 경우 두 영역을 하나로 합쳐 영역 수를 줄입니다.
2. **분할 (Splitting)**: 영역 개수가 상한 $N_{max}$보다 적을 때, 가장 큰 영역을 절반으로 분할하여 메모리 접근 패턴이 변하는 경계면의 해상도(Resolution)를 높입니다.

이 피드백 루프를 통해 핫스팟(Hotspot) 메모리 주변은 잘게 쪼개져 정밀하게 모니터링되고, 광대한 콜드 메모리는 거대한 하나의 영역으로 압축됩니다.

## 3. DAMOS (DAMON-based Operation Schemes)

DAMON이 메모리 접근 패턴을 관측하는 수동적 모니터라면, **DAMOS**는 관측된 통계를 기반으로 커널 수준의 메모리 관리 동작을 자동 수행하는 능동적 정책 엔진입니다.

### 3.1 주요 조작 프리미티브 (Operation Actions)
- `DAMOS_PAGEOUT`: 접근 빈도가 0이고 연령이 높은 페이지들을 시스템 직접 회수(Direct Reclaim) 전에 선제적으로 백그라운드 스왑아웃하여 메모리 누수를 방지합니다.
- `DAMOS_WILLNEED`: 접근 빈도가 급격히 상승한 영역에 `madvise(MADV_WILLNEED)`를 발행하여 스왑/디스크로부터 미리 페이지를 올려두어 메이저 폴트를 0으로 만듭니다.
- `DAMOS_COLD`: 비활성 LRU 리스트로 선제 이동시켜 워킹 세트 보호.

### 3.2 안전성 제어: Quotas & Watermarks
1. **처리량 쿼터 (Quotas)**:
   밀리초 단위의 시간 쿼터와 바이트 단위의 용량 쿼터(`quota_bytes`)를 설정하여, 선제적 스왑아웃이 디스크 I/O 대역폭을 고갈시키는 I/O 쓰래싱(Thrashing)을 방지합니다.
2. **워터마크 (Watermarks)**:
   시스템 여유 메모리 비율($	ext{free\_mem\_pct}$)을 감시하여, 메모리가 넉넉한 정상 상태(High Watermark 이상)에서는 DAMOS를 자동으로 정지시켜 CPU를 아끼고, 메모리 압박 상태에서만 활성화합니다.

---

## 4. 결론

DAMON과 DAMOS는 클라우드 네이티브 환경에서 메모리 모니터링 오버헤드를 $O(1)$로 묶어두면서도 프로세스의 실제 워킹 세트 크기를 실시간으로 계측하고, 선제적 페이지 회수를 통해 서버 메모리 비용(TCO)을 20%~30% 절감하는 최신 리눅스 커널의 핵심 메모리 서브시스템입니다.
