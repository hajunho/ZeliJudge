# [ZeliJudge 백서 #025] 1초에 1,000명이 몰려왔다!: 처리율 제한 장치(Rate Limiting)와 토큰 버킷(Token Bucket)의 마법

> **"무료 API를 오픈했다가 10분 만에 300만 원 청구서를 받지 않으려면, 게이트웨이 현관문에 토큰 버킷 경비원을 세워야 합니다."**

---

## 1. 💡 비전공자 바이브 코더를 위한 현실 비유: "워터파크 파도풀 물통"

워터파크에 가면 일정한 속도로 물이 뚝뚝 떨어져 채워지는 거대한 물통이 있습니다:

```text
[수도꼭지] ──(일정한 속도: 100ms마다 1방울)──> [물통: 최대 3방울 보관 가능]
                                                     │
                                           [손님이 올 때마다 1방울씩 퍼감]
```

- **상황 1: 평화로운 시간 (트래픽 없음)**
  - 손님이 안 오면 물통에 물방울이 최대 용량(3개)까지 꽉 찹니다. 넘친 물은 그냥 버려집니다.
- **상황 2: 갑작스러운 친구 3명의 동시 입장 (버스트 트래픽, Burst)**
  - 평소에 모아둔 물방울이 3개 있으므로, 친구 3명이 동시에 들이닥쳐도 **대기 시간 없이 즉시 3명 모두 입장(`ALLOWED`)**시킵니다!
- **상황 3: 4번째 손님의 무리한 입장 (과부하, Throttled)**
  - 이제 물통이 텅 비었습니다!
  - 경비원은 4번째 손님을 가로막고 말합니다:  
    *"손님! 지금 물통이 비었습니다. 70ms 뒤에 물 한 방울이 채워지니 그때 다시 오세요!"*  
    ──> 🔴 **`429 Too Many Requests (Retry-After: 70ms)`**

이것이 바로 AWS, Stripe, Cloudflare, OpenAI 등 전 세계 모든 빅테크 기업이 사용하는 **토큰 버킷(Token Bucket)** 알고리즘입니다!

---

## 2. 🔍 처리율 제한 4대 알고리즘 전격 비교

| 알고리즘 | 동작 방식 | 장점 | 치명적 단점 |
|---|---|---|---|
| **고정 윈도우 (Fixed Window)** | 1초 단위로 카운터 리셋 | 구현이 가장 단순함 | **윈도우 경계(0.9초~1.1초)에 2배의 트래픽 폭탄** 허용 |
| **이동 윈도우 로그 (Sliding Window Log)**| 모든 요청의 시간을 로그로 저장 | 정밀도 100% 완벽 | 요청 1건마다 타임스탬프 저장으로 **메모리 폭발** |
| **누출 버킷 (Leaky Bucket)** | 큐에 담아 일정 속도로 흘려보냄 | 출력 속도가 완벽히 균일 | 순간적인 **버스트 트래픽도 큐에 갇혀 느려짐** |
| **토큰 버킷 (Token Bucket)** | 물통에 토큰 충전 & 소비 | **순간 버스트 수용 + 메모리 극소 $O(1)$** | 튜닝할 파라미터가 2개(용량, 충전속도) |

---

## 3. ⚡ 지연 평가(Lazy Refill): 타이머 없이 O(1)로 토큰 채우기

초보 개발자들은 "토큰을 일정 시간마다 채워야 한다"고 하면 백그라운드에서 무한 루프나 `setInterval` 타이머를 돌리려 합니다:
```python
# ❌ 절대 금지: 백그라운드 타이머로 100ms마다 토큰 채우기 (CPU 낭비 극심!)
async def refill_loop():
    while True:
        await asyncio.sleep(0.1)
        tokens = min(CAPACITY, tokens + 1)
```

진짜 고수들은 백그라운드 타이머를 일절 쓰지 않는 **지연 평가(Lazy Evaluation)** 기법을 사용합니다:
- **요청이 들어온 바로 그 순간**에만 현재 시각과 지난 요청 시각의 차이($\Delta t$)를 계산하여,
- 그동안 충전되었어야 할 토큰 수를 수학 공식(나눗셈)으로 단 1번에 계산합니다:

$$\Delta tokens = \lfloor \frac{t - t_{last}}{REFILL\_MS} \rfloor$$

- 메모리: 변수 딱 2개(`tokens`, `t_last`)만 사용 ($O(1)$)
- 연산 속도: 나눗셈 1번으로 끝 ($O(1)$)
- 10만 개의 요청이 쏟아져도 0.05초 만에 완벽히 처리됩니다!

## 4. 🌐 HTTP 표준 응답 헤더

실무에서 토큰 버킷 처리율 제한기는 클라이언트에게 다음 표준 헤더를 돌려줍니다:

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
Retry-After: 70
X-RateLimit-Limit: 3
X-RateLimit-Remaining: 0

{
  "error": "rate_limit_exceeded",
  "message": "Too many requests. Please retry after 70 milliseconds."
}
```
