# [ZeliJudge 백서 #027] 옆 동네 서버가 터졌는데 우리 서버까지 죽어요?: 서킷 브레이커(Circuit Breaker)와 장애 격리

> **"마이크로서비스에서 가장 위험한 것은 외부 서버의 에러가 아니라, 외부 서버의 30초짜리 침묵(Timeout)입니다."**

---

## 1. 💡 비전공자 바이브 코더를 위한 현실 비유: "가정집 두꺼비집(누전 차단기)"

가정집 전기 배전반(두꺼비집)에는 **누전 차단기(Circuit Breaker)**가 달려 있습니다:

```text
[정상 상황: CLOSED (스위치 닫힘, 통전)]
전기가 정상적으로 흐릅니다. TV, 냉장고, 세탁기 모두 안전하게 작동합니다.

[합선 발생: OPEN (스위치 열림, 차단)]
거실의 세탁기 모터가 과열되어 펑! 하고 합선되었습니다!
누전 차단기가 없다면? ──> 전선이 타들어가며 아파트 전체에 불이 납니다!
누전 차단기가 있다면? ──> "딱!" 소리와 함께 스위치가 내려가며 세탁기로 가는 전기를 즉시 끊어버립니다!
덕분에 안방의 냉장고와 TV는 화재 없이 안전하게 계속 돌아갑니다!
```

이것이 바로 **서킷 브레이커(Circuit Breaker)** 패턴의 본질입니다!  
외부 결제사(PG사)에 불이 났을 때, 결제사로 가는 전원 스위치를 내려서 **우리 쇼핑몰의 메인 홈과 로그인 서비스가 함께 불타는 연쇄 참사를 막아내는 방화벽**입니다!

---

## 2. 🔍 컴퓨터 과학적 원리: 연쇄 장애 (Cascading Failure)

많은 초보 개발자가 "외부 서버가 에러를 뱉으면 500 에러 뜨고 끝나겠지"라고 안일하게 생각합니다.  
하지만 진짜 재앙은 **"타임아웃(Timeout) 대기"**에서 발생합니다:

```text
[클라이언트 100명 접속]
  │
  ▼
[우리 서버 스레드 풀 (최대 100개)]
  │ 100개의 스레드가 일제히 외부 PG사 결제 API 호출!
  ▼
[외부 결제사 서버: 화재로 응답 불가 (30초 타임아웃)]
  │
  └─ 30초 동안 100개의 스레드가 아무 일도 못 하고 멍하니 대기!
  └─ 스레드 풀 잔여량: 0개! (완전 고갈)
```

- 이때 새로운 사용자가 쇼핑몰 메인 화면(`/`)을 보려고 접속합니다.
- 결제와 아무 상관없는 단순 HTML 조회인데도, **서버에 남아있는 빈 스레드가 0개**이므로 연결이 거절됩니다!
- 외부 서버 1개의 장애가 시스템 전체로 전염되어 **우리 서버의 모든 기능이 도미노처럼 쓰러지는 연쇄 장애(Cascading Failure)**가 완성됩니다.

---

## 3. 🔄 서킷 브레이커 유한 상태 머신 (FSM)

서킷 브레이커는 완벽한 3단계 상태 전이(State Machine)로 동작합니다:

```text
          연속 N회 실패
   ┌───────────────────────────┐
   │                           ▼
┌──────────┐   냉각시간 경과   ┌──────────┐
│  CLOSED  │ ───────────────> │   OPEN   │ (Fast Fail: 외부호출 0회, 0초 만에 거절)
└──────────┘                  └──────────┘
   ▲                               │
   │ 연속 M회 성공                 │ 냉각시간 후 첫 요청
   └─────────── ┌───────────┐ ─────┘
                │ HALF-OPEN │
                └───────────┘
                      │ 1회라도 실패 시
                      └───────────────> OPEN으로 재추락
```

1. **`CLOSED` (닫힘, 정상 가동)**:
   - 모든 트래픽이 외부 API로 정상 통과합니다.
   - 연속 $N$회 에러가 나면 위험을 감지하고 서킷을 `OPEN`으로 전환합니다.
2. **`OPEN` (열림, 전원 차단)**:
   - 외부 API를 **단 1회도 호출하지 않습니다.**
   - 들어오는 모든 요청에 대해 스레드를 낭비하지 않고 **0.001초 만에 즉시 실패(Fast Fail)**시키거나 준비된 기본 데이터(Fallback)를 돌려줍니다.
   - 정해진 냉각 시간(Recovery Timeout) 동안 외부 서버가 쉴 수 있도록 보호합니다.
3. **`HALF-OPEN` (반열림, 정찰병 파견)**:
   - 냉각 시간이 지나면 외부 서버가 살아났는지 조심스럽게 **소수의 시험 요청**만 보내봅니다.
   - 시험 요청이 연속 $M$회 성공하면 "아, 이제 다 나았구나!" 하고 `CLOSED`로 복구합니다.
   - 단 1회라도 실패하면 "아직 아프네" 하고 즉시 `OPEN`으로 되돌아갑니다.

---

## 4. 🛡️ 실무 바이브 코더를 위한 Fallback(대체 응답) 전략

서킷이 `OPEN`되었을 때 단순히 에러 화면을 띄우는 것보다 **대체 응답(Fallback)**을 돌려주면 사용자 경험이 비약적으로 상승합니다:

- **결제 API 장애 시**: *"현재 카드사 전산망 점검 중입니다. 무통장 입금이나 카카오페이를 이용해 주세요."*
- **추천 알고리즘 API 장애 시**: 에러를 내지 않고, 미리 캐싱해 둔 *'실시간 스테디셀러 TOP 10'* 정적 목록 반환.
- **날씨/환율 API 장애 시**: 1시간 전 마지막으로 수집했던 과거 환율 데이터 반환.
