# 이론 설명: B+Tree 동시성 제어와 래치 크래빙(Latch Crabbing)

## 1. 락(Lock)과 래치(Latch)의 결정적 차이
데이터베이스 시스템에서 **락(Logical Lock)**과 **래치(Physical Latch)**는 완전히 서로 다른 목적과 계층에서 동작합니다:

| 구분 | 논리적 락 (Lock) | 물리적 래치 (Latch) |
| :--- | :--- | :--- |
| **보호 대상** | 트랜잭션 단위의 사용자 데이터 (테이블, 레코드) | 메모리 내의 물리적 자료구조 (B+Tree 노드, 버퍼 페이지) |
| **소유자** | 트랜잭션 (Transaction ID) | OS/엔진 워커 스레드 (Worker Thread) |
| **유지 기간** | 트랜잭션 커밋/롤백 시까지 (2PL, 수 밀리초~수 초) | 자료구조 페이지 접근/수정 시에만 (수 마이크로초) |
| **교착상태(Deadlock)** | 데드락 감지 알고리즘(Wait-For Graph) 및 롤백 | 정렬된 래치 획득 순서 규약(Latch Hierarchy)으로 원천 방지 |

---

## 2. 래치 크래빙(Latch Crabbing / Lock Coupling) 프로토콜

### 2.1 검색 연산 (S-Latch Crabbing)
탐색 스레드는 트리의 위에서 아래로 하강하면서 다음 규약을 따릅니다:
1. 루트 노드에 공유 래치(S-Latch)를 획득합니다.
2. 다음 하위 노드를 결정한 후, 하위 자식 노드에 S-Latch를 획득합니다.
3. 자식 노드의 S-Latch가 안전하게 확보되는 즉시, **부모 노드의 S-Latch를 해제**합니다.
4. 리프 노드에 도달하여 원하는 키/값을 읽은 후 리프 S-Latch를 해제합니다.

> **이점**: 탐색 스레드는 하강 도중 최대 2개의 연속된 노드 래치만 일시적으로 보유하며, 대부분의 순간에는 1개의 노드 래치만 유지합니다. 따라서 서로 다른 스레드가 동일한 분기를 차단 없이 동시에 통과할 수 있습니다.

### 2.2 삽입 연산 (X-Latch Crabbing with Safe Node Check)
삽입 스레드는 구조적 분할(Structure Modification Operation, SMO)을 안전하게 처리하기 위해 다음 규약을 따릅니다:
1. 루트 노드에 배타 래치(X-Latch)를 획득하고 보유 스택(`held_latches`)에 추가합니다.
2. 하위 자식 노드로 이동할 때, 자식 노드에 X-Latch를 획득하고 `held_latches`에 추가합니다.
3. **안전 노드(Safe Node) 여부 판정**:
   - 삽입 시 안전 노드의 조건: `len(node.keys) < max_keys`
   - 만약 자식 노드가 안전하다면, 하위 리프에서 분할이 발생하더라도 그 분할 전파가 이 자식 노드에서 멈추므로 **조상 노드들은 절대 수정되지 않습니다**.
   - 따라서 **이 자식 노드의 상위에 있는 모든 조상 노드의 X-Latch를 즉시 해제(`early_unlocked_ancestors`)**하고 스택에서 제거합니다!
4. 자식 노드가 가득 찬 상태(`len(node.keys) >= max_keys`)라면, 최악의 경우 루트까지 분할이 올라올 수 있으므로 조상들의 X-Latch를 계속 잡고 하강합니다.
5. 리프 노드에서 삽입을 완료하고, 필요한 경우 분할을 전파한 후 보유 중인 모든 래치를 해제합니다.

## 3. 왜 전역 래치(Global Latch)는 현대 서버에서 실패하는가?
전역 래치는 트리의 루트 노드 하나에 단일 뮤텍스를 걸어 동시 접근을 제어합니다:
- **직렬화 병목**: 64코어 최신 서버에서 초당 수백만 쿼리를 처리할 때, 각 쿼리가 전역 래치를 독점하면 CPU 코어 63개가 래치 대기 큐에서 스핀(Spin)하거나 슬립(Sleep)합니다.
- 처리량(Throughput)이 스레드 수 증가에 비례해 확장(Scalability)되지 않고 오히려 문맥 교환 오버헤드로 인해 역성장합니다.

## 4. 비동기화(Unsynchronized) 접근 시 발생하는 데이터 레이스 참사
B+Tree 노드가 가득 차서 `[10, 20, 30]`에서 `35`가 추가되어 좌측 `[10, 20]`과 우측 `[30, 35]`로 분할되는 물리적 순간:
1. 메모리 포인터와 배열 복사가 비원자적(Non-atomic)으로 일어납니다.
2. 래치가 없다면, 다른 스레드가 `30`을 찾는 순간 이미 좌측 노드에서는 `30`이 지워졌으나 우측 노드를 가리키는 부모 인덱스 포인터는 아직 갱신되지 않았을 수 있습니다.
3. 결과적으로 데이터베이스에 분명히 존재하는 레코드가 쿼리 결과에서 누락(`read_failures`)되거나 잘못된 메모리 주소를 역참조하여 프로세스가 충돌(Crash)합니다.

래치 크래빙은 이러한 데이터 레이스를 100% 원천 방지하면서도, 상위 조상 노드를 신속하게 조기 언락함으로써 수천 개의 동시 세션에서도 높은 동시성을 보장합니다.
