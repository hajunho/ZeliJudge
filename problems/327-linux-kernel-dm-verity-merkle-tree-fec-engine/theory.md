# Linux Kernel dm-verity: 머클 트리 기반 투명 블록 무결성 검증 심층 분석

## 1. 개요: 불변 인프라와 신뢰 부팅(Verified Boot)의 필요성

전통적인 시스템에서는 악성 코드가 권한 상승(Privilege Escalation)을 통해 `/system` 또는 `/usr` 파티션 내부의 시스템 바이너리(`sshd`, `libc.so`)를 백도어로 변조할 수 있었습니다.
변조된 파일은 파일시스템 검사(fsck)를 거치더라도 정상 파일로 취급되므로 침해 사실을 탐지하기가 극히 어렵습니다.

이를 원천 차단하기 위해 **Google 크롬OS 팀**과 **Android 보안 팀**은 커널 레벨에서 블록 디바이스 전체를 읽기 전용 불변(Immutable) 상태로 고정하고, 블록이 메모리로 읽히는 순간 암호학적으로 변조를 검증하는 **dm-verity**를 개발했습니다.

---

## 2. 머클 트리(Merkle Tree) 아키텍처

파일 단위 해시 서명(IMA/EVM)은 대용량 파일 실행 시 파일 전체를 메모리로 읽어야만 해시를 검증할 수 있어 심각한 메모리 낭비와 I/O 지연을 초래합니다.
반면 `dm-verity`는 4KB 단위 블록 기반 머클 트리를 채택하여 **$O(\log N)$의 블록 단위 온디맨드 검증**을 수행합니다:

1. **데이터 계층 (Level 0 Leaf Nodes)**:
   - 수 기가바이트의 시스템 파티션 블록($D_0, D_1, \dots, D_{N-1}$)의 각 4KB 해시를 계산합니다.
2. **해시 블록 계층 (Intermediate Levels)**:
   - 4KB 해시 블록 하나는 32바이트 SHA-256 해시를 128개까지 담을 수 있습니다.
   - 128개의 하위 해시를 묶어 다시 상위 해시를 계산하는 방식으로 피라미드형 트리를 구축합니다.
3. **루트 해시 (Root Digest)**:
   - 트리의 최정점에 단 하나의 32바이트 해시만이 남습니다.
   - 이 루트 해시만 하드웨어 보안 칩(TPM, TrustZone, Titan-M)에 RSA/ECDSA 서명으로 저장해 두면, 수십 기가바이트의 시스템 파티션 전체의 무결성을 단 하나의 공개키 검증으로 보증할 수 있습니다.

## 3. 리드-솔로몬(Reed-Solomon) 순방향 에러 정정 (FEC)

모바일 기기나 임베디드 장치에서는 플래시 메모리(eMMC, UFS)의 전하 누설이나 고온 환경으로 인해 악의적인 해킹이 아니더라도 자연적인 비트플립(Bit-rot)이 발생할 수 있습니다.
만약 에러 정정 수단이 없다면 단 1비트의 손상으로도 디바이스가 부팅 불가(Brick) 상태에 빠지게 됩니다.

`dm-verity`는 이를 방지하기 위해 **리드-솔로몬(Reed-Solomon RS) 에러 정정 알고리즘**을 옵션(`use_fec`)으로 통합했습니다:
- 파티션 끝부분에 패리티 블록을 추가 저장합니다.
- 데이터 블록이나 머클 트리 해시 블록에서 손상이 감지되면, 커널은 즉시 FEC 엔진을 가동하여 손상된 바이트를 실시간으로 복원합니다.
- 복원에 성공하면 에러 카운터만 기록하고 I/O 요청을 정상 처리함으로써 시스템의 고가용성(High Availability)과 보안성을 동시에 확보합니다.

---

## 4. 실무 적용 사례

1. **Android Verified Boot (AVB)**:
   - 안드로이드 부팅 프로세스에서 부트로더 -> boot -> vendor_boot -> system 파티션의 무결성을 체인으로 검증.
2. **Kubernetes Bottlerocket / CoreOS**:
   - 컨테이너 호스트 OS의 루트 파일시스템을 dm-verity로 잠가 컨테이너 탈출(Container Escape) 공격자가 호스트 커널 모듈이나 바이너리를 수정하는 것을 원천 차단.
3. **systemd-sysext & systemd-homed**:
   - 휴대용 홈 디렉터리 및 시스템 확장 이미지의 불변성 보증.
