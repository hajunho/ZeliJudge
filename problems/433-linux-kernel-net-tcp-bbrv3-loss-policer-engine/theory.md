# Theory #433: 리눅스 커널 TCP BBRv3 혼잡 제어 아키텍처 및 L4S/AccECN 통합

## 1. 혼잡 제어의 진화: Loss-Based에서 BBRv3까지

### 1.1 레거시 손실 기반(Loss-based) 알고리즘의 딜레마
전통적인 TCP Tahoe, Reno, CUBIC은 **패킷 손실(Packet Loss)**이 발생할 때까지 전송 윈도우(`cwnd`)를 선형 또는 3차 함수로 계속 팽창시킵니다.
이는 라우터의 버퍼를 가득 채워 왕복 지연 시간(RTT)을 수백 밀리초까지 폭증시키는 **버퍼블로트(Bufferbloat)**를 초래하며, 대용량 버퍼가 고갈되어 패킷이 일괄 드롭될 때 비로소 전송 속도를 50% 반토막 냅니다.

### 1.2 BBRv1과 BBRv2의 한계
- **BBRv1 (2016)**:
  - 클라인록의 이상적 동작점($BDP = BW_{\text{max}} \times RTT_{\text{min}}$)을 모델링하여 최소 지연과 최대 처리량을 달성했습니다.
  - 그러나 버퍼가 얕은 스위치에서 패킷 손실이 일어나도 대역폭을 줄이지 않아 경쟁 플로우(CUBIC)를 기아 상태로 몰아넣거나, 무선망에서 과도한 재전송을 유발했습니다.
- **BBRv2 (2019)**:
  - 손실(Loss)과 ECN에 반응하도록 설계되었으나, CUBIC과의 공존 환경에서 손실 감지 시 대역폭 추정치를 지나치게 보수적으로 줄여 처리량이 급락하는 역효과가 발생했습니다.

## 2. BBRv3의 핵심 메커니즘 (Linux Kernel 6.x+)

Google이 2023년 공개하고 IETF에 제안한 **BBRv3**는 상용 인터넷 환경의 모든 불확실성(무선망 손실, L4S 초저지연 ECN, ISP 속도 제한기)을 해결하기 위해 4대 핵심 원리를 도입했습니다.

### 2.1 PROBE_BW 4-Subphase 상태 머신
기존의 8단계 사이클을 4단계 파이프라인으로 단순화하고 견고하게 개선했습니다:
1. `PROBE_UP`: `pacing_gain = 1.25`로 설정하여 잠재적 잉여 대역폭이 존재하는지 탐색합니다.
2. `PROBE_DOWN`: 탐색 과정에서 병목 스위치 큐에 쌓인 여분의 패킷을 제거하기 위해 `pacing_gain = 0.75`로 속도를 낮춥니다.
3. `PROBE_CRUISE`: 추정된 실제 대역폭에 맞춰 `pacing_gain = 1.0`으로 순항합니다.
4. `PROBE_REFILL`: 다음 `UP` 탐색에 대비해 파이프를 정확히 $1.0 \times BDP$로 채웁니다.

## 3. 손실 헤드룸(Loss Headroom)과 무선망 보호

모든 패킷 유실이 네트워크 혼잡을 의미하는 것은 아닙니다. 5G/LTE 및 Wi-Fi 환경에서는 채널 간섭, 페이딩(Fading), 핸드오버로 인해 1~2%의 무작위 패킷 드롭이 상시 발생합니다.
- **손실 헤드룸 메커니즘**:
  - BBRv3는 $L_{\text{headroom}}$(기본 2%) 파라미터를 도입했습니다.
  - 측정된 손실률이 2% 이하인 경우, 이는 채널 잡음에 의한 무작위 손실로 판정하여 $BW_{\text{max}}$ 추정치를 전혀 감쇄하지 않습니다.
  - 손실률이 2%를 초과할 때만 실제 큐 오버플로우로 간주하여 초과분에 비례하는 완만한 페널티를 부여합니다.

## 4. 토큰 버킷 폴리서(Token Bucket Policer) 감지

많은 통신사(ISP)와 퍼블릭 클라우드는 SLA를 강제하기 위해 토큰 버킷 레이트 리미터(Policer)를 설치합니다.
- **폴리서의 동작 특성**:
  - 대역폭 초과 패킷을 버퍼에 큐잉(지연)하지 않고 **즉각 드롭**합니다.
  - 따라서 RTT는 최소 RTT($RTT_{\text{min}}$) 부근을 유지하면서도, 전송 속도를 높이는 순간 급격한 패킷 유실이 발생합니다.
- **BBRv3 감지 로직**:
  - $RTT_{\text{sample}} \le 1.15 \times RTT_{\text{min}}$ (큐 적체가 없음)인 상태에서 10% 이상의 대량 손실이 감지되면, 이를 전형적인 **하드웨어 폴리서**로 확정합니다.
  - 즉각 `policer_detected = true`를 선언하고, 현재 전송률을 폴리서 속도($R_{\text{policed}}$)로 상한 고정하여 더 이상의 무의미한 대역폭 프로빙을 중단합니다.

## 5. AccECN / L4S 기반 비례 감쇄 (Proportional ECN Response)

BBRv3는 차세대 초저지연 인터넷 표준인 L4S(Low Latency, Low Loss, and Scalable Throughput / RFC 9330)와 완벽히 호환됩니다.
- 스위치에 미세한 큐가 쌓이기 시작하면 패킷 IP 헤더의 ECN 비트(CE, Congestion Experienced)가 마킹됩니다.
- BBRv3는 최근 1 RTT 동안 도착한 ACK 중 CE 마킹된 바이트의 비율($F_{\text{ecn}}$)을 EWMA 계수 $g = 1/16$로 누적하여 혼잡도 지표 $\alpha$를 계산합니다.
- $\alpha$에 비례하여 $CWND$를 $(1 - \alpha/2)$ 비율로 부드럽게 감쇄함으로써, 1ms 미만의 초저지연을 유지하면서도 패킷 손실을 0건으로 억제합니다.
