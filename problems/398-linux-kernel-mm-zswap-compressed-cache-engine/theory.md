# 398: 리눅스 커널 메모리 관리 — ZSWAP/ZRAM 압축 캐시와 LRU 계층형 스왑 아키텍처 이론

## 1. 메모리 압박과 스왑 I/O의 병목

현대 운영체제에서 물리적 RAM과 보조기억장치(NVMe SSD/HDD) 간의 속도 격차는 여전히 3~4 자릿수(Order of Magnitude)에 달합니다:
- **DRAM 읽기/쓰기 레이턴시**: 약 50~100 나노초(ns)
- **NVMe SSD 랜덤 읽기 레이턴시**: 약 50~100 마이크로초(µs) (DRAM 대비 약 1000배 느림)
- **HDD 랜덤 탐색 레이턴시**: 약 5~10 밀리초(ms) (DRAM 대비 약 10만 배 느림)

프로세스의 익명 페이지를 보조기억장치로 스왑아웃하고 다시 스왑인하는 과정은 심각한 CPU I/O 대기(I/O Wait)를 유발하며, 시스템 전체의 응답성을 마비시키는 스왑 스래싱(Swap Thrashing)의 원인이 됩니다.

---

## 2. ZSWAP의 설계 원리와 동작 메커니즘

리눅스 커널 3.11에 추가된 **ZSWAP (`mm/zswap.c`)** 은 물리적 스왑 파티션 앞단에 위치하는 압축 RAM 캐시입니다.

### 2.1 트레이드오프: CPU 연산 vs 스토리지 I/O
- CPU가 4KB 데이터를 LZ4나 Zstandard로 압축/해제하는 데 걸리는 시간은 약 1~5 마이크로초(µs)에 불과합니다.
- 디스크에 4KB를 쓰고 읽는 시간(50~500µs)에 비해 최소 10배~50배 빠릅니다.
- 즉, **약간의 CPU 사이클을 지불하여 느린 스토리지 I/O를 완전히 상쇄**하는 것이 Zswap의 핵심 경제학입니다.

### 2.2 Zswap 풀 관리와 zpool 메모리 할당자
Zswap은 단편화 없는 압축 청크 관리를 위해 특수 메모리 할당자(`zsmalloc`, `zbud`, `z3fold`)를 사용합니다:
- `zsmalloc`: 여러 개의 압축 객체를 묶어 4KB 페이지 프레임에 빽빽하게 패킹함으로써 메모리 낭비(슬랙)를 최소화합니다.

### 2.3 동일 바이트(Same-Filled) 감지
수많은 서버 프로세스는 초기화된 대형 버퍼나 제로 페이지(Zero Page)를 메모리에 상주시키고 있습니다. Zswap은 페이지의 모든 4096바이트가 일치하는지 $O(N)$으로 검사하여, 일치할 경우 압축조차 거치지 않고 메타데이터로만 0바이트 저장합니다. 이는 전체 압축 풀 효율을 극대화합니다.

### 2.4 LRU 기반 계층형 라이트백 (Tiered Writeback)
RAM은 유한하므로 Zswap 풀이 가득 찼을 때 새 페이지를 위해 공간을 만들어야 합니다. Zswap은 독자적인 LRU 리스트를 유지하여, 가장 접근되지 않은 콜드 페이지를 골라 압축 해제 후 물리 스왑 디스크로 내보냅니다. 이를 통해 자주 접근되는 핫 페이지는 초고속 RAM zswap에 유지되고, 진정한 콜드 데이터만 느린 디스크로 강등(Demote)되는 2계층(Tiered) 스왑 아키텍처가 완성됩니다.

---

## 3. 결론

Zswap은 서버의 유효 메모리 용량을 1.5배~2배 확장하는 동시에, I/O 병목을 획기적으로 낮추어 클라우드 인프라의 TCO 절감과 컨테이너 밀집도를 극대화하는 리눅스 가상 메모리 관리의 핵심 엔진입니다.
