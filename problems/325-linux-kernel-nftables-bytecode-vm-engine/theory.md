# Linux 커널 Netfilter nftables: 레지스터 VM 아키텍처 및 세트 분류 심층 분석

## 1. iptables의 한계와 nftables의 탄생 배경

20년 넘게 리눅스 방화벽의 표준으로 군림했던 `iptables`는 뛰어난 안정성에도 불구하고 현대 클라우드/컨테이너 환경에서 심각한 구조적 한계에 부딪혔습니다:
1. **모놀리식 C 코드 확장(Match & Target Extensions)**:
   - `iptables`는 프로토콜별, 기능별로 각각 별도의 커널 모듈(`ipt_recent`, `ipt_limit`, `xt_tcp` 등)을 작성해야 했습니다. 유사한 비교 로직이 수십 개의 모듈에 중복 구현되어 커널 코드 베이스가 비대해졌습니다.
2. **거대한 규칙 덤프 및 원자적 교체 비용**:
   - 단 하나의 규칙을 추가하거나 수정할 때도 테이블 전체 메모리 블록을 통째로 유저스페이스로 복사(Dump)한 뒤, 수정본을 다시 커널로 원자적 전송(Atomic Replacement)해야 했습니다. 규칙이 수만 개인 대규모 쿠버네티스 노드에서는 iptables 갱신 시 수 초 동안 패킷 포워딩 지연 및 CPU 스파이크가 발생했습니다.
3. **선형 탐색($O(N)$) 병목**:
   - 패킷마다 체인의 첫 번째 규칙부터 마지막 규칙까지 선형으로 순회하므로, 규칙 수가 증가함에 따라 네트워크 처리량(Throughput)이 급격히 저하되었습니다.

이 문제를 근본적으로 해결하기 위해 **패트릭 맥하디(Patrick McHardy)**와 넷필터 핵심 개발팀은 **nftables**를 설계했습니다.

## 2. 레지스터 기반 가상 머신(Register-based VM) 구조

`nftables`의 핵심 설계 철학은 **"커널은 단순하고 극도로 빠른 인터프리터(VM)만 제공하고, 복잡한 정책 해석과 최적화는 유저스페이스(`nft`)가 담당한다"**는 것입니다.

### 레지스터 메모리 레이아웃
`nftables` 커널 루프(`net/netfilter/nf_tables_core.c: nft_do_chain`)는 스택 프레임에 로컬 구조체 `struct nft_regs`를 할당합니다:
```c
struct nft_regs {
    union {
        u32             data[20];
        struct nft_verdict verdict;
    };
};
```
- **평결 레지스터(`NFT_REG_VERDICT`)**:
  규칙 평가 상태 및 결과를 저장합니다:
  - `NFT_CONTINUE`: 현재 규칙 평가 완료, 다음 규칙으로 전진.
  - `NFT_BREAK`: 조건 불일치, 현재 규칙 탈출 후 다음 규칙으로 전진.
  - `NF_ACCEPT` / `NF_DROP`: 최종 커널 평결, 체인 평가 즉시 종료.
  - `NFT_JUMP` / `NFT_GOTO`: 서브 체인으로 분기.
  - `NFT_RETURN`: 서브 체인에서 복귀.
- **데이터 레지스터(`NFT_REG32_00` ~ `NFT_REG32_15`)**:
  패킷 헤더에서 추출한 필드(IPv4 주소 4바이트, TCP 포트 2바이트 등)나 연산 중간 결과를 저장하는 32비트 레지스터 16개.

## 3. 표현식(Expression) 추상화와 직교성(Orthogonality)

`nftables`의 모든 필터링 로직은 단 몇 가지의 단순하고 직교적인 빌딩 블록 표현식(`struct nft_expr_ops`)의 조합으로 완성됩니다:
- `nft_payload`: 네트워크 계층(`skb_network_header`) 또는 전송 계층(`skb_transport_header`)에서 지정된 오프셋과 길이의 바이트를 추출하여 대상 레지스터에 로드합니다.
- `nft_cmp`: 레지스터 값과 즉치값을 $==, 
eq, <, \le, >, \ge$ 연산자로 비교합니다.
- `nft_bitwise`: 불필요한 비트를 마스킹하거나 플래그를 추출합니다: `(sreg & mask) ^ xor`.
- `nft_lookup`: 레지스터에 로드된 키를 바탕으로 집합(Set)이나 사전(Map)을 조회합니다.
- `nft_dynset`: 연결 수 제한이나 악성 IP 차단을 위해 실시간으로 요소를 셋에 추가/갱신하고 타임아웃을 부여합니다.

이러한 모듈식 직교성 덕분에 커널은 새로운 프로토콜 헤더가 등장하더라도 커널 코드를 단 한 줄도 수정하지 않고 유저스페이스 컴파일러 업데이트만으로 완벽히 지원할 수 있습니다.

## 4. 1급 객체 집합(Set)과 동적 가비지 컬렉션(GC)

`nftables`의 가장 강력한 기능 중 하나는 내장된 고성능 집합 인프라입니다:
1. **타입별 백엔드 최적화**:
   - 비트맵 셋(`nft_set_bitmap`): 포트 번호와 같이 0~65535 범위의 정밀한 연속 정수용 ($O(1)$).
   - 해시 셋(`nft_set_hash`): 무작위 IPv4/IPv6 IP 블랙리스트용 ($O(1)$).
   - 레드-블랙 트리 셋(`nft_set_rbtree`): CIDR 서브넷 범위(예: 10.0.0.0/8) 및 포트 범위 탐색용 ($O(\log N)$).
2. **동적 셋(Dynamic Sets)과 상태성(Statefulness)**:
   - `DYNSET` 표현식은 데이터 플레인(Data plane)에서 실시간으로 IP나 세션을 셋에 삽입합니다.
   - 각 요소는 생성 시각(`created_ts`)과 유효 기간(`timeout_ms`)을 가집니다.
   - 패킷 평가 주기 또는 백그라운드 워커에서 만료된 엔트리를 자동으로 수거(GC)함으로써 메모리 누수를 원천 차단하고 SYN Flood 및 DDoS 방어를 제로 오버헤드로 수행합니다.
