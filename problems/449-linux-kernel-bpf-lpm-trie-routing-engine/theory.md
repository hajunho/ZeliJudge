# 심층 시스템 이론: 리눅스 커널 BPF_MAP_TYPE_LPM_TRIE (`kernel/bpf/lpm_trie.c`) 및 RCU-Safe 패트리샤 트라이 라우팅 아키텍처

## 1. 최장 접두사 일치(LPM)와 eBPF 데이터 패스의 과제

소프트웨어 정의 네트워킹(SDN) 및 서비스 메시(Cilium, Katran, Calico) 환경에서 패킷 포워딩 및 ACL 검사는 모든 인그레스 패킷마다 수행되는 핵심 연산입니다.

### 1) 전통적인 라우팅 알고리즘의 문제점
- **선형 탐색(Linear Array Scan)**: 규칙 수 $N$에 비례하여 $O(N)$ 시간이 소요되므로 수천 개 이상의 규칙에서 와이어스피드(100Gbps) 처리가 불가능.
- **해시 테이블 체인(Hash Table per Prefix Length)**: IPv4 기준 33개의 해시 테이블을 역순 탐색. 해시 연산 오버헤드와 캐시라인 미스가 매 홉마다 누적됨.
- **이진 기수 트라이(Binary Radix Tree)**: 비트 단위로 분기하는 트라이 구조는 $O(W)$ ($W$는 주소 비트 길이, IPv4=32, IPv6=128)에 수렴하여 규칙 수 $N$과 무관하게 일정한 탐색 시간을 보장함.

## 2. 리눅스 커널 lpm_trie의 메모리 구조 및 비트 슬라이싱

리눅스 커널 `kernel/bpf/lpm_trie.c`의 노드 구조:

```c
struct lpm_trie_node {
    struct rcu_head rcu;
    struct lpm_trie_node __rcu *child[2];
    u32 prefixlen;
    u32 flags;
    u8 data[0];
};
```

### 1) RCU 기반 무잠금 탐색 (Lockless Traversal)
- `child[0]`과 `child[1]` 포인터는 `__rcu` 어노테이션이 부여되어 있습니다.
- 패킷 수신 패스트패스(XDP 훅)에서 eBPF 프로그램은 스핀락이나 뮤텍스를 전혀 획득하지 않고 `rcu_read_lock()` 상태에서 트라이를 하향 순회합니다.
- 쓰기 작업(노드 삽입, 분할, 삭제)은 신규 노드를 먼저 메모리에 구성한 후 `rcu_assign_pointer()`를 통해 원자적으로 포인터를 교체합니다.
- 제거된 노드는 유예 기간(Grace Period)이 지난 후 `call_rcu()`에 의해 안전하게 해제됩니다.

### 2) 공통 접두사 분할 (Prefix Splitting)
기존에 `172.16.1.0/24`가 있는 상태에서 `172.16.2.0/24`가 삽입될 때:
- 두 주소의 상위 22비트는 동일하지만 23번째 비트부터 달라집니다.
- 커널은 22비트 길이의 **중간 분기 노드(Intermediate Node)**를 동적 할당하고, 두 서브넷을 각각 좌측(0)과 우측(1) 자식으로 매답니다.
- 이 분기 노드는 자체적으로 매핑된 라우팅 데이터가 없는 순수 내비게이션 노드(`is_value_node = false`)입니다.

```
                  [Intermediate Node /22 (172.16.0.0)]
                                  │
                  ┌───────────────┴───────────────┐
             bit 23 = 0                      bit 23 = 1
                  │                               │
                  ▼                               ▼
       [Node /24 (172.16.1.0)]         [Node /24 (172.16.2.0)]
       (Action: Route US-East)         (Action: Route US-West)
```

## 3. 최장 접두사 일치(Longest Prefix Match) 탐색 불변식

트라이 순회 중 쿼리 IP $Q$에 대해:
1. 루트 노드부터 시작하여 현재 노드의 비트 마스크와 $Q$의 상위 비트를 비교합니다:
   $$\text{mask}(Q, \text{node.prefixlen}) == \text{node.ip}$$
2. 일치하고 해당 노드가 유효한 데이터(`is_value_node`)를 가지고 있다면, `best_match` 포인터를 현재 노드로 갱신합니다.
3. $Q$의 `node.prefixlen`번째 비트를 읽어 다음 자식 노드로 이동합니다.
4. 더 이상 일치하는 자식이 없으면 탐색을 종료하고 마지막으로 기록된 `best_match`의 값을 반환합니다.

이를 통해 `192.168.1.100`을 조회할 때 `/0` (기본 게이트웨이), `/16` (사설망), `/24` (파드 서브넷), `/32` (파드 호스트) 규칙이 공존하더라도, 가장 구체적이고 긴 마스크를 가진 `/32` 규칙이 $O(1)$의 결정론적 시간 안에 완벽하게 선택됩니다.

## 4. 노드 삭제 및 트라이 축약 (Trie Collapse)

규칙이 삭제되어 노드가 비활성화되면 트라이는 불필요한 중간 노드로 인해 메모리가 낭비되고 탐색 깊이가 길어지는 문제를 겪을 수 있습니다.

### 1) 바이패스 축약 (Bypass Collapse)
어떤 중간 노드가 단 하나의 자식만을 가지게 된 경우:
- 해당 중간 노드는 더 이상 분기 역할을 수행하지 못하는 잉여 노드입니다.
- 커널은 부모 노드의 포인터를 자식으로 직접 연결하여 중간 노드를 RCU-체인에서 우회(Bypass) 및 회수합니다.
- 이를 통해 트라이의 깊이를 항상 최소로 유지하며 캐시 효율성을 극대화합니다.

---

## 5. 결론 및 실무적 의미

`BPF_MAP_TYPE_LPM_TRIE`는 대규모 쿠버네티스 클러스터와 분산 데이터센터의 트래픽 라우팅 및 보안 정책 집행에서 대체 불가능한 핵심 데이터 구조입니다.
비트 조작 기반의 패트리샤 트라이와 리눅스 RCU 동시성 모델의 결합은 현대 운영체제 커널이 제공하는 알고리즘적 우아함의 정점을 보여줍니다.
