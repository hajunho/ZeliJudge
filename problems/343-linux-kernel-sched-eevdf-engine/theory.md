# Theory: Linux 6.6 Kernel EEVDF (Earliest Eligible Virtual Deadline First) Scheduler

## 1. 배경: CFS의 한계와 EEVDF로의 대전환

리눅스 커널 2.6.23(2007)부터 채택되었던 **CFS(Completely Fair Scheduler)**는 레드-블랙 트리(Red-Black Tree)를 이용하여 가장 작은 가상 런타임($v_i$)을 가진 태스크를 항상 선택하는 방식으로 완벽한 공정성(Fairness)을 보장했습니다.

그러나 현대 컴퓨팅 환경에서 다음과 같은 **치명적인 구조적 결함**이 지속적으로 드러났습니다:
1. **반응성(Latency)과 처리량(Throughput)의 딜레마**: 오디오 버퍼링, 웹 렌더링, 고빈도 거래(HFT) 등 즉각적인 반응이 필요한 작업도 CFS에서는 $v_i$가 가장 작아질 때까지 대기해야만 했습니다.
2. **휴리스틱의 한계**: 이를 우회하기 위해 커널 개발자들은 깨어난 태스크의 $v_i$를 깎아주는 `latency-nice`, `min_vruntime` 휴리스틱을 덕지덕지 추가했으나, 이는 배치(Batch) 작업의 기아 현상이나 불필요한 문맥 전환 폭풍(Context-switch storm)을 야기했습니다.

이를 근본적으로 해결하기 위해 2023년 리눅스 커널 6.6에서 Ingo Molnar와 Peter Zijlstra는 Peter Hoon의 1995년 논문 *"Earliest Eligible Virtual Deadline First (EEVDF)"*을 커널에 이식하여 스케줄러를 전면 교체했습니다.

---

## 2. EEVDF의 수학적 원리

EEVDF는 태스크 선택을 **적격성(Eligibility)**과 **긴급성(Deadline)**이라는 독립된 두 차원으로 분리합니다.

### 2.1 지연(Lag)과 적격성 (Eligibility)
이상적인 유체 흐름 모델(Fluid Flow Model)에서 시간 $t$ 동안 시스템의 평균 가상 시간 $V(t)$는 전체 가중치 $W$에 비례하여 흐릅니다:
$$V(t) = \int_0^t \frac{1024}{W(\tau)} d\tau$$

태스크 $i$가 실제로 소비한 가상 시간 $v_i(t)$와의 차이를 **지연(Lag)**이라고 정의합니다:
$$L_i(t) = V(t) - v_i(t)$$
- $L_i(t) > 0$: 해당 태스크가 자신의 권리보다 덜 실행됨 (시스템이 태스크에 빚을 짐).
- $L_i(t) < 0$: 해당 태스크가 자신의 권리보다 더 많이 실행됨 (태스크가 미래의 시간을 가불해 씀).

**핵심 규칙 (Eligibility)**:
오직 **$L_i(t) \ge 0$ (즉 $v_i(t) \le V(t)$)**인 태스크만이 CPU를 점유할 자격이 있습니다. 아무리 마감시간이 급해도, 이미 자신의 할당량을 초과 소비한 태스크는 다른 태스크가 따라올 때까지 선택되지 못합니다.

### 2.2 가상 마감시간 (Virtual Deadline)
태스크가 요구하는 타임 슬라이스 $q_i$ (`slice_ns`)에 대해 가상 마감시간 $d_i$는 다음과 같이 정의됩니다:
$$d_i = v_i + \frac{q_i \times 1024}{w_i}$$
- **지연 민감형 작업**: 작은 슬라이스 $q_i$ (예: 1ms)를 요청하므로 마감시간 $d_i$가 매우 가깝습니다. 따라서 적격 상태가 되자마자 즉각 CPU를 선점합니다.
- **처리량 지향 작업**: 큰 슬라이스 $q_i$ (예: 10ms)를 요청하므로 마감시간 $d_i$가 멀리 떨어져 있습니다. 한번 CPU를 잡으면 문맥 전환 없이 길게 실행되지만, 지연 민감형 작업이 적격해지면 기꺼이 양보합니다.

## 4. 커널 구현 디테일 및 장점

1. **단일 RB-Tree 아키텍처**: 리눅스 커널 `fair.c`에서는 $v_i$ 기준의 메인 RB-트리와 함께 서브트리별 최소 마감시간(`min_deadline`)을 증강 트리(Augmented Tree)로 유지하여 $O(\log N)$에 최적 후보를 탐색합니다.
2. **수면 후 복귀 시 클램핑**: 태스크가 오랫동안 잠들었다가 깨어났을 때 과거의 막대한 양의 Lag($L_i \gg 0$)를 악용하여 CPU를 독점하는 것을 막기 위해, $v_i \leftarrow \max(v_i, V)$로 재설정합니다.
