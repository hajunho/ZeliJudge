## 🔑 1. 일상 비유: 공장제 열쇠와 마스터키, 그리고 마법의 소금(Salt)

어느 아파트 단지의 경비원(초보 개발자)이 주민들의 안전을 위해 집 열쇠를 관리하기로 했습니다.
* 경비원의 생각:
  *"열쇠에 적힌 진짜 비밀번호(`123456`)를 장부에 적어두면 위험하니까, 열쇠의 홈 모양(해시값)만 장부에 복사해서 적어둬야지!"*

그런데 전문 털이범(해커)이 나타났습니다.
털이범은 전 세계에서 가장 흔하게 쓰이는 자물쇠 열쇠 1억 개의 홈 모양을 미리 다 본떠서 모아둔 **'마스터키 사전 (레인보우 테이블)'**을 가방에 넣고 다녔습니다.
* 경비실 장부를 훔친 털이범은 장부에 적힌 홈 모양을 자기 사전에서 검색했습니다.
* **단 0.001초 만에** *"아, 이 홈 모양은 `123456`번 열쇠네!"* 하고 원본 열쇠를 그대로 복제해 주민들의 집을 털어버렸습니다.

이때 보안 전문가가 나타나 경비원에게 비법을 전수했습니다:
> *"열쇠를 만들 때, 집집마다 앞마당에서 가져온 **무작위 흙과 자갈(Salt, 소금)**을 한 줌씩 섞어서 열쇠 표면에 거칠게 붙여버리세요!*
> *그럼 주민 100명이 똑같이 `123456`번 열쇠를 쓰더라도, **섞인 흙 모양이 집마다 천차만별이라 세상에 똑같은 열쇠가 단 하나도 없게 됩니다!** 도둑의 마스터키 사전은 무용지물이 됩니다!"*

이것이 바로 컴퓨터 과학에서 비밀번호를 지키는 핵심 방패, **솔트(Salt)**의 원리입니다.

## 🧮 2. 단방향 해시(One-Way Hash)의 진실: "복호화 불가"의 착각

초보 개발자들은 `hashlib.sha256()`을 쓰면서 이렇게 믿습니다:
> *"SHA-256은 단방향 함수니까, 해시값(`8d969...`)에서 원본 비밀번호(`123456`)를 수학적으로 거꾸로 되돌리는 복호화(Decryption)는 불가능해! 그러니까 안전해!"*

수학적으로 역연산이 불가능하다는 말은 사실입니다.
하지만 해커는 **수학 문제를 풀 생각 따위는 처음부터 없었습니다.**

### 해커의 무기: 레인보우 테이블 (Rainbow Table)
해커들은 전 세계 사람들이 자주 쓰는 수억 개의 단어(`password`, `qwerty`, `admin`, `love1234`)를 이미 다 알고 있습니다.
그래서 해커는 자신의 고성능 GPU 서버를 며칠 돌려서 미리 거대한 표를 만들어 둡니다:

| 평문 비밀번호 (Plaintext) | SHA-256 해시값 (미리 계산된 해시) |
| :--- | :--- |
| `123456` | `8d969eef6ecad3c29a3a629280e686cf0c3f5d5a86aff3ca12020c923adc6c92` |
| `password` | `5e884898da28047151d0e56f8dc6292773603d0d6aabbdd62a11ef721d1542d8` |
| `admin` | `8c6976e5b5410415bde908bd4dee15dfb167a9c873fc4bb8a81f6f2ab448a918` |

이제 해커가 탈취한 DB에서 `8d969eef...`라는 해시값을 보는 순간, 계산할 필요도 없이 사전에서 **"찾기(Ctrl + F)"**만 누르면 0초 만에 원본 `123456`이 그대로 튀어나옵니다!

## 🧂 3. 솔트(Salt)의 2대 방어 원리

솔트(Salt)란, 비밀번호를 해싱하기 전에 **유저마다 각자 다르게 생성해 부여하는 무작위 난수 문자열**입니다.

```python
# [위험한 단순 해시]
hash = sha256("123456")

# [안전한 솔트 해시]
salt = "x7K$9pL2"  # 유저마다 고유한 무작위 문자열
hash = sha256(salt + "123456")  # sha256("x7K$9pL2123456")
```

### 1) 레인보우 테이블 공격의 완전한 무력화
해커가 솔트가 적용된 비밀번호를 레인보우 테이블로 뚫으려면,
기존의 `123456`뿐만 아니라 `aaaa123456`, `aaab123456`, ... 모든 가능한 솔트의 조합을 미리 다 해싱해 두어야 합니다.
하지만 솔트 길이가 16자만 되어도 가능한 경우의 수가 $62^{16} \approx 4.7 \times 10^{28}$개에 달하여, **전 우주의 모든 하드디스크를 다 합쳐도 사전을 저장할 수 없게 됩니다.** 레인보우 테이블이 원천적으로 불가능해집니다!

### 2) 동일 비밀번호 사용자 간의 해시 분리
솔트가 없으면 `123456`을 쓰는 1,000명의 해시값이 전부 똑같이 보입니다. 해커는 한 사람의 비밀번호만 알아내도 1,000명의 계정을 동시에 털 수 있습니다.
하지만 솔트를 치면, 1,000명이 모두 똑같은 `123456`을 쓰더라도 **솔트가 제각각 다르기 때문에 1,000개의 해시값이 완전히 다른 외계어**로 저장됩니다!

## 🚨 4. 실무 백엔드 개발자 수칙: SHA-256도 부족하다?

놀랍게도 현대 정보보안에서는 **단순 SHA-256 + Salt조차도 비밀번호 저장용으로는 불충분**하다고 경고합니다.
왜일까요?

> **"SHA-256은 컴퓨터에게 너무 빠르다!"**

SHA-256은 원래 수 기가바이트의 대용량 파일을 1초 만에 검증하기 위해 **초고속으로 동작하도록 설계**된 함수입니다.
최신 그래픽카드(GPU) 1장을 쓰면 해커는 1초에 수십억 번의 SHA-256 해시를 무차별 대입(Brute-Force)할 수 있습니다.

### 현대 표준: 느린 해시 함수 (Slow KDF)
그래서 현대 웹 표준(OWASP 권장)은 컴퓨터가 일부러 수천 번~수만 번 해시를 반복 계산하여 **1번 검증에 0.1초 정도 걸리도록 의도적으로 늦춘 키 유도 함수**를 사용합니다:
1. **Argon2id** (현재 가장 강력한 국제 표준)
2. **bcrypt** (가장 널리 쓰이는 표준)
3. **PBKDF2** (FIPS 인증 표준)

```python
# [현업 프로덕션의 표준 비밀번호 암호화 (bcrypt 예시)]
import bcrypt

# 회원가입 시: 솔트 자동 생성 및 고속 공격 방지 반복 해싱
hashed = bcrypt.hashpw(password.encode('utf-8'), bcrypt.gensalt())

# 로그인 검증 시
if bcrypt.checkpw(input_password.encode('utf-8'), hashed):
    print("로그인 성공!")
```
