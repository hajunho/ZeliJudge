# 이론 설명: 2PC 블로킹 문제와 3PC 비차단 프로토콜 (Skeen's Theorem)

## 1. 2단계 커밋(2PC)의 구조와 불확실성 구간 (Window of Uncertainty)
2PC에서 참여자 노드가 `YES`를 투표하고 `PREPARED` 상태에 머무는 구간을 **불확실성 구간(Uncertainty Window)**이라고 부릅니다.

```
[코디네이터]                     [참여자 P1]                  [참여자 P2]
     |                                |                           |
     |---- PREPARE ------------------>|                           |
     |---- PREPARE ---------------------------------------------->|
     |<--- VOTE YES ------------------| [PREPARED: 락 획득]         |
     |<--- VOTE YES ----------------------------------------------| [PREPARED: 락 획득]
     |
  [CRASH!] <--- 코디네이터 사망!
     X
                                [P1: 커밋인지 롤백인지 모름!]   [P2: 커밋인지 롤백인지 모름!]
                                [영구 대기 (BLOCKED)]          [영구 대기 (BLOCKED)]
```

### 왜 2PC에서는 참여자들끼리 결정할 수 없는가?
- 만약 P1과 P2가 서로 통신해서 "우리 둘 다 YES를 냈으니 커밋하자!"라고 결정한다면:
  - 코디네이터가 죽기 직전에 다른 노드(P3)의 `NO`를 받고 `ABORT`를 로컬에 쓴 뒤 죽었을 수 있습니다.
  - 이 경우 P1, P2는 커밋하고 P3는 롤백하여 **원자성(Atomicity)이 깨지고 데이터가 찢어집니다(Split-Brain)**.
- 반대로 "코디네이터가 안 오니 롤백하자!"라고 결정한다면:
  - 코디네이터가 죽기 직전에 P1에게는 못 보냈지만 P2에게는 `COMMIT`을 보내고 죽었을 수 있습니다.
- 따라서 2PC의 `PREPARED` 상태에서는 **코디네이터가 살아 돌아올 때까지 모든 락을 쥔 채 무기한 블로킹되어야만 합니다 (Skeen의 정리)**.

## 2. 3단계 커밋(3PC)의 핵심 원리: 상태 전이 격리
Dale Skeen 박사는 2PC의 준비와 커밋 사이에 **Pre-Commit**이라는 중간 상태를 삽입함으로써, **"어떤 노드도 커밋 상태일 수 없는 상태"**와 **"모든 노드가 준비 완료된 상태"**를 엄격히 분리했습니다:

```
[2PC 상태 전이]
INIT -> PREPARED -> COMMITTED / ABORTED
        (동시 존재 가능: 불확실성!)

[3PC 상태 전이]
INIT -> PREPARED -> PRE_COMMIT -> COMMITTED
           |
           v
        ABORTED
```

### 3PC 불변식 (Invariants):
1. **불변식 1**: 어떤 노드가 `COMMITTED` 상태에 있다면, 다른 모든 노드는 최소한 `PRE_COMMIT` 상태 이상에 도달해 있어야 합니다.
2. **불변식 2**: 어떤 노드가 `PRE_COMMIT` 상태에 있다면, 모든 노드가 이미 `YES`를 투표했음이 보장됩니다.
3. **불변식 3**: 어떤 노드가 `PREPARED` 상태에만 머물러 있다면, 그 어떤 노드도 `COMMITTED` 상태에 도달할 수 없습니다.

이 3가지 불변식 덕분에, 코디네이터가 사망했을 때 남은 참여자들은 서로의 상태만 교환하여:
- 단 한 명이라도 `PRE_COMMIT`을 보았다면 -> **전원 커밋 결정**
- 전원이 `PREPARED` 이하에 머물러 있다면 -> **전원 롤백 결정**
으로 안전하게 자가 종결(Non-blocking Termination)할 수 있습니다.

## 3. 현대 분산 시스템의 선택: 3PC 대신 Raft/Paxos 2PC
이론적으로 3PC는 훌륭하지만, 현실의 네트워크 파티션(Split-Brain) 환경에서는 비동기 네트워크 지연으로 인해 분할된 양쪽 진영이 서로 다른 결정을 내릴 수 있는 취약점이 있습니다.
따라서 Google Spanner, CockroachDB 등 최신 분산 DB는 **코디네이터 그룹 자체를 Raft/Paxos 합의 클러스터로 다중화한 Paxos-backed 2PC**를 채택하여 2PC의 블로킹 취약점을 완벽하게 극복했습니다.
