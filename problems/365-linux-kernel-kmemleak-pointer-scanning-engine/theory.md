# Linux Kernel Kmemleak (Kernel Memory Leak Detector) 아키텍처 및 포인터 스캐닝 심층 분석

## 1. 개요 및 설계 동기

리눅스 커널은 수천만 줄의 C 코드로 구성되어 있으며, 복잡한 에러 처리 경로(error handling paths), 조건부 `goto out_err;` 레이블, 그리고 비동기 RCU 콜백 등이 얽혀 있어 메모리 누수가 발생하기 매우 쉽습니다.

사용자 공간과 달리 커널 공간에서는 주소 공간이 고갈되면 커널 패닉(Kernel Panic)이나 OOM-Killer가 연쇄적으로 시스템 중요 프로세스를 강제 종료시키게 됩니다.

카탈린 마리카(Catalin Marinas, ARM 커널 메인테이너)가 2009년 Linux 2.6.31에 제안하여 머지된 **kmemleak(`mm/kmemleak.c`)**은 커널을 재컴파일하지 않고도 운영 중인 시스템에서 실시간으로 누수된 메모리 블록을 추적하는 진단 도구입니다.

---

## 2. 포인터 스캐닝과 3색 마킹 (Tri-color Marking)

kmemleak은 다익스트라(Dijkstra)의 3색 가비지 컬렉션(Tri-color GC) 알고리즘을 차용하여 작동합니다:

### 2.1 객체 트리 인덱싱
모든 동적 할당 함수(`kmalloc`, `kmem_cache_alloc`, `vmalloc` 등)는 내부적으로 `kmemleak_alloc()`을 호출하여 할당된 메모리 블록을 표현하는 `struct kmemleak_object`를 생성하고, 전역 레드-블랙 트리(`object_tree_root`)에 삽입합니다.

### 2.2 내부 포인터(Interior Pointer)의 수용
C 언어에서는 구조체의 시작 주소(`ptr`)뿐만 아니라, 구조체 내부의 특정 멤버 변수 주소(`ptr + offset`)를 가리키는 포인터가 빈번하게 사용됩니다 (예: `container_of` 매크로, `list_head` 임베딩).
따라서 kmemleak은 어떤 포인터 값 $V$가 주어졌을 때 다음과 같은 범위 포함 여부를 레드-블랙 트리로 검색합니다:
$$\text{object.ptr} \le V < \text{object.ptr} + \text{object.size}$$
이 조건이 성립하면 해당 객체는 유효하게 참조되고 있는 것으로 인정됩니다.

### 2.3 스캔 루프 (The Scan Loop)
1. **초기화**: 모든 활성 객체의 `count`를 0으로 리셋.
2. **루트 등록**:
   - 데이터 섹션(`.data`, `.bss`), 프로세스 커널 스택(Task Stacks), 모듈 데이터 영역 등 전역 메모리 영역을 스캔하여 발견된 포인터의 목적지 객체 `count`를 증가시킵니다.
   - `min_count == 0`으로 지정된 객체(영구 루트)를 Gray 리스트에 추가합니다.
3. **Gray 리스트 순회 (BFS)**:
   - Gray 리스트에서 객체를 하나씩 꺼내어, 그 객체가 점유하는 모든 메모리 워드를 스캔합니다.
   - 워드 값 중 다른 커널 객체를 가리키는 포인터가 있으면 그 피참조 객체의 `count`를 증가시키고, 피참조 객체의 `count >= min_count`가 되면 그 객체를 다시 Gray 리스트에 추가합니다.
4. **White 객체 판별 및 에이징 (Aging)**:
   - 스캔이 끝난 후에도 `count < min_count`인 객체는 도달 불가능한 White 객체입니다.
   - 일시적인 참조 단절이나 레이스 컨디션으로 인한 거짓 양성을 방지하기 위해, White 객체는 즉시 누수로 단정되지 않고 `unreferenced_cycles` 카운터를 증가시킵니다.
   - 이 카운터가 `scan_threshold_cycles`에 도달하면 최종 메모리 누수(`confirmed_leaks`)로 판정되어 스택 트레이스와 함께 관리자에게 보고됩니다.

## 3. 거짓 양성(False Positive) 완화 기법

커널 코드에는 포인터 스캐너의 시야를 벗어나는 다양한 트릭이 존재합니다:
1. **포인터 태깅(Pointer Tagging)**: 포인터의 하위 2~3비트에 플래그를 저장(예: x86_64 8바이트 정렬 시 하위 3비트는 항상 0이므로 이를 플래그로 활용). 스캐너는 이를 유효하지 않은 주소로 오판할 수 있습니다.
2. **XOR 마스킹 / 암호화 버퍼**: 보안 버퍼나 압축 알고리즘 내부의 가리킴.
3. **완화 API**:
   - `kmemleak_not_leak(ptr)`: 해당 객체의 `min_count = 0`으로 설정. 외부에서 가리키지 않더라도 누수가 아니며, 이 객체 내부의 포인터들은 계속 탐색.
   - `kmemleak_ignore(ptr)`: 객체에 `KMEMLEAK_BLACK` 플래그 부여. 스캔 대상에서 완전 제외.

## 4. 복잡도 및 최적화

| 연산 | 시간 복잡도 | 설명 |
| :--- | :--- | :--- |
| **객체 삽입/삭제** | $O(\log N)$ | 레드-블랙 트리를 통한 시작 주소/범위 관리 |
| **포인터 검색** | $O(\log N)$ | 주어진 주소를 포함하는 슬랩 객체 탐색 |
| **전체 스캔** | $O(M \cdot \log N)$ | $M$개의 워드 스캔 및 RB-tree 조회 |

본 시뮬레이션 엔진은 리눅스 커널의 가장 실전적이고 정교한 메모리 누수 진단 서브시스템인 kmemleak의 전체 라이프사이클을 완벽하게 재현합니다.
