> **"식탐 괴물에게 '조금만 먹어라'고 조건을 명확히 주지 않으면, 접시째로 식탁을 삼켜버린다."**

## 🍽️ 1. 일상 비유: 뷔페의 식탐 괴물과 매너 손님

어느 호텔 뷔페에 두 종류의 손님이 방문했습니다.
주방장이 안내 표지판을 걸어두었습니다:
> *"뚜껑(`<`)이 열린 곳에서 음식을 집고, 뚜껑(`>`)이 닫힌 곳에서 멈추시오."*

* **매너 손님 (게으른 매칭, Lazy / `.*?`)**:
  - 첫 번째 열린 뚜껑(`<`)을 보고 만두를 집은 뒤, **바로 앞에 있는 첫 번째 닫는 뚜껑(`>`)을 만나자마자 얌전하게 멈춥니다.**
  - 다음 칸으로 이동해서 두 번째 열린 뚜껑과 닫는 뚜껑 사이의 음식만 쏙쏙 골라 담습니다.
* **식탐 괴물 (탐욕적 매칭, Greedy / `.*`)**:
  - 첫 번째 열린 뚜껑(`<`)을 발견하자마자 입을 벌리고 **뷔페 홀 끝까지 돌진**합니다.
  - 그리고 식당 맨 끝에 있는 **가장 마지막 닫는 뚜껑(`>`)까지 마주치는 모든 테이블, 장식, 의자, 다른 손님의 접시(본문 텍스트)를 한 입에 통째로 꿀꺽 삼켜버립니다!**

이 식탐 괴물이 바로 정규표현식의 기본 수량자인 **탐욕적 수량자(`.*`)**입니다.

## ⚙️ 2. 정규표현식 엔진의 내부 동작: 최장 일치(Longest Match)의 함정

컴퓨터를 잘 모르는 바이브 코더는 `r'<.*>'`를 보며 이렇게 상상합니다:
> *"컴퓨터가 `<`를 보고, 바로 뒤에 있는 `>`를 찾아서 태그 하나씩 예쁘게 지워주겠지?"*

하지만 정규표현식 엔진(NFA: Non-deterministic Finite Automata)은 정반대로 움직입니다:

```text
문자열: <b>공지사항</b> 오늘 <i>휴무</i>

1. '<' 발견: '<b>'의 '<'에서 시작!
2. '.*' 실행 (탐욕적 엔진):
   - "아무 글자나 최대한 많이 먹으라고? 일단 문자열 맨 끝까지 전부 먹어치우자!"
   - 엔진이 '<b>공지사항</b> 오늘 <i>휴무</i>' 끝까지 한 번에 질주함!
3. '>' 탐색 (역방향 백트래킹, Backtracking):
   - "맨 끝에서부터 거꾸로 되짚어가면서 가장 먼저 만나는 '>'를 찾자!"
   - '</i>'의 맨 끝 '>'를 발견!
4. 최종 매칭 결과:
   - '<' (첫 <b> 앞)부터 '>' (마지막 </i> 뒤)까지 전체가 하나의 매칭으로 확정!
   - 싹 지워버리니 남는 글자는 아무것도 없음! (본문 전멸)
```

정규표현식에서 기본 수량자(`*`, `+`, `{n,m}`)는 **"패턴이 허용하는 한 가장 긴 문자열(Longest Match)을 매칭한다"**는 탐욕적(Greedy) 본성을 가지고 있습니다.

## 🛑 3. 구원투수: 게으른 수량자 (Lazy / Non-Greedy: `?`)

물음표(`?`)는 정규표현식에서 두 가지 완전히 다른 의미를 가집니다:
1. `a?` : 단독으로 쓰일 때는 "a가 0개 또는 1개 있음"
2. `*?`, `+?` : **다른 수량자 뒤에 붙을 때는 "탐욕을 멈추고 최소한만 매칭하라(Shortest Match)"는 스위치!**

```python
import re

html = "<b>공지</b> 내용 <i>끝</i>"

# [위험: 탐욕적 매칭]
re.sub(r'<.*>', '', html)
# 결과: ''  <-- 중간의 ' 내용 '까지 통째로 삼켜버림!

# [안전: 게으른 매칭]
re.sub(r'<.*?>', '', html)
# 결과: '공지 내용 끝'  <-- 태그만 쏙쏙 4번 매칭하여 제거!
```

게으른 수량자 `.*?`는 한 글자씩 전진하면서 **바로 다음 문자가 `>`인지 확인하고, `>`를 만나는 즉시 탐색을 끝냅니다.** 덕분에 태그 단위로 안전하게 분리됩니다.

## 💥 4. 실무에서 터지는 대표적 정규식 참사들

### 1) 마크다운 코드 블록 파싱 참사
```python
# 문서에 코드 블록이 2개 있을 때:
doc = "첫번째 코드: ```python print(1) ``` 중간 설명... 두번째 코드: ```python print(2) ```"

# 탐욕적 정규식:
re.findall(r'```.*```', doc)
# 결과: 첫 번째 코드부터 두 번째 코드까지 '중간 설명...'을 포함한 거대한 1개로 통째로 묶여 파싱 실패!
```

### 2) JSON 필드 추출 참사
```python
json_str = '{"name": "Alice", "role": "admin", "bio": "Hello"}'
re.findall(r'"name": ".*"', json_str)
# 결과: "name": "Alice", "role": "admin", "bio": "Hello" 전체가 하나의 name 값으로 오염!
```

## 🏆 5. 성능 보너스: 게으른 수량자보다 더 빠른 기법 (`[^>]*`)

게으른 수량자 `.*?`도 안전하지만, 매 글자마다 "다음 글자가 `>`인가?"를 확인하는 오버헤드가 있습니다.
실무 시니어 개발자들은 HTML 태그를 지울 때 **부정 문자 집합(Negated Character Class)**을 선호합니다:

```python
# [가장 빠르고 완벽한 태그 제거 정규식]
clean = re.sub(r'<[^>]*>', '', html)
```
- `<[^>]*>` : `<`로 시작하고, **`>`가 아닌 문자들**만 반복해서 읽다가, `>`를 만나면 닫아라!
- 이 방식은 백트래킹(되짚기)이 발생하지 않아 대용량 웹 크롤링 데이터에서도 수십 배 빠르고 안전합니다.

## 🎯 6. 요약

1. **정규식의 기본 수량자(`.*`, `.+`)는 탐욕적(Greedy)이라 가장 먼 끝까지 먹어치운다.**
2. **괄호나 따옴표 사이의 내용을 지울 때는 반드시 게으른 수량자(`.*?`, `.+?`)를 써라.**
3. **더 빠른 대안으로 부정 문자 집합(`[^>]*`, `[^"]*`)을 적극 활용하라!**
