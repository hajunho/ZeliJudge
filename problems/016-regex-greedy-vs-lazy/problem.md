# [ZeliJudge #016] 사라진 공지사항과 식탐 괴물: 정규표현식(Regex) 탐욕적(Greedy) vs 게으른(Lazy) 매칭

## 📌 문제 배경 스토리
사내 인트라넷 게시판을 개편하던 신입 백엔드 개발자 젤리는 HTML 태그가 섞인 게시글 본문에서 태그를 벗겨내고 순수 텍스트만 추출하는 검색 인덱싱 파이프라인을 구축했습니다.
젤리는 HTML 태그가 항상 여는 괄호(`<`)로 시작해서 닫는 괄호(`>`)로 끝난다는 점에 착안하여, 파이썬의 정규표현식(Regex) 모듈 `re`를 사용해 다음과 같이 한 줄로 멋지게 코드를 작성했습니다:

```python
# [젤리가 작성한 HTML 태그 제거 정규식]
import re

def strip_tags(html_content):
    # '<'로 시작해서 아무 문자(.*)나 들어가고 '>'로 끝나는 태그를 모조리 빈 문자열로 치환!
    clean_text = re.sub(r'<.*>', '', html_content)
    return clean_text
```

젤리는 생각했습니다:
*"태그 안에는 어떤 글자든 들어갈 수 있으니까 `.*`를 쓰면 완벽해! 정규식 마스터가 된 기분이다!"*

하지만 프로덕션 배포 직후, 회사 인트라넷 공지사항 게시판은 대혼란에 빠졌습니다:
- **원본 글**: `Notice: <b>[긴급 필독]</b> 2026년 추석 연휴 안내 <i>(인사팀)</i> 끝.`
- **젤리의 정규식 실행 후**: `Notice:  끝.`

사내 수백 개 부서의 모든 공지사항 본문이 거짓말처럼 감쪽같이 증발해 버린 것입니다!
팀장이 젤리의 모니터를 보고 경악하며 소리쳤습니다:
*"젤리 씨! 정규표현식에서 기본 수량자 `*`는 **탐욕적(Greedy, 식탐 괴물)** 수량자입니다! 문자열 전체에서 첫 번째 `<`를 만난 뒤, 만족할 때까지 멈추지 않고 문자열 끝까지 달려가서 **가장 마지막에 있는 `>`까지의 모든 본문 텍스트를 한 입에 꿀꺽 삼켜버린다**고요! 태그를 지울 때는 반드시 게으른(Lazy/Non-Greedy) 수량자인 `<.*?>`를 써서 닫는 괄호를 만나자마자 멈추게 해야 합니다!"*

CTO는 데이터 유실 사고를 전수 조사하기 위해,
1. 탐욕적 매칭(`GREEDY`, `r'<.*>'`)으로 훼손된 텍스트
2. 비탐욕적 매칭(`LAZY`, `r'<.*?>'`)으로 정상 추출된 텍스트
3. 탐욕적 매칭 때문에 **억울하게 함께 삼켜져 영구 증발한 순수 본문 글자 수**
를 정밀하게 분석하는 정규표현식 분석 엔진을 개발하라고 지시했습니다.

---

## ⚙️ 시스템 동작 규칙

문자열 $S$에 대해 두 가지 정규표현식 매칭 규칙을 적용합니다.

### 1. 탐욕적 매칭 (`GREEDY`, `r'<.*>'`)
- 문자열 전체에서 **가장 처음 등장하는 `<`**부터 **가장 마지막에 등장하는 `>`**까지의 모든 구간을 단 하나의 거대한 덩어리로 매칭하여 제거합니다.
- 즉, 가장 처음 등장하는 `<`의 인덱스를 $L$, 가장 마지막에 등장하는 `>`의 인덱스를 $R$이라 할 때 ($L < R$):
  - 제거 구간은 $S[L..R]$ 입니다.
  - 남은 결과는 $S[0..L-1] + S[R+1..]$ 이 됩니다.
- 만약 올바른 `<`와 `>` 쌍($L < R$)이 존재하지 않는다면 아무것도 제거되지 않고 원본 $S$가 그대로 유지됩니다.

### 2. 비탐욕적 / 게으른 매칭 (`LAZY`, `r'<.*?>'`)
- 문자열을 왼쪽부터 순서대로 스캔하면서, `<`를 만난 후 **가장 먼저 만나는 첫 번째 `>`**까지를 하나의 개별 태그로 매칭하여 제거합니다.
- 닫히지 않은 `<` (뒤에 `>`가 없는 경우)는 매칭되지 않고 그대로 보존됩니다.

### 3. 증발한 본문 글자 수 (`LOST`)
- 비탐욕적 정상 결과의 길이에서 탐욕적 결과의 길이를 뺀 값입니다:
  `LOST = len(LAZY_RESULT) - len(GREEDY_RESULT)`
- 탐욕적 정규식이 중간 본문 텍스트를 과도하게 먹어치운 글자 수를 나타내며, 항상 0 이상의 정수입니다.

---

## 📥 입력 형식 (Input)

- 첫째 줄에 테스트할 문자열의 총 개수 $Q$가 주어집니다. ($1 \le Q \le 10,000$)
- 둘째 줄부터 $Q$개의 줄에 걸쳐 문자열 $S$가 한 줄씩 주어집니다.
- 각 문자열 $S$의 길이는 1 이상 1,000 이하입니다.

---

## 📤 출력 형식 (Output)

- 각 문자열마다 3줄씩 다음 규격으로 출력합니다:
  `GREEDY:<greedy_result>`
  `LAZY:<lazy_result>`
  `LOST:<lost_count>`

---

## 💡 입출력 예제

### 예제 입력 1
```text
2
Notice: <b>[ALERT]</b> System maintenance tonight! <i>(IT Team)</i> Done.
<h1>Title</h1>
```

### 예제 출력 1
```text
GREEDY:Notice:  Done.
LAZY:Notice: [ALERT] System maintenance tonight! (IT Team) Done.
LOST:45
GREEDY:
LAZY:Title
LOST:5
```

### 예제 설명 1
- **1번째 문자열**:
  - `GREEDY`는 첫 번째 `<`(`<b>` 앞)부터 마지막 `>`(`</i>` 뒤)까지 통째로 삼켜버려 `Notice:  Done.`만 남습니다.
  - `LAZY`는 `<b>`, `</b>`, `<i>`, `</i>` 4개의 태그만 개별적으로 깔끔하게 지워 `Notice: [ALERT] System maintenance tonight! (IT Team) Done.`이 남습니다.
  - 탐욕적 정규식 때문에 중간 본문 45글자가 억울하게 증발했습니다 (`LOST:45`).
- **2번째 문자열**:
  - `<h1>Title</h1>` 전체가 첫 번째 `<`와 마지막 `>` 사이에 있으므로 `GREEDY`는 빈 문자열(`""`)이 됩니다.
  - `LAZY`는 `<h1>`과 `</h1>`만 제거하여 `Title`이 남습니다 (`LOST:5`).

---

### 예제 입력 2
```text
2
x < 5 and y > 10
Just plain text without tags
```

### 예제 출력 2
```text
GREEDY:x  10
LAZY:x  10
LOST:0
GREEDY:Just plain text without tags
LAZY:Just plain text without tags
LOST:0
```

### 예제 설명 2
- 수학 부등호 `x < 5 and y > 10`은 `<`와 `>`가 단 하나씩만 존재하므로 탐욕적 매칭과 게으른 매칭의 결과가 완벽히 동일하며, 손실 글자 수는 0입니다.
- 태그가 전혀 없는 일반 텍스트는 원본 그대로 보존되며 손실 글자 수는 0입니다.
