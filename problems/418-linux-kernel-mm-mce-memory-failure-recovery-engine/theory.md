# 이론 문서 418: Linux 커널 메모리 관리와 MCE 하드웨어 장애 격리 및 고가용성(RAS) 내부 원리

## 1. 개요 및 배경 (Hardware Failure Reality & Motivation)

현대 데이터센터의 서버들은 수백 기가바이트에서 수 테라바이트에 달하는 고밀도 DRAM을 탑재하고 있습니다.
DRAM 셀은 미세 커패시터에 전하를 저장하는 구조적 특성상, 다음과 같은 물리적 요인으로 인해 전하가 유출되거나 반전될 수 있습니다:
- **소프트 에러 (Soft Error)**: 대기 중의 알파 입자나 우주 방사선(Cosmic Rays / 중성자 충돌)에 의해 특정 비트가 일시적으로 반전되는 현상.
- **하드 에러 (Hard Error)**: 물리적 실리콘 결함, 게이트 산화막 열화, 핀 접촉 불량 등으로 특정 비트가 0 또는 1로 고착(Stuck-at)되는 현상.
- **인접 교란 에러 (Rowhammer)**: 특정 DRAM 행(Row)을 고속으로 반복 활성화하여 인접 행의 커패시터 전하를 누출시키는 취약점.

서버급 ECC(Error-Correcting Code) 메모리는 단일 비트 에러(SEC, Single Error Correction)를 투명하게 수정하지만, 2비트 이상의 오류(**DED, Double Error Detection / UCE, Uncorrectable Error**)는 하드웨어 수준에서 자체 복구할 수 없습니다.

과거에는 UCE가 발생하면 CPU가 `#MC` 예외를 발생시키고 커널이 즉시 패닉을 일으켰으나, `mm/memory-failure.c`는 **"에러의 영향을 받는 최소 단위(물리 4KB 페이지)만을 국소적으로 도려내어 시스템 전체의 연속 가동을 유지"**합니다.

## 2. 하드웨어 머신 체크 아키텍처 (x86 MCA)

인텔과 AMD 프로세서는 x86 Machine Check Architecture (MCA)를 구현하고 있습니다:
1. **MCi_STATUS 레지스터**:
   - 비트 63 (`VAL`): 레지스터 내용 유효 플래그.
   - 비트 62 (`OVER`): 에러 오버플로우 플래그.
   - 비트 61 (`UC`): 복구 불가능 오류 (Uncorrected Error).
   - 비트 57 (`PCC`): Processor Context Corrupted (1이면 CPU 상태가 영구 파괴되어 패닉 불가피, 0이면 컨텍스트 보존되어 소프트웨어 복구 가능).
   - 비트 56 (`S`): 시그널링 방식 (Signaling).
   - 비트 55 (`AR`): Action Required (1이면 현재 실행 중인 코어가 직접 에러 메모리에 접근하여 동기적 즉각 조치 필요).
2. **MCi_ADDR 레지스터**: 오류가 발생한 물리 메모리 주소(Physical Address)를 저장합니다.

## 3. 커널 `memory_failure()` 핵심 알고리즘 (`mm/memory-failure.c`)

커널 MCE 핸들러가 물리 주소를 PFN(Page Frame Number)으로 변환한 뒤 `memory_failure()`를 호출하면 다음과 같은 5단계 파이프라인이 수행됩니다:

### 3.1 1단계: 페이지 유효성 검증 및 락 획득
- `pfn_to_page(pfn)`을 통해 `struct page`를 가져옵니다.
- `TestSetPageHWPoison(page)`를 원자적으로 실행하여 중복 MCE 처리를 방어합니다.

### 3.2 2단계: 버디 할당자 프리 페이지 처리
- `PageBuddy(page)`가 참인 경우:
  - 해당 페이지는 사용자나 커널 데이터가 전혀 들어있지 않은 빈 페이지입니다.
  - `take_page_off_buddy()`를 실행하여 버디의 프리 리스트에서 제거합니다.
  - 어떤 프로세스도 해당 메모리를 보고 있지 않으므로 **시그널 발송 없이 조용히 격리(Isolation)**합니다.

### 3.3 3단계: 파일 백업 클린 페이지 캐시 처리
- `PageDirty(page)`가 거짓이고 `page_mapping(page)`가 유효한 경우:
  - 데이터의 진본이 디스크(SSD/HDD)에 존재합니다.
  - `try_to_unmap(page, TTU_IGNORE_ACCESS)`를 실행하여 해당 페이지를 참조하고 있는 모든 프로세스의 PTE 매핑을 끊습니다.
  - 인덱스 트리(`mapping->i_pages`)에서 페이지를 제거하고 할당 해제합니다.
  - **프로세스를 죽이지 않습니다!** 나중에 프로세스가 해당 페이지에 접근하면 페이지 폴트(`#PF`)가 발생하고, 파일시스템은 디스크에서 새로운 정상 물리 페이지로 데이터를 다시 읽어옵니다.

### 3.4 4단계: 더티 페이지 및 사용자 익명 메모리 처리
- 익명 메모리(`PageAnon`)나 수정된 파일 페이지(`PageDirty`):
  - 메모리 내용이 파괴되었고 대체할 백업 소스가 없습니다.
  - 프로세스의 가상 메모리 주소 공간에서 해당 페이지의 PTE를 영구 무효화(`PTE_POISON`)합니다.
  - `kill_proc()`을 호출하여 프로세스에 **`SIGBUS`** 시그널을 전달합니다:
    - **`BUS_MCEERR_AR` (Action Required)**: 동기적 접근으로 인해 프로세스가 더 이상 진행할 수 없을 때 사용됩니다.
    - **`BUS_MCEERR_AO` (Action Optional)**: 비동기 스크러버에 의해 발견되어 아직 프로세스가 해당 메모리를 읽지 않았을 때 통지됩니다.

### 3.5 5단계: 커널 슬랩 및 예약 메모리 (치명적 장애)
- 커널 자체의 슬랩 캐시(`PageSlab`)나 시스템 예약 페이지가 손상된 경우:
  - 커널 내부 불변식(Invariants)이 깨졌으므로 침묵하는 데이터 손상(Silent Data Corruption)을 막기 위해 의도적으로 **`panic()`**을 호출합니다.

## 4. 선제적 소프트 오프라인 (`soft_offline_page`)

정정 가능한 1비트 에러(CE)는 하드웨어 자체에 의해 수정되지만, 특정 물리 셀에서 CE가 반복적으로 누적된다는 것은 하드웨어 셀의 수명이 임계점에 도달했음을 의미합니다.

### 4.1 무손실 선제적 마이그레이션 메커니즘
1. 커널 데몬(또는 `rasdaemon`)이 특정 PFN의 CE 카운터가 임계치를 초과했음을 감지합니다.
2. `soft_offline_page(pfn)`을 호출합니다.
3. 커널은 새로운 예비 페이지(Spare Page)를 할당받습니다.
4. 원본 페이지의 내용을 예비 페이지로 완벽하게 복사합니다.
5. 프로세스의 페이지 테이블 엔트리(PTE)가 예비 페이지를 가리키도록 원자적으로 재매핑합니다.
6. 원본 노화 페이지를 `HWPOISON`으로 격리하여 향후 할당되지 않도록 차단합니다.
7. **결과: 프로세스 중단이나 에러 발생 없이 100% 무중단 예방 조치가 완료**됩니다.

## 5. 가상화 및 엔터프라이즈 데이터베이스 연계

- **KVM / QEMU 가상화**:
  - 호스트 리눅스 커널이 `BUS_MCEERR_AR`을 QEMU 프로세스에 전달하면, QEMU는 전체 VM을 종료하지 않고 **가상 CPU(vCPU)에 게스트 MCE를 주입(Inject)**합니다. 게스트 OS(Linux/Windows)가 자체적으로 해당 프로세스를 사살하거나 드라이버를 리셋하여 다른 테넌트 VM을 완벽하게 보호합니다.
- **엔터프라이즈 DBMS (Oracle, SAP HANA, PostgreSQL)**:
  - `SIGBUS` (`BUS_MCEERR_AR`) 핸들러를 등록하여, 손상된 버퍼 풀 페이지에 해당하는 단일 트랜잭션만 롤백(Rollback)하고 데이터베이스 인스턴스 전체는 정상 가동을 유지합니다.
