# 깊이 있는 컴퓨터 과학: Dynamo/Cassandra 분산 아키텍처, Gossip 안티-엔트로피와 톰스톤 GC

## 1. 마스터리스(Masterless) 분산 스토리지 철학

전통적인 주-종(Primary-Replica) 복제는 리더 노드가 쓰기를 직렬화하므로 강력한 일관성을 제공하지만, 리더 장애 시 쓰기 가용성이 중단되는 한계가 있습니다.
2007년 Amazon의 Dynamo 논문과 Apache Cassandra는 **가용성 최우선(Always Writable)** 철학을 바탕으로 리더가 없는 대칭형(Symmetric) 마스터리스 아키텍처를 도입했습니다.
- 모든 노드가 클라이언트 요청의 코디네이터(Coordinator) 역할을 수행할 수 있습니다.
- 슬로피 쿼럼(Sloppy Quorum)과 힌티드 핸드오프(Hinted Handoff)를 통해 일시적 노드 장애에도 쓰기 작업을 무중단으로 수락합니다.

## 2. 가십 프로토콜(Gossip Protocol)과 안티-엔트로피(Anti-Entropy)

마스터리스 클러스터에서는 중앙 집중형 메타데이터 저장소(ZooKeeper, etcd 등) 대신 피어-투-피어 **Gossip 프로토콜**을 사용합니다.
- 각 노드는 주기적(보통 1초 간격)으로 클러스터 내 임의의 피어 노드를 선택하여 상태 다이제스트(Scuttlebutt 프로토콜)를 교환합니다.
- **안티-엔트로피(Anti-Entropy)**:
  - 노드 간 데이터 불일치를 백그라운드에서 주기적으로 탐지하고 복구하는 프로세스입니다.
  - 대규모 데이터 세트를 비교하기 위해 **머클 트리(Merkle Tree, 해시 트리)**를 생성하여, 루트 해시만 비교함으로써 네트워크 대역폭 소비를 최소화하면서 불일치 구간만 정밀 동기화합니다.

## 3. 벡터 클록(Vector Clock)과 인과적 일관성 (Causal Consistency)

단일 물리적 시계(Wall-Clock)는 NTP 동기화 오차와 상대성 이론적 한계로 인해 분산 노드 간의 엄격한 인과 관계(Happens-Before, $\to$)를 표현할 수 없습니다.

### 3.1 벡터 클록 메커니즘
시스템 내 $N$개의 노드가 있을 때, 각 레코드마다 벡터 클록 $V = [v_1, v_2, \dots, v_N]$을 첨부합니다:
1. 노드 $i$에서 쓰기가 발생하면 $V[i] \leftarrow V[i] + 1$.
2. 다른 노드로 전파되거나 병합될 때 벡터 클록의 각 원소를 보존.

### 3.2 인과적 우위 판별
- $V_A \ge V_B \iff \forall k, V_A[k] \ge V_B[k]$
- $V_A > V_B$이면 $V_A$가 $V_B$를 엄격히 지배하므로 $V_B$는 구버전으로 안전하게 덮어써집니다.
- 만약 $V_A \not\ge V_B$ 이고 $V_B \not\ge V_A$ 라면 두 쓰기는 **동시성 충돌(Concurrent Divergence)** 상태입니다.
  - Cassandra는 실무적 단순성을 위해 최종 타임스탬프 승자 방식(**LWW, Last-Write-Wins**)을 주로 채택합니다.
  - Riak 등은 두 버전을 형제(Sibling)로 유지하여 클라이언트 애플리케이션 레벨에서 장바구니 합치기(Merge)를 수행하도록 위임합니다.

## 4. 톰스톤(Tombstone)과 좀비 데이터 부활(Zombie Resurrection) 방어

### 4.1 물리 삭제의 치명적 함정
분산 환경에서 어떤 노드가 레코드를 즉시 물리적으로 삭제(`rm`)하면, 그 노드의 상태는 "데이터가 없음"이 됩니다.
- 이때 과거 데이터를 보관하고 있던 오프라인 노드가 네트워크에 복귀하여 안티-엔트로피 가십 동기화를 시도하면:
  - 동기화 엔진 입장에서는 데이터가 없는 노드보다 데이터를 가진 노드가 더 "새로운 삽입"을 받은 것으로 판단하여 데이터를 역으로 복제해 줍니다.
  - 이것이 바로 삭제되었던 데이터가 영원히 되살아나는 **좀비 데이터 부활(Zombie Resurrection)** 참사입니다.

### 4.2 톰스톤 메커니즘과 `gc_grace_seconds`
- 삭제는 데이터의 소멸이 아니라 **"이 데이터는 삭제되었다"는 특수 삭제 마커(Tombstone)**를 새 벡터 클록과 함께 쓰는 작업입니다.
- 톰스톤 역시 일반 레코드처럼 가십과 Read Repair를 통해 모든 노드로 복제 전파됩니다.
- **`gc_grace_seconds` (Cassandra 기본값 10일)**:
  - 톰스톤이 클러스터 내의 모든 노드에 전파될 충분한 시간을 보장하는 안전 유예 기간입니다.
  - 어떤 노드가 10일 이상 오프라인 상태였다가 복귀하면, 이미 정상 노드들이 톰스톤을 GC로 날려버렸을 수 있으므로 그 노드는 데이터를 복구하지 말고 **전체 재동기화(Node Rebuild)**를 거쳐야 합니다.
