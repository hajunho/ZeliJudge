# Theory #434: 리눅스 커널 DAMON 기반 선제적 메모리 관리 및 LRU 정렬 (CONFIG_DAMON_LRU_SORT) 아키텍처

## 1. 개요 및 배경 (The Paradigm Shift: Reactive to Proactive Reclaim)

### 1.1 사후 반응적(Reactive) 메모리 회수의 한계
리눅스 가상 메모리(VM) 서브시스템의 전통적인 페이지 회수 엔진(`mm/vmscan.c`)은 시스템에 여유 메모리가 부족해질 때 비로소 깨어납니다:
- `kswapd` 커널 스레드는 워터마크가 `WMARK_LOW` 아래로 떨어지면 회수를 시작합니다.
- 만약 메모리 할당 속도가 `kswapd`의 회수 속도를 앞지르면, 할당을 요청한 유저 프로세스 스레드가 직접 회수(`direct reclaim`) 경로로 진입하여 CPU를 100% 소모하며 페이지를 스캔합니다.
- **치명적 문제**: 수백 기가바이트의 메모리가 장착된 서버에서 수천만 개의 페이지를 훑으며 락을 걸고 해제하는 작업은 P99 지연 시간을 수백 밀리초로 치솟게 만들어 실시간 서비스(SLA)를 파괴합니다.

### 1.2 선제적(Proactive) 메모리 관리와 DAMON
이 문제를 극복하기 위해 박성재(SeongJae Park)가 개발한 **DAMON(Data Access MONitor)** 프레임워크가 리눅스 5.15에 머지되었고, 리눅스 5.18에서 **`mm/damon/lru_sort.c`** 모듈이 완성되었습니다.
- **핵심 철학**: "메모리 압박이 닥치기 전에, 백그라운드에서 극소량의 CPU(1% 미만)만을 사용하여 메모리를 상시 핫/콜드로 정렬해 둔다."
- 메모리가 부족해지는 순간, 커널은 무거운 스캔 없이 이미 비활성 리스트 끝에 모여있는 차가운 페이지를 즉각 버리기만 하면 되므로 회수 지연 시간이 0에 수렴하게 됩니다.

## 2. DAMON core 모니터링 메커니즘

`mm/damon/core.c`는 3단계 파이프라인으로 동작합니다:
1. **적응형 영역 분할 및 병합 (Adaptive Region Split/Merge)**:
   - 가상/물리 주소 공간을 여러 개의 `damon_region`으로 나눕니다.
   - 접근 빈도가 유사한 인접 영역은 하나로 합치고, 접근 패턴이 갈라지는 영역은 쪼개어 전체 모니터링 영역 개수를 일정 수준(예: 10~1000개)으로 제한함으로써 O(1) 모니터링 오버헤드를 달성합니다.
2. **샘플링 (Sampling Window)**:
   - 주기적으로(예: 5ms) 영역 내 임의의 페이지의 PTE `Accessed` 비트를 확인하고 즉각 클리어합니다.
3. **집계 (Aggregation Window)**:
   - 일정 샘플링 주기(예: 100ms)가 지나면 누적 접근 횟수를 집계하고 체류 시간(`age`)을 갱신합니다.

## 3. mm/damon/lru_sort.c의 2대 동작 원리

### 3.1 핫 영역 선제 승격 (`hot_thres`)
- 애플리케이션의 핵심 워킹셋 페이지는 높은 접근 빈도를 기록합니다.
- `access_count >= hot_thres`인 영역에 대해 DAMON은 `mark_page_accessed()`를 선제적으로 호출합니다.
- 이로써 해당 페이지들은 Active LRU 리스트의 최상단(Head)으로 승격되어, 예기치 못한 메모리 압박이 닥쳐도 퇴출 후보로 잘못 선정되는 일이 원천 차단됩니다.

### 3.2 콜드 영역 선제 강등 (`cold_min_age`)
- 초기화 후 다시는 읽히지 않는 설정 파일이나 로그 버퍼 등은 `access_count == 0` 상태를 유지합니다.
- 이 상태가 `cold_min_age` 집계 주기 동안 지속되면, DAMON은 `deactivate_page()`를 호출하여 해당 영역을 Inactive LRU 리스트의 최하단(Tail)으로 즉각 강등시킵니다.

## 4. 자원 보호를 위한 Quota 및 Watermark 시스템

선제적 정렬 작업 자체가 과도한 CPU나 I/O를 소모한다면 주객전도가 됩니다. `lru_sort.c`는 2중 안전장치를 갖추고 있습니다:
1. **크기 및 시간 쿼터 (Size & Time Quota)**:
   - `size_quota_pages` (또는 `time_quota_ms`): 단일 리셋 주기(예: 1000ms) 동안 최대 얼마만큼의 페이지만 승격/강등할지 상한을 강제합니다. 쿼터를 초과하면 다음 주기까지 동작을 일시 중단합니다.
2. **워터마크 스위칭 (Free Memory Watermark)**:
   - 여유 메모리가 풍부할 때(`wmark_high` 이상)는 DAMON 모니터링 자체를 잠재워 CPU 소모를 0으로 만듭니다.
   - 메모리가 서서히 소진되어 중간 수위에 도달할 때 활성화되어 선제 정렬을 가동합니다.

## 5. 실무 벤치마크 및 도입 효과

- **Redis 및 Memcached**: 대규모 키-값 저장소에서 `damon_lru_sort`를 적용했을 때, 메모리 압박 시 P99.9 응답 지연 시간이 최대 98% 감소하며 테일 레이턴시가 획기적으로 안정화됩니다.
- **쿠버네티스 컨테이너 고밀도 집약**: 노드 메모리를 95% 이상으로 오버커밋한 환경에서도 워킹셋 스래싱 없이 유휴 페이지만 정밀하게 회수할 수 있습니다.
