# 400: 리눅스 커널 메모리 관리 — 레드-블랙 트리의 종말과 Maple Tree(RCU-Safe B-Tree) VMA 아키텍처 대혁신

## 1. 25년의 유산: 레드-블랙 트리와 `mmap_lock` 확장성 위기

리눅스 커널 2.6부터 6.0에 이르기까지, 프로세스의 주소 공간 관리(VMA)는 항상 `rb_node` 기반 레드-블랙 트리와 연결 리스트에 의존했습니다.

### 1.1 왜 레드-블랙 트리는 멀티코어 환경에서 붕괴했는가?
1. **RCU 무잠금 순회의 원천 불가능성**:
   레드-블랙 트리는 삽입/삭제 시 트리의 블랙 높이(Black Height) 균형을 맞추기 위해 회전(Left/Right Rotation)과 색상 재할당을 수행합니다. 회전 과정에서 부모, 자식, 삼촌 노드의 포인터 3~4개가 연속적으로 재연결되는데, 락 없이 트리를 읽고 있는 병행 리더(Concurrent Reader)는 순간적으로 순환 고리(Loop)나 댕글링 포인터를 만나 커널 크래시(Kernel Panic)를 일으킵니다.
2. **`mmap_lock` 병목 (Global Bottleneck)**:
   이로 인해 어떤 스레드가 페이지 폴트를 처리(`do_anonymous_page()`)하더라도 반드시 읽기 락(`down_read(&mm->mmap_lock)`)을 획득해야 했습니다. 128코어, 256스레드 서버에서 자바 가상머신(JVM)이나 C++ 서버가 동시 메모리 할당을 수행하면 `mmap_lock` 경합으로 CPU 사용률의 40% 이상이 스핀락 대기에 소모되었습니다.

## 2. Maple Tree (`lib/maple_tree.c`)의 혁신

리눅스 커널 6.1에 도입된 **Maple Tree**는 이러한 한계를 완전히 극복하기 위해 설계된 RCU-Safe 범위 B-Tree입니다.

### 2.1 범위 지향 B-Tree 노드 (Range-oriented B-Tree)
- 각 노드는 개별 키가 아닌 **상한 피벗(Pivot)** 배열을 보관합니다.
- 슬롯 $i$는 이전 피벗과 현재 피벗 사이의 범위 $[	ext{pivot}[i-1] + 1, 	ext{pivot}[i]]$를 가리킵니다.
- 메모리 공간이 연속적이든 비연속적이든, 빈 구멍(Gap)과 할당된 VMA를 단일 트리 노드 내부에서 균일하게 표현할 수 있습니다.

### 2.2 RCU 안전 복사(Copy-on-Write for Tree Mutations)
Maple Tree가 노드를 분할(Split)하거나 병합(Merge)할 때, 기존 노드를 인플레이스(In-place)로 변형하지 않고 새로운 노드를 할당하여 데이터를 복사한 후 원자적 포인터 교체(`rcu_assign_pointer`)를 수행합니다.
따라서 `mas_walk()`를 호출하는 독자(Reader)는 어떠한 락도 잡지 않고도 항상 일관성 있는 트리의 스냅샷을 안전하게 순회할 수 있습니다.

### 2.3 Per-VMA Lock의 실현
Maple Tree의 무잠금 RCU 탐색 능력을 바탕으로, 리눅스 6.4는 마침내 **개별 VMA 단위의 락(`vma->vm_lock`)** 을 완성했습니다. 서로 다른 메모리 영역에서 발생하는 페이지 폴트는 이제 전역 `mmap_lock`을 건너뛰고 완벽한 병렬(Embarrassingly Parallel)로 실행됩니다.

## 3. 결론

Maple Tree는 리눅스 커널 가상 메모리 관리 역사상 20년 만에 이루어진 가장 위대한 아키텍처 전환점입니다.
본 시뮬레이터는 이러한 최신 커널의 범위 인덱싱, VMA 중간 분할(Splitting), 무잠금 탐색 및 빈 주소 공간 검색을 100% 충실하게 모델링하여 실무 엔지니어에게 최고 수준의 시스템 통찰을 제공합니다.
