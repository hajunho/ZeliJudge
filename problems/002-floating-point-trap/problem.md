## 📖 실무 버그 시나리오

스타트업의 간편결제 e-커머스 플랫폼을 개발하던 주니어 엔지니어 지우는 장바구니 결제 및 정산 모듈을 개발했습니다.
지우는 AI 코딩 툴에게 다음과 같은 요구사항을 전달했습니다:

> *"상품 가격, 할인율(%), 부가세율(%)을 입력받아 최종 결제 금액을 계산하고, 1원 미만 소수점은 일반 반올림(0.5 이상 올림, 사사오입)해 줘."*

AI는 망설임 없이 다음과 같은 파이썬 코드를 내놓았습니다:

```python
# AI가 작성해 준 코드
def calculate_price(price, discount_rate, vat_rate):
    # discount_rate, vat_rate는 10.5 같은 백분율 실수
    discount = price * (discount_rate / 100.0)
    supply_price = price - discount
    vat = supply_price * (vat_rate / 100.0)
    final_price = supply_price + vat
    
    # 반올림 후 정수 변환
    return round(final_price)
```

지우는 `price = 10000`, `discount_rate = 10.0`, `vat_rate = 10.0`으로 테스트했습니다.
결과는 정확히 `9900`원이 나왔고, 몇 가지 테스트케이스도 무사히 통과했습니다. 지우는 안심하고 결제 엔진을 배포했습니다.

그런데 월말이 되자 **회계팀과 결제대행사(PG사)로부터 긴급 항의**가 빗발쳤습니다:

> *"고객이 결제한 금액과 PG사가 청구한 영수증 사이에 1원씩 차이가 나는 건이 수천 건 발생했습니다! 전체 정산 장부에서 수백만 원의 불일치가 발생해 회계 감사가 중단되었습니다!"*

원인을 파헤쳐 보니 충격적이었습니다:
1. `49.99 + 0.01`을 계산했더니 컴퓨터 안에서는 `50.0`이 아니라 `49.99999999999999`가 되어 있었습니다.
2. 파이썬의 `round()` 함수는 일반적인 사사오입이 아니라 **짝수 쪽으로 반올림하는 '은행원 반올림(Round-half-to-even)'** 방식을 사용하여, `2.5`를 반올림하면 `2`가 되고 `3.5`를 반올림하면 `4`가 되는 등 0.5원 단위에서 예측 불가능한 1원 누락이 발생했던 것입니다!

AI는 겉보기에 멀쩡한 수학 수식을 코드로 바꿔주었지만, **컴퓨터의 2진수 비트 메모리가 실수를 어떻게 저장하는지**는 전혀 고려하지 않았던 것입니다.

## 🎯 문제 설명

전자상거래 플랫폼의 결제 거래 $N$건이 주어집니다.
각 거래마다 원화 상품 가격 $P$, 할인율 $D$(\%), 부가세율 $V$(\%)가 주어질 때, 각 거래의 최종 결제 금액을 정확히 계산하여 **$N$건의 총 결제 금액 합**을 구하세요.

### 결제 금액 계산 규칙
1. **공급가액**: 상품 가격 $P$에서 할인 금액을 뺍니다.
   $$\text{할인 금액} = P \times \frac{D}{100}$$
   $$\text{공급가액} = P - \text{할인 금액} = P \times \left(1 - \frac{D}{100}\right)$$
2. **부가세**: 공급가액에 부가세율을 곱합니다.
   $$\text{부가세} = \text{공급가액} \times \frac{V}{100}$$
3. **최종 결제 금액 (실수)**:
   $$\text{최종 금액} = \text{공급가액} + \text{부가세} = P \times \left(1 - \frac{D}{100}\right) \times \left(1 + \frac{V}{100}\right)$$
4. **회사의 정산 정책 (사사오입)**:
   * 각 거래의 최종 결제 금액에서 **1원 미만(소수점 이하 첫째 자리)**은 **일반적인 사사오입(Round Half Up)**을 적용하여 정수로 확정합니다.
     * 즉, 소수점 이하 부분이 $0.5$ 이상이면 올리고, $0.5$ 미만이면 버립니다. (음수는 주어지지 않습니다)
     * *(주의: 파이썬 내장 `round()`는 짝수 반올림이므로 오답이 될 수 있습니다! [theory.md](theory.md) 참고)*
5. 확정된 $N$건의 최종 결제 금액(정수)들의 **총합**을 계산합니다.

---

## 📥 입력 형식 (Input)

* **첫째 줄**: 거래 건수 $N$ ($1 \le N \le 10,000$)
* **둘째 줄부터 $N$개의 줄**: 각 줄에 상품 가격 $P$, 할인율 $D$, 부가세율 $V$가 공백으로 구분되어 주어집니다.
  * $P$는 $1$ 이상 $100,000,000$ 이하의 정수입니다.
  * $D$는 $0.00$ 이상 $100.00$ 이하의 실수입니다. (소수점 최대 둘째 자리)
  * $V$는 $0.00$ 이상 $100.00$ 이하의 실수입니다. (소수점 최대 둘째 자리)

---

## 📤 출력 형식 (Output)

* 모든 거래의 최종 결제 금액(사사오입 적용 후 정수)의 **총합**을 첫째 줄에 정수로 출력합니다.

---

## 💡 예제 1

### 입력
```text
3
10000 10.00 10.00
25 50.00 0.00
100 15.25 10.00
```

### 출력
```text
10006
```

### 힌트
1. 거래 1: $10000 \times (1 - 0.10) \times (1 + 0.10) = 10000 \times 0.90 \times 1.10 = 9900.0$ 원 $\rightarrow$ $9900$ 원
2. 거래 2: $25 \times 0.5 = 12.5$ 원 $\rightarrow$ 사사오입 시 $0.5$ 이상이므로 $13$ 원
3. 거래 3: $100 \times (1 - 0.1525) \times 1.10 = 100 \times 0.8475 \times 1.10 = 93.225$ 원 $\rightarrow$ $0.225 < 0.5$ 이므로 $93$ 원
4. 총합: $9900 + 13 + 93 = 10006$ 원

## 💡 예제 2 (부동소수점 오차 테스트)

### 입력
```text
2
1 0.00 0.00
1000 33.33 10.00
```

### 출력
```text
734
```

### 힌트
* 거래 2: $1000 \times (1 - 0.3333) \times 1.10 = 1000 \times 0.6667 \times 1.10 = 733.37$ 원 $\rightarrow$ 사사오입 적용 시 $733$ 원
* 총합: $1 + 733 = 734$ 원

## 🔍 채점 엣지케이스 안내
1. `0.5`에 정확히 걸쳐서 사사오입과 은행원 반올림의 결과가 갈리는 경우 (예: 12.5, 22.5 등)
2. `0.0001` 수준의 미세한 2진수 부동소수점 오차로 인해 `x.499999999999` 또는 `x.500000000001`이 되어 버림/올림이 뒤바뀌는 케이스
3. $N = 10,000$ 건의 대용량 트랜잭션 누적 합산
