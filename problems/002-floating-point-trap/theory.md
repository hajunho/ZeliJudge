# 📘 [CS 이론 #002] 사라진 1원의 비밀: IEEE 754 부동소수점과 금융 연산

> **"0.1 + 0.2가 0.3이 아니라고? 컴퓨터는 왜 덧셈도 제대로 못할까?"**  
> e-커머스, 핀테크, 게임 개발에서 매년 수십억 원의 사고를 내는 부동소수점의 진실.

---

## 1. 충격적인 진실: $0.1 + 0.2 \ne 0.3$

파이썬이나 자바스크립트 콘솔을 열고 다음 한 줄을 쳐보세요:

```python
>>> 0.1 + 0.2 == 0.3
False
>>> 0.1 + 0.2
0.30000000000000004
```

초등학생도 아는 $0.1 + 0.2 = 0.3$을 왜 최신 슈퍼컴퓨터도 틀릴까요?  
컴퓨터가 고장 난 것이 아닙니다. **컴퓨터가 2진수(Binary)로 숫자를 저장하는 기계이기 때문**입니다.

---

## 2. 10진수와 2진수의 소수 표현 차이

우리가 일상에서 쓰는 10진수에서 $\frac{1}{3}$을 소수로 나타내면 어떻게 되나요?
$$\frac{1}{3} = 0.3333333333333333... \text{ (무한소수)}$$
종이가 아무리 넓어도 $3$을 끝까지 쓸 수 없으므로 중간에 적당히 잘라야 합니다.

**똑같은 일이 컴퓨터의 2진수 세계에서 벌어집니다.**
10진수에서는 너무나 깔끔한 $0.1$($\frac{1}{10}$)이, 2진수 세계에서는 **무한 순환소수**가 됩니다:

$$0.1_{10} = 0.000110011001100110011..._2$$

2진법에서 유한소수가 되려면 분모가 $2$의 거듭제곱($\frac{1}{2}, \frac{1}{4}, \frac{1}{8}, \frac{1}{16}...$) 꼴이어야 합니다.  
하지만 $10$은 $2 \times 5$이므로, $5$ 때문에 2진수로는 절대 딱 떨어지게 표현할 수 없습니다!

---

## 3. 컴퓨터는 실수를 어떻게 저장할까? (IEEE 754 표준)

컴퓨터의 메모리(RAM)는 무한하지 않습니다.  
현대 모든 프로그래밍 언어(C, C++, Java, Python, Go, JS 등)는 전기전자공학자협회(IEEE)의 **IEEE 754 배정밀도(Double Precision, 64비트)** 표준을 따릅니다:

```
[ IEEE 754 64비트 부동소수점 구조 ]
┌─────┬───────────────────────┬────────────────────────────────────────────────────────┐
│ 부호│     지수부 (Exponent)  │                 가수부 (Fraction / Mantissa)            │
│ 1비트│          11비트       │                         52비트                         │
└─────┴───────────────────────┴────────────────────────────────────────────────────────┘
```

* **부호 (1 bit)**: 양수(0) / 음수(1)
* **지수부 (11 bits)**: 소수점의 위치 ($2^{-1022} \sim 2^{1023}$)
* **가수부 (52 bits)**: 숫자의 실제 유효 자릿수

### 53번째 비트의 절삭 (Truncation & Rounding)
가수부에 할당된 자리는 정확히 **52비트**뿐입니다.  
2진수로 변환된 $0.1$의 무한 순환소수($0.0001100110011...$)를 적다가 52비트가 꽉 차면, 컴퓨터는 **뒤의 비트들을 가차 없이 잘라내거나 반올림**합니다.

이로 인해 메모리에 저장된 $0.1$의 실제 값은:
$$0.1000000000000000055511151231257827021181583404541015625$$
가 됩니다!

이 미세한 먼지 같은 오차가 연산을 거듭하면서 눈덩이처럼 불어나 **"사라진 1원"**이 되는 것입니다.

## 4. 파이썬 `round()`의 또 다른 배신: 은행가 반올림(Banker's Rounding)

*"부동소수점 오차가 생기면 그냥 반올림(`round()`)하면 되는 거 아니야?"*  
AI가 가장 흔히 내놓는 순진한 답변입니다. 하지만 파이썬의 `round()` 함수를 실행해 보면 기절초풍할 일이 생깁니다:

```python
>>> round(1.5)
2
>>> round(2.5)
2   # 응? 3이 아니라 2라고?!
>>> round(3.5)
4
>>> round(4.5)
4   # 5가 아니라 4?!
```

우리가 초등학교 때 배운 반올림은 **사사오입(Round Half Up)**으로, $0.5$ 이상이면 무조건 올림입니다 ($2.5 \rightarrow 3$).  
하지만 파이썬의 `round()`는 IEEE 754 권장 표준인 **Round Half to Even (오사오입 / 은행원 반올림)**을 채택하고 있습니다:
* 소수점이 정확히 $.5$일 때, **가장 가까운 짝수(Even)** 쪽으로 반올림합니다.
* $2.5$에서 짝수는 $2$이므로 $2$로 버림되고, $3.5$에서 짝수는 $4$이므로 $4$로 올림됩니다.

> **파이썬이 왜 이렇게 만들었을까요?**  
> 대규모 통계 데이터를 다룰 때 항상 $0.5$를 올리면 전체 평균이 위쪽으로 편향(Bias)되는 문제가 생깁니다. 절반은 올리고 절반은 버려서 통계적 중립을 지키려는 의도입니다.  
> **하지만 1원이라도 틀리면 철창에 가는 회계/금융 도메인에서는 재앙이 됩니다.**

## 5. 실무 엔지니어의 해결책 2가지

### 방법 A: 정수 스케일링 (Integer Arithmetic) - 가장 빠르고 추천되는 방식
소수를 아예 쓰지 않고 **정수 연산**만으로 문제를 해결하는 방식입니다.  
달러는 센트($1 = 100\text{ cents}$) 단위로, 할인율 $15.25\%$는 $\frac{1525}{10000}$이라는 분수(정수)로 처리합니다.

```python
# 할인율 15.25%, 부가세율 10.00%일 때
# 10000을 곱해 정수로 변환 후 연산
# 사사오입 공식: (분자 * 2 + 분모) // (분모 * 2) 또는 (분자 + 분모 // 2) // 분모
```
정수 연산은 CPU 레벨에서 100% 오차 없는 완벽한 계산을 보장합니다. Stripe, 페이팔 등 세계적인 결제 시스템들이 내부적으로 모든 통화를 최소 정수 단위(Cents, Won)로 다루는 이유입니다.

### 방법 B: `decimal` 모듈 활용 (Fixed-Point Arithmetic)
파이썬 표준 라이브러리 `decimal.Decimal`은 사람이 손으로 10진수 계산을 하듯 정확한 10진 소수 연산을 지원합니다:

```python
from decimal import Decimal, ROUND_HALF_UP

# 문자열 형태로 넘겨야 부동소수점 변환 오차가 없습니다!
p = Decimal("100")
d = Decimal("15.25")
v = Decimal("10.00")

# 공급가액 = P * (1 - D / 100)
supply = p * (Decimal("1") - d / Decimal("100"))
# 최종금액 = 공급가액 * (1 + V / 100)
final = supply * (Decimal("1") + v / Decimal("100"))

# 사사오입(ROUND_HALF_UP)으로 1원 단위 정수 확정
result = int(final.quantize(Decimal("1"), rounding=ROUND_HALF_UP))
```

`quantize(Decimal("1"), rounding=ROUND_HALF_UP)`는 정확히 우리가 원하는 초등학교식 사사오입을 완벽하게 수행합니다.
