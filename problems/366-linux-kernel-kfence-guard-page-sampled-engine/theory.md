# Linux Kernel KFENCE (Kernel Electric-Fence) 아키텍처 및 실운영 저오버헤드 메모리 안전성 심층 분석

## 1. 개요 및 설계 동기

리눅스 커널의 메모리 손상 취약점(OOB, UAF, Double-Free)은 시스템 침해와 권한 상승의 주된 원인입니다.

기존의 대표적인 동적 분석 도구인 **KASAN(Generic KASAN)**은 1:8 섀도우 메모리를 통해 바이트 단위의 정확한 탐지를 제공하지만, 다음과 같은 치명적인 한계로 인해 프로덕션 서버에 탑재할 수 없습니다:
1. **CPU 실행 속도 2배 이상 저하**: 모든 메모리 로드/스토어 명령어마다 섀도우 주소 계산과 비교 어셈블리가 삽입됨.
2. **메모리 오버헤드 20~30% 이상**: 섀도우 메모리 공간 및 슬랩 레드존 패딩.

2020년 구글의 알렉산더 포타펜코(Alexander Potapenko), 마르코 엘버(Marco Elver), 드미트리 비유코프(Dmitry Vyukov)가 고안하여 Linux 5.12에 공식 머지된 **KFENCE(Kernel Electric-Fence / `mm/kfence/`)**는 **"1% 미만의 오버헤드로 실운영 환경에서 메모리 버그를 포착한다"**는 목표를 달성한 혁신적인 프레임워크입니다.

---

## 2. 가드 페이지(Guard Page)와 하드웨어 MMU 기반 탐지

KFENCE는 유저스페이스의 Electric Fence (D.H. Perens, 1987) 아이디어를 커널에 샘플링 방식으로 이식했습니다.

### 2.1 풀 메모리 레이아웃
부팅 시 `kfence_pool`은 연속된 물리/가상 페이지들로 사전 예약됩니다:
$$\text{Total Pages} = 2 \times \text{CONFIG\_KFENCE\_NUM\_OBJECTS} + 1$$

- 홀수 페이지($1, 3, 5, \dots$): 객체가 할당되는 **Object Page**.
- 짝수 페이지($0, 2, 4, \dots$): 페이지 테이블 엔트리(PTE)가 완전히 유효하지 않게(`PAGE_NONE` / unmapped) 설정된 **Guard Page**.

```
+------------+------------+------------+------------+------------+
| Guard Pg 0 | Obj Slot 0 | Guard Pg 1 | Obj Slot 1 | Guard Pg 2 |
| (Unmapped) |  (Valid)   | (Unmapped) |  (Valid)   | (Unmapped) |
+------------+------------+------------+------------+------------+
```

### 2.2 좌우 확률적 밀착 (Left vs Right Alignment)
페이지 크기가 4096바이트이고 객체 크기가 64바이트인 경우:
- **우측 밀착 (`align_right = true`)**:
  - 오프셋: $4096 - 64 = 4032$.
  - 객체의 마지막 바이트 바로 다음 바이트는 인접한 우측 가드 페이지의 첫 바이트입니다.
  - 따라서 단 1바이트의 버퍼 오버플로우(Heap Out-of-Bounds Write/Read)도 즉시 CPU 하드웨어 MMU 페이지 폴트(`#PF`)를 유발합니다.
- **좌측 밀착 (`align_right = false`)**:
  - 오프셋: $0$.
  - 객체의 첫 바이트 바로 이전 바이트는 인접한 좌측 가드 페이지입니다.
  - 버퍼 언더플로우를 즉시 포착합니다.

### 2.3 Use-After-Free 및 Double-Free 탐지
- `kfree(P)`가 호출되면, KFENCE는 해당 객체가 위치한 Object Page 자체의 PTE를 즉시 무효화(`kfence_protect_page`)합니다.
- 이후 어떤 커널 스레드가 댕글링 포인터를 역참조하면, 가드 페이지와 마찬가지로 해당 페이지 접근 자체가 하드웨어 `#PF`를 트리거하여 즉시 UAF 버그 리포트와 스택 트레이스를 출력합니다.
- 이미 무효화된 슬롯에 대해 다시 `kfree()`가 호출되면 슬롯 메타데이터의 `state == FREED` 검사를 통해 `BUG_KFENCE_DOUBLE_FREE`를 보고합니다.

## 3. 샘플링(Sampling) 아키텍처와 오버헤드 통제

KFENCE가 오버헤드를 1% 미만으로 유지하는 비결은 **샘플링 주기(`sample_interval`)**에 있습니다:
- 일반적인 커널 슬랩 할당은 초당 수십만~수백만 번 발생합니다.
- KFENCE 타이머(`kfence_timer`)는 설정된 주기(예: 매 100ms마다 한 번씩)에만 다음 할당 요청을 가로채도록 `kfence_allocation_gate`를 엽니다.
- 수천 대, 수만 대의 데이터센터 서버가 운영되는 환경에서는 통계적 확률에 의해 모든 커널 코드 경로의 잠재적 버그가 점진적으로 포착됩니다.

## 4. KASAN과 KFENCE 비교

| 특성 | Generic KASAN | KFENCE |
| :--- | :--- | :--- |
| **탐지 방식** | 컴파일러 코드 계측 + 1:8 섀도우 메모리 | 하드웨어 MMU 가드 페이지 + 샘플링 |
| **속도 오버헤드** | ~100% (2배 느려짐) | **< 1% (무시 가능한 수준)** |
| **메모리 오버헤드** | > 20% | **< 수 메가바이트 (고정 풀)** |
| **적용 환경** | CI/CD, Syzkaller 퍼징, 커널 테스트베드 | **실운영 프로덕션 (AWS, GCP, 안드로이드)** |
| **OOB 탐지 정밀도** | 바이트 단위 즉각 탐지 | 가드 페이지 밀착 경계에서 하드웨어 탐지 |

본 시뮬레이터는 최신 프로덕션 리눅스 커널의 핵심 안정성 기제인 KFENCE의 페이지 레이아웃, 샘플링, MMU 폴트 및 라이프사이클을 완벽하게 재현합니다.
