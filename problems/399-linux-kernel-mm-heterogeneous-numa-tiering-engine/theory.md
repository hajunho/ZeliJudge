# 399: 리눅스 커널 메모리 관리 — 이종 메모리 계층화(CXL/HBM)와 AutoNUMA 힌팅 폴트 마이그레이션 이론

## 1. 하드웨어 이종 메모리 토폴로지 (Heterogeneous Memory Topology)

전통적인 대칭형 멀티프로세서(SMP) 환경에서는 모든 CPU 코어가 단일 메모리 버스를 공유했습니다. 그러나 코어 수가 수백 개로 증가하고 AI 워크로드가 급증함에 따라 메모리 하드웨어는 복합적인 이종 계층 구조로 진화했습니다:
- **HBM (High Bandwidth Memory)**: 실리콘 관통 전극(TSV)으로 칩 위에 적층된 초고속 메모리. 테라바이트급 대역폭을 제공하나 용량이 제한적임.
- **Local DDR5 SDRAM**: CPU 소켓 직결 메모리. 균형 잡힌 속도와 용량.
- **CXL (Compute Express Link) Memory**: PCIe 5.0/6.0 물리 계층 기반의 저지연 캐시 코히어런트 확장 메모리. 대규모 용량 확장이 가능하나 지연시간이 로컬 DRAM보다 약 1.5~2배 김.

## 2. AutoNUMA와 힌팅 페이지 폴트 (NUMA Hinting Page Fault)

응용 프로그램이 수백 기가바이트의 메모리를 할당할 때, 커널이 어떤 페이지를 Fast Tier에 두고 어떤 페이지를 Slow Tier에 둘지 정적으로 결정하는 것은 불가능합니다. 런타임에 메모리 접근 국소성(Locality)을 추적해야 합니다.

### 2.1 하드웨어 트랩을 이용한 접근 추적 메커니즘
커널은 주기적으로 백그라운드 태스크를 통해 VMA 내 페이지 테이블 엔트리의 접근 권한을 무효화(`_PAGE_PROTNONE`)합니다:
1. CPU가 해당 주소를 읽거나 쓸 때 하드웨어 페이지 폴트(Page Fault) 예외가 발생합니다.
2. 커널의 예외 핸들러 `do_numa_page()`가 호출됩니다.
3. 커널은 이것이 유효하지 않은 메모리 접근이 아니라 **NUMA 모니터링을 위한 의도적 힌팅 폴트**임을 인식합니다.
4. 폴트를 발생시킨 CPU의 NUMA 노드 번호와 해당 페이지의 물리 위치를 비교하여 `numa_hinting_faults` 카운터를 증가시킨 뒤, PTE 권한을 복원하고 명령어를 재개합니다.

이 방식은 페이지 테이블을 일일이 전수 스캔하지 않고도 오직 실제 CPU가 읽고 쓰는 활성 페이지에 대해서만 이벤트 기반(Event-driven)으로 핫니스를 수집할 수 있게 해줍니다.

## 3. 마이그레이션 파이프라인과 대역폭 쓰로틀링

### 3.1 승격(Promotion)과 강등(Demotion)
- **승격 (Slow -> Fast)**: Slow Tier에 상주하던 페이지의 힌팅 폴트 빈도가 임계치를 초과하면, 고속 Tier로 페이지를 복사하고 페이지 테이블 매핑을 갱신합니다.
- **강등 (Fast -> Slow)**: Fast Tier의 가용 공간이 고갈되면, `kswapd`는 페이지를 디스크로 방출하는 대신 Slow Tier로 이주(Demote)시킵니다. 디스크 I/O가 전혀 발생하지 않으므로 레이턴시 스파이크가 방지됩니다.

### 3.2 인터커넥트 대역폭 포화 방지
페이지 마이그레이션은 CPU 버스와 인터커넥트 대역폭을 소모합니다. 대량의 페이지가 한꺼번에 마이그레이션되면 통신 병목이 발생하므로, 커널은 `max_migrations_per_tick` 파라미터를 통해 초당 이동 가능한 페이지 수를 엄격히 제한(Throttling)합니다.

---

## 4. 결론

리눅스 커널의 이종 메모리 계층화는 차세대 CXL 데이터센터와 AI 가속 인프라에서 고가의 고속 메모리 활용도를 100%로 끌어올리고 대규모 모델의 추론 및 학습 비용을 대폭 절감하는 첨단 메모리 오케스트레이션 서브시스템입니다.
