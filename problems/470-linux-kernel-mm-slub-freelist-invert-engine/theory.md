# 리눅스 커널 SLUB 메모리 할당자 및 동결(Frozen) 슬랩 아키텍처 심층 이론

## 1. 메모리 할당자의 진화: 왜 SLAB에서 SLUB인가?

전통적인 리눅스 커널의 SLAB 할당자(`mm/slab.c`)는 다음과 같은 심각한 구조적 문제점을 노출했습니다:
1. **대기열 큐(Queue) 오버헤드**: 각 CPU마다 `kmem_cache`에 속한 객체들을 캐싱하기 위해 전용 배열 큐(`struct array_cache`)를 유지했습니다. 수백 개의 CPU와 수천 개의 슬랩 캐시가 결합되면 이 큐 메타데이터 자체에만 수 기가바이트의 메모리가 낭비되었습니다.
2. **이중 잠금 및 핑퐁 경합**: 객체를 할당하거나 해제할 때 로컬 큐가 비거나 차면 전역 슬랩 리스트 락(`cache_chain_lock` / `n->list_lock`)을 잡아야 했으며, 다중 코어에서 락 획득을 위한 스핀락 경합이 극심했습니다.

크리스토프 라메터가 고안한 **SLUB 할당자(`mm/slub.c`)**는 모든 객체 큐를 과감히 폐기하고, 물리 메모리 페이지(`struct page` / `struct slab`) 자체에 내장된 단일 연결 리스트(In-Object Freelist)를 직접 활용하는 Unqueued 디자인을 확립했습니다.

## 2. 패스트 패스(Fast Path)와 프로즌 슬랩(Frozen Slab)의 마법

SLUB의 극한 성능은 **"동결(Frozen)"** 개념에서 나옵니다.

### 2.1 kmem_cache_cpu의 단일 포인터 아키텍처
CPU가 메모리를 할당할 때:
```c
struct kmem_cache_cpu {
    void **freelist;      /* 활성 슬랩의 첫 번째 빈 객체 포인터 */
    struct page *page;    /* 현재 CPU에 할당된 활성 슬랩 페이지 */
};
```
CPU는 `c->freelist`가 가리키는 객체를 가져오고, 객체 내부에 저장된 다음 객체 포인터(`*freelist`)로 포인터를 전진시킵니다. 이 과정에는 스핀락이나 뮤텍스가 일절 개입하지 않습니다.

### 2.2 프로즌 슬랩의 배타성과 동시적 원격 해제
활성 슬랩은 `page->frozen = 1`로 마킹됩니다:
- **할당의 배타성**: 해당 슬랩에서 객체를 꺼내갈 수 있는 주체는 오직 그 슬랩을 동결한 단 하나의 CPU뿐입니다.
- **해제의 병렬성**: 다른 CPU가 해당 슬랩에서 이전에 할당받았던 객체를 `kfree()`할 경우, 활성 CPU의 `c->freelist`를 건드리지 않고, 대신 슬랩 페이지의 `page->freelist`에 원자적 `cmpxchg_double` 명령어로 살포시 삽입합니다.

## 3. 슬로우 패스(Slow Path)와 프리리스트 인버트(Invert)

활성 CPU가 자신의 로컬 `freelist`를 모두 비우면 슬로우 패스로 분기합니다.

### 3.1 원격 프리리스트 반전 (Invert)
활성 CPU는 즉시 새 슬랩을 찾으러 가지 않고, 다른 CPU들이 `page->freelist`에 원격으로 반환해 놓은 객체들이 있는지 검사합니다:
```c
if (page->freelist) {
    c->freelist = page->freelist;
    page->freelist = NULL;
    /* 즉시 로컬 freelist가 채워져 패스트 패스로 복귀! */
}
```
이 한 번의 원자적 스왑(Swap/Invert)을 통해 노드 락이나 버디 할당자를 거치지 않고도 즉각 할당을 재개할 수 있습니다.

### 3.2 언프리즈(Unfreeze)와 노드 부분 리스트(Node Partial)
만약 로컬과 원격 프리리스트가 모두 비어있다면, 해당 슬랩은 완전히 포화(Full)된 상태입니다.
CPU는 해당 슬랩의 동결을 해제(`page->frozen = 0`)하고 활성 캐시에서 떼어냅니다.
이후 NUMA 노드의 공유 부분 리스트(`kmem_cache_node->partial`)에서 다른 슬랩을 수확(Harvest)하여 동결시키거나, 버디 할당자로부터 새로운 물리 페이지를 할당받습니다.

## 4. 메모리 낭비 방지: min_partial 임계치와 버디 반납

서버 워크로드가 피크를 지나 메모리 사용량이 감소할 때, 동결 해제된 슬랩들의 객체가 속속들이 반환됩니다.
슬랩 내의 모든 객체가 해제되어 `inuse == 0`이 되었을 때:
- 만약 시스템의 모든 빈 슬랩을 즉시 버디 할당자로 반환하면, 직후의 할당 요청 시 버디 할당자를 다시 호출해야 하므로 슬랩 할당/해제 핑퐁(Trashing) 오버헤드가 발생합니다.
- 따라서 SLUB은 `n->nr_partial <= s->min_partial`일 때는 완전히 빈 슬랩이라도 노드 부분 리스트에 보관해 두고, `min_partial`을 초과하여 충분한 여유 슬랩이 확보되었을 때만 물리 페이지를 버디 할당자에 반환합니다.

SLUB 할당자는 현대 멀티코어 리눅스 커널의 메모리 고속화, NUMA 지역성 극대화, 그리고 단편화 억제를 동시에 달성한 시스템 소프트웨어 엔지니어링의 정점입니다.
