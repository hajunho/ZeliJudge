# [Pro #270 깊이 읽기] eBPF BPF_MAP_TYPE_LPM_TRIE 최장 일치 접두사 라우팅과 이진 패트리샤 트라이의 커널 내부 원리

## 1. 리눅스 네트워킹의 병목과 eBPF 패킷 포워딩 혁명

전통적인 리눅스 커널의 네트워크 포워딩(L3 Forwarding)은 `iptables`, `netfilter`, 그리고 FIB(Forwarding Information Base) 라우팅 테이블을 거칩니다. 수만 개 이상의 CIDR 방화벽 규칙과 서브넷 라우트가 존재하는 대규모 데이터센터나 쿠버네티스 클러스터 환경에서는 다음과 같은 심각한 성능 저하가 발생합니다:
- **선형 탐색($O(N)$)의 한계**: 규칙이 늘어날수록 패킷당 순회해야 하는 체인 수가 급증하여 패킷 처리 지연(Latency)이 치솟습니다.
- **sk_buff 할당 오버헤드**: 패킷이 NIC 드라이버에서 커널 L3 계층으로 올라갈 때마다 거대한 소켓 버퍼(`struct sk_buff`)를 할당하고 파싱하는 불필요한 메모리 복사가 수반됩니다.

이를 해결하기 위해 리눅스 4.11 커널에 도입된 **`BPF_MAP_TYPE_LPM_TRIE`**는 커널 네트워크의 최하단인 **XDP(eXpress Data Path)** 및 **tc(Traffic Control)** 계층에서 `sk_buff` 할당 없이 원시 패킷 헤더만을 읽어 **최장 일치 접두사(Longest Prefix Match, LPM)**를 $O(W)$(IPv4의 경우 $W \le 32$)의 일정한 시간 복잡도로 판별합니다. 실리움(Cilium)과 메타의 카트란(Katran) L4 로드 밸런서가 단일 서버에서 40Gbps~100Gbps 와이어 스피드(Wire Speed)를 달성할 수 있는 핵심 비결이 바로 이 맵입니다.

## 2. 최장 일치 접두사(LPM)와 이진 기수 트리(Radix Trie)의 구조

IP 라우팅에서 하나의 목적지 IP는 여러 개의 서브넷 범위에 동시에 포함될 수 있습니다:
```
  [ 0.0.0.0/0 ]          <--- 기본 게이트웨이 (인터넷 전체 포괄, Prefixlen = 0)
       ▲
       │ 포함
  [ 10.0.0.0/8 ]         <--- 사설망 대역 (Prefixlen = 8)
       ▲
       │ 포함
  [ 10.1.0.0/16 ]        <--- 특정 데이터센터 VPC (Prefixlen = 16)
       ▲
       │ 포함
  [ 10.1.2.0/24 ]        <--- 특정 랙 서브넷 (Prefixlen = 24)
       ▲
       │ 포함
  [ 10.1.2.100/32 ]      <--- 특정 호스트/컨테이너 단일 IP (Prefixlen = 32)
```

인터넷 라우팅의 기본 공리(RFC 1812)는 **"가장 구체적인(즉, 접두사 길이 $P$가 가장 긴) 경로를 선택해야 한다"**는 것입니다. 목적지가 `10.1.2.100`인 패킷은 위의 5개 라우트에 모두 부합하지만, 반드시 가장 구체적인 `/32` 라우트를 따라야 합니다.

### 이진 기수 트리(Binary Radix Tree) 구현 메커니즘
```
                        [ Root (0.0.0.0/0) ]
                             /                                  bit=0      bit=1
                          /                                 [ 0.0.0.0/1 ]     [ 128.0.0.0/1 ]
                       ...                 ...
                      /
               [ 10.0.0.0/8 ]  <--- Prefixlen 8 (Leaf node with RouteInfo)
                   /
                bit=0 (0)
                 /
             bit=1 (1)
               /
         [ 10.1.0.0/16 ]       <--- Prefixlen 16
             /
         bit=0 (0)
           /
       bit=1 (1)
         /
   [ 10.1.2.0/24 ]             <--- Prefixlen 24
```

- 각 노드는 2개의 자식 포인터(`child[0]`, `child[1]`)를 가지며, IP의 비트열을 따라 분기합니다.
- 노드 내부에는 해당 깊이까지의 네트워크 접두사가 유효한 라우트인지 여부(`is_leaf`)와 실제 라우팅 데이터(`RouteInfo`)가 저장됩니다.
- 탐색 과정에서 트리를 루트부터 하향식으로 내려가면서, 거쳐가는 경로 상에서 만나는 **가장 마지막 `is_leaf` 노드**가 바로 최장 일치 접두사(LPM)입니다.
- 탐색 시간은 등록된 전체 라우트 수 $N$에 전혀 영향을 받지 않으며, 오직 IPv4 주소의 비트 길이인 32회 루프(또는 트라이의 최대 깊이)로 엄격히 제한됩니다.

## 3. 등가 다중 경로(ECMP)와 5-튜플 해싱

현대 고성능 네트워크 스위치 및 로드 밸런서에서는 동일한 목적지 네트워크로 가는 여러 개의 게이트웨이 경로를 묶어 대역폭을 확장하는 **등가 다중 경로(ECMP, Equal-Cost Multi-Path)**를 사용합니다.

단순 라운드 로빈(Round-Robin) 방식으로 패킷을 교대로 보내면 다음과 같은 심각한 문제가 발생합니다:
- 경로별 미세한 지연 시간 차이로 인해 TCP 패킷의 **순서 역전(Packet Reordering)**이 발생합니다.
- TCP 수신측에서 중복 ACK(Duplicate ACK)를 발생시키고 불필요한 패킷 재전송과 혼잡 윈도우(CWND) 급락을 초래합니다.

따라서 ECMP는 반드시 동일한 TCP/UDP 연결(Flow)에 속하는 패킷들이 항상 동일한 넥스트홉으로 향하도록 **5-튜플 일관성 해시(5-tuple Hashing)**를 적용합니다:

$$\text{Flow\_Key} = (\text{src\_ip}, \text{dst\_ip}, \text{src\_port}, \text{dst\_port}, \text{protocol})$$
$$\text{hop\_index} = \text{CRC32}(\text{Flow\_Key}) \pmod{\text{len(next\_hops)}}$$

이를 통해 플로우 내부의 패킷 순서 역전을 100% 방지하면서도 서로 다른 수천만 개의 플로우 트래픽을 다중 코어 및 다중 물리 회선으로 균등하게 분산시킬 수 있습니다.

## 4. 트라이 가지치기(Node Pruning)와 메모리 무결성

라우트 삭제(`DELETE`) 연산 시, 단순히 타깃 노드의 `is_leaf` 플래그만 끄고 방치하면 트라이 내부에 자식도 없고 라우트 데이터도 없는 **유령 노드(Zombie Intermediate Nodes)**가 영구히 누적되어 커널 메모리를 낭비합니다.

따라서 삭제 연산 후에는 경로를 역추적(Stack pop)하면서:
1. 해당 노드가 더 이상 유효 라우트가 아니고,
2. 좌우 자식 노드가 모두 `None`인 경우,
부모 노드의 해당 자식 포인터를 `None`으로 정리하고 메모리를 즉각 회수하는 **상향식 가지치기(Bottom-up Tree Pruning)**를 수행합니다. 이를 통해 트라이의 총 노드 수(`trie_node_count`)와 최대 깊이(`max_depth`)가 항상 최소한의 기하학적 형태로 유지됩니다.
