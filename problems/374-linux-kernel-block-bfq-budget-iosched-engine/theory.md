# 리눅스 커널 BFQ (Budget Fair Queueing) 스토리지 I/O 스케줄러 백서

## 1. 개요: CFQ의 한계와 BFQ의 탄생

리눅스 커널 2.6부터 오랫동안 표준 스토리지 I/O 스케줄러로 군림했던 **CFQ(Completely Fair Queueing)**는 각 프로세스에 일정 시간(Time Slice, 예: 100ms) 동안 디스크 점유권을 부여하는 방식으로 동작했습니다.

그러나 시간 기반 공정 큐잉은 회전식 하드 디스크(HDD)의 탐색 시간(Seek Time) 차이와 최신 SSD/플래시 메모리의 비대칭 I/O 특성 앞에서 심각한 병목을 드러냈습니다:
- **대역폭 낭비**: 시간 슬라이스 동안 순차 I/O를 수행하는 프로세스는 높은 대역폭을 누리지만, 랜덤 I/O를 수행하는 프로세스는 시간의 대부분을 헤드 이동에 소비하여 전체 디바이스 처리량이 급감했습니다.
- **대화형(Interactive) 태스크의 기아**: 백그라운드 대용량 복사 프로세스가 긴 시간 슬라이스를 독점하는 동안 마우스 클릭, 동영상 렌더링, 오디오 버퍼링 요청이 큐 뒤에 갇혀 심각한 시스템 버벅임(UI Lag)이 발생했습니다.

파올로 발렌테(Paolo Valente)가 설계한 **BFQ(Budget Fair Queueing / `block/bfq-iosched.c`)**는 시간 슬라이스 대신 **섹터(또는 바이트) 수량으로 정의되는 버짓(Budget)**을 할당함으로써 이 문제를 근본적으로 해결했습니다.

## 2. $B^2\text{WF}^2\text{Q}+$ 알고리즘 수학적 기초

BFQ의 이론적 토대는 패킷 교환망의 최적 패킷 스케줄링 이론인 **$\text{WF}^2\text{Q}+$ (Worst-case Fair Weighted Fair Queueing)**를 스토리지 I/O 영역으로 확장한 **$B^2\text{WF}^2\text{Q}+$**입니다.

### 2.1 가상 시간(Virtual Time)의 진화
글로벌 가상 시간 $V(t)$는 디바이스가 실제로 처리한 섹터 수량을 활성 큐들의 유효 가중치 합으로 나눈 비율에 비례하여 단조 증가합니다:
$$
V(t + \Delta t) = V(t) + \frac{\text{sectors}}{W_{\text{eff}}}
$$
가상 시간은 시스템 전체가 얼마나 많은 유효 작업을 수행했는지를 나타내는 정규화된 지표입니다.

### 2.2 가상 시작/종료 시각의 태깅
각 큐 $k$가 활성화(I/O 요청 발생)될 때:
- **가상 시작 시각**:
  $$
  S_k = \max(V(t), F_k^{\text{prev}})
  $$
- **가상 종료 시각**:
  $$
  F_k = S_k + \frac{B_k}{W_{k, \text{eff}}}
  $$
여기서 $B_k$는 큐 $k$에 할당된 1회 버스트 섹터 버짓이며, $W_{k, \text{eff}}$는 큐의 유효 가중치입니다.

### 2.3 큐 선택 규칙 (Eligibility & Earliest Finish)
스케줄러는 가상 시작 시각이 현재 가상 시간 이하인 '준비된(Eligible)' 큐 집합 $\mathcal{E} = \{ k \mid S_k \le V(t) \}$ 중에서, **가상 종료 시각 $F_k$가 가장 작은 큐**를 선택하여 서비스를 시작합니다.
이 방식은 어떤 큐도 자신의 할당 몫 이상으로 디바이스를 독점할 수 없도록 엄격한 상한선(Worst-case Fairness)을 수학적으로 보장합니다.

## 3. 대화형 태스크를 위한 저지연 메커니즘 (Low-Latency Heuristics)

BFQ가 데스크톱과 모바일 장치에서 압도적인 체감 반응성을 제공하는 비결은 **저지연 휴리스틱(Low-Latency Heuristics)**에 있습니다:

```
+---------------------------------------------------------------------------------+
|                       BFQ 저지연 및 대화형 휴리스틱 흐름                       |
+---------------------------------------------------------------------------------+
  [Task Emits I/O]
         │
         ├───► 1. 휴면 시간(Think Time) 검사
         │        - 장시간 idle 후 소량의 I/O를 요청하는가?
         │        - YES -> 대화형(Interactive) / Soft Real-Time으로 분류
         │
         ├───► 2. 가중치 부스트 (Interactive Boost)
         │        - W_{eff} = W * boost_factor (예: 2배~10배)
         │        - F_k가 매우 천천히 증가 -> 우선 디스패치 권한 장기 유지
         │
         ├───► 3. 백그라운드 벌크 큐 선점 (Preemption)
         │        - 현재 대용량 큐가 버짓을 소진 중이더라도
         │          대화형 큐 도착 시 즉시 현재 요청 완료 직후 디스패치 인터셉트
         ▼
  [Interactive Request Dispatched in < 1ms]
```

1. **소프트 실시간 및 대화형 탐지**:
   - 오디오/비디오 재생 프로세스는 20~30ms마다 소량의 버퍼를 읽고 다시 잠듭니다.
   - BFQ는 큐의 I/O 패턴(요청 간격, 요청 크기)을 감시하여 대화형 태스크를 자동 식별합니다.
2. **동적 버짓 자동 튜닝 (Budget Auto-Tuning)**:
   - 순차 대용량 쓰기는 장치 최대 대역폭을 뽑아낼 수 있도록 큰 버짓($B_k = 512$ 섹터 이상)을 부여합니다.
   - 대화형 태스크에는 작은 버짓($B_k = 16 \sim 32$ 섹터)을 부여하여 즉각 처리 후 장치를 반환하도록 유도합니다.

## 4. 커널 실무와 성능 엔지니어링

현대 리눅스 환경에서 BFQ는 SATA SSD, eMMC, HDD, SD 카드 등 레이턴시 편차가 크고 I/O 깊이가 제한적인 스토리지 환경에서 최고의 성능을 발휘합니다.
- `cat /sys/block/sda/queue/scheduler` -> `[bfq] mq-deadline none`
- Cgroup v2 `io.weight` 설정을 통해 컨테이너별/서비스별 I/O 대역폭을 수학적으로 완벽하게 격리할 수 있습니다.

본 문제는 BFQ 스케줄러의 $B^2\text{WF}^2\text{Q}+$ 가상 시간 추적, 버짓 차감 및 대화형 큐 선점 메커니즘을 100% 정밀하게 재현하여 고성능 커널 I/O 스케줄링의 진수를 체득하게 합니다.
