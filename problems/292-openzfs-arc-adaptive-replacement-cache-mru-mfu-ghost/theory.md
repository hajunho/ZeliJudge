# 고성능 스토리지 캐싱 백서: OpenZFS ARC(Adaptive Replacement Cache), 고스트 캐시와 스캔 오염 방어

## 1. 캐시 교체 알고리즘의 역사와 한계

운영체제와 스토리지 시스템에서 DRAM 캐시는 수백 나노초(ns)의 빠른 속도로 수 밀리초(ms)가 소요되는 디스크 I/O를 은폐하는 핵심 계층입니다.

```text
               [전통적 캐시 알고리즘의 2대 진영]
  
       (1) 최근성 중심 (Recency): LRU (Least Recently Used)
       - 장점: 시간 지역성(Temporal Locality)에 신속 대응
       - 치명적 단점: 순차 스캔(Sequential Scan) 1회에 워킹셋 100% 전멸 (Scan Pollution)
  
       (2) 빈도 중심 (Frequency): LFU (Least Frequently Used)
       - 장점: 반복 참조되는 인기 데이터 영구 보호
       - 치명적 단점: 과거의 인기가 영원히 남는 빈도 정체 (Frequency Starvation / Cache Bloat)
```

1990년대 중반 이후 2Q, LRU-2, LRFU 등 다양한 하이브리드 기법이 제안되었으나, 대부분 워크로드에 따라 수동 튜닝이 필요하거나 복잡도가 높았습니다.

## 2. 님로드 메기도와 다르멘드라 모다의 ARC (FAST 2003)

2003년 IBM 알마덴 연구소의 메기도와 모다는 튜닝 파라미터가 전혀 필요 없이, 시스템이 실시간으로 입출력 패턴을 학습하여 스스로를 최적화하는 **자가 적응형 교체 캐시 (ARC: Adaptive Replacement Cache)**를 고안했습니다.

### 4대 리스트의 상호작용과 고스트 캐시

```text
                      [전체 관리 공간 (크기: 2c)]
    ┌───────────────────────────────┬───────────────────────────────┐
    │     L1 = T1 ∪ B1 (최근성)     │     L2 = T2 ∪ B2 (빈도성)     │
    ├───────────────┬───────────────┼───────────────┬───────────────┤
    │      T1       │      B1       │      T2       │      B2       │
    │  (실제 데이터)│  (고스트 키)  │  (실제 데이터)│  (고스트 키)  │
    └───────────────┴───────────────┴───────────────┴───────────────┘
    ◀───── p ──────▶                ◀──── c - p ────▶
    ▲                               ▲
    └───────────────┬───────────────┘
             실제 캐시 (크기: c)
```

1. **실제 데이터 리스트 ($T_1, T_2$)**:
   - $T_1$: 최근에 1회 읽힌 페이지 (MRU 성향).
   - $T_2$: 2회 이상 읽힌 페이지 (MFU 성향).
   - 총 메모리 사용량은 언제나 $|T_1| + |T_2| \le c$로 엄격히 제한됩니다.
2. **고스트 캐시 ($B_1, B_2$)**:
   - $T_1$과 $T_2$에서 메모리 부족으로 디스크로 축출된 페이지의 **키(식별자)만을 보관**합니다.
   - 고스트 캐시는 데이터 바이트를 들고 있지 않으므로 메모리를 거의 소비하지 않으면서도, **"방금 축출한 페이지가 곧바로 다시 필요해졌는가?"**를 추적하는 정밀한 피드백 센서 역할을 합니다.

## 3. 학습과 적응: $p$의 마법

ARC의 핵심 지능은 $B_1$과 $B_2$의 히트 여부에 따라 $T_1$의 목표 크기인 $p$를 실시간으로 가감하는 피드백 루프에 있습니다:

* **$B_1$ 히트 시**: "최근에 한 번 들어왔다가 쫓겨난 페이지가 또 요청되었다. 최근성 캐시($T_1$)의 크기가 부족하다!" $\implies p$를 증가시켜 $T_1$ 공간 확장.
* **$B_2$ 히트 시**: "자주 쓰이던 페이지가 쫓겨났다가 또 요청되었다. 빈도성 캐시($T_2$)의 크기가 부족하다!" $\implies p$를 감소시켜 $T_2$ 공간 확장.
* **변화량의 동적 스케일링**:
  $$\text{증가폭 } \Delta_1 = \max\left(1, \frac{|B_2|}{|B_1|}\right), \quad \text{감소폭 } \Delta_2 = \max\left(1, \frac{|B_1|}{|B_2|}\right)$$
  한쪽 고스트 캐시가 압도적으로 크면, 불균형을 신속하게 교정하기 위해 큰 폭으로 $p$를 도약시킵니다.

## 4. OpenZFS와 엔터프라이즈 스토리지에서의 실무적 의의

썬 마이크로시스템즈(Sun Microsystems)의 매슈 아렌스(Matthew Ahrens)와 제프 본윅(Jeff Bonwick)은 ZFS를 설계할 때 ARC를 메인 스토리지 캐시로 채택했습니다:
1. **스캔 오염 면역**: 일일 백업이나 대용량 파일 복사 작업이 진행되어도, 신규 데이터는 $T_1$에만 잠시 머물다 축출되며, $T_2$에 존재하는 데이터베이스 인덱스와 메타데이터는 안전하게 보호됩니다.
2. **무설정(Zero-Tuning)**: 엔지니어가 수동으로 캐시 비율을 튜닝할 필요 없이, OLTP와 배치 워크로드의 교차 환경에서 스스로 최적의 히트율을 수렴합니다.
