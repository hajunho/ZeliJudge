# 005. 문자열 덧셈의 늪: 불변 객체(Immutable)와 메모리 복사 지옥

* **난이도**: Lv.1 (실무 필수 / 데이터 처리)
* **카테고리**: 메모리 관리, 문자열 불변성(Immutability), 가변 버퍼, 시간 복잡도
* **시간 제한**: 1.0초
* **메모리 제한**: 256 MB
* **핵심 CS 이론**: [theory.md 읽으러 가기](theory.md)

---

## 📖 실무 버그 시나리오

빅데이터 분석 파이프라인을 구축하던 주니어 데이터 엔지니어 도현이는 매일 밤 수십만 줄의 서버 로그에서 에러 메시지만 추출하여 하나의 통합 보고서 문자열을 생성하는 배치 작업을 맡았습니다.

도현이는 AI 코딩 도구에게 다음과 같이 요청했습니다:

> *"로그 리스트를 받아서 `[ERROR]`로 시작하는 라인들의 접두사를 제거하고 개행 문자로 합쳐서 하나의 큰 텍스트 문자열로 만들어 줘."*

AI는 너무나 익숙하고 친숙한 5줄짜리 파이썬 코드를 작성해 주었습니다:

```python
# AI가 작성해 준 코드
def aggregate_errors(log_lines):
    report = ""
    for line in log_lines:
        if line.startswith("[ERROR] "):
            message = line[8:]          # 접두사 '[ERROR] ' 제거
            report += message + "\n"    # <- 재앙의 시작!
    return report
```

도현이는 테스트용 샘플 로그 50줄을 넣고 실행해 보았습니다. **0.0005초** 만에 완벽한 보고서가 출력되었습니다. 도현이는 만족하며 코드를 프로덕션 배치 서버에 등록했습니다.

하지만 다음 날 새벽 2시, 하루치 에러 로그 10만 건($N=100,000$)이 들어오자 **배치 서버가 1시간이 지나도 끝나지 않았습니다.**  
서버의 CPU 사용률은 100%를 찍었고, 메모리 사용량은 수 GB까지 치솟았으며, 가비지 컬렉터(GC)가 미친 듯이 돌며 프로세스가 멈춰버렸습니다.

당황한 도현이가 AI에게 *"문자열 합치기가 왜 1시간이나 걸리지?"*라고 물었지만, AI는 "서버의 RAM이 부족하니 스왑 메모리를 늘리라"는 엉뚱한 소리만 늘어놓았습니다.

도현이의 코드에서 `report += message`는 왜 컴퓨터를 마비시켰을까요?

AI는 파이썬의 `+` 연산자가 편리해 보여 썼지만, **파이썬 문자열이 '불변(Immutable)' 객체이며 루프마다 이전 데이터를 통째로 메모리에 새로 복사하고 있다는 사실($O(N^2)$의 지옥)**을 전혀 몰랐던 것입니다.

## 🎯 문제 설명

대규모 서버 로그 $N$줄이 주어집니다.
각 줄의 문자열 중 접두사가 `[ERROR] `(대괄호 ERROR 뒤 공백 1칸 포함, 8글자)로 시작하는 로그만 필터링하세요.

필터링된 각 에러 로그에서 `[ERROR] ` 접두사를 제거한 실제 에러 본문 메시지들을 **원래 순서대로 개행 문자(`\n`)로 연결한 하나의 큰 문자열**로 구성하여 출력하세요.

### ⚠️ 주의 사항
* 에러 로그가 최대 $100,000$줄 주어집니다.
* `report += message` 방식으로 문자열을 누적하면 **시간 초과(Time Limit Exceeded)** 또는 **메모리 초과(Memory Limit Exceeded)** 판정을 받게 됩니다.
* **가변 리스트(Mutable List)에 모은 뒤 `join()`을 사용하거나 스트리밍 방식으로 $O(N)$ 시간 복잡도 내에 해결해야 합니다.** ([theory.md](theory.md) 참고)

---

## 📥 입력 형식 (Input)

* **첫째 줄**: 로그의 총 줄 수 $N$ ($1 \le N \le 100,000$)
* **둘째 줄부터 $N$개의 줄**: 각 줄에 로그 문자열이 주어집니다.
  * 각 로그 줄의 길이는 $1$ 이상 $50$ 이하의 문자열입니다.
  * 공백, 영문 대소문자, 숫자, 특수문자로 구성될 수 있습니다.

---

## 📤 출력 형식 (Output)

* `[ERROR] `로 시작하는 로그들의 접두사를 제거한 메시지들을 원래 순서대로 줄바꿈(`\n`)하여 출력합니다.
* 마지막 줄 끝에도 개행 문자(`\n`)가 포함되어야 합니다.
* 만약 `[ERROR] `로 시작하는 로그가 단 하나도 없다면 아무것도 출력하지 않거나 빈 줄을 출력합니다.

### 입력
```text
5
[INFO] Server started on port 8080
[ERROR] Database connection timed out
[DEBUG] User id=42 requested /profile

[INFO] Health check passed
```

### 출력
```text
Database connection timed out
Payment gateway 502 Bad Gateway
```

## 🔍 채점 엣지케이스 안내
1. **$N = 100,000$ 대규모 에러 로그**: 모든 줄이 `[ERROR] `로 시작하여 $O(N^2)$ 문자열 덧셈 시 100% 타임아웃 발생하는 케이스
2. 에러 로그가 단 1건도 없는 경우
3. 접두사가 `[ERROR]`이지만 뒤에 공백이 없는 경우 (예: `[ERROR]DiskFull` $\rightarrow$ 무시되어야 함)
4. 에러 메시지 내용이 빈 문자열인 경우 (예: `[ERROR] ` $\rightarrow$ 빈 줄로 출력되어야 함)
