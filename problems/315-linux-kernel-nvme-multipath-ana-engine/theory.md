# 리눅스 커널 NVMe 네이티브 멀티패싱 및 ANA 아키텍처 이론

## 1. 개요 및 배경: dm-multipath의 한계와 NVMe 네이티브 멀티패스

스토리지 영역 네트워크(SAN) 환경에서 다중 호스트 버스 어댑터(HBA)와 스위치를 통한 다중 경로 연결은 데이터센터 고가용성의 필수 요건입니다.
리눅스는 전통적으로 **Device Mapper Multipath (`dm-multipath`)** 서브시스템을 사용하여 블록 장치 다중화를 구현했습니다.

그러나 초당 수백만 IOPS와 마이크로초 단위 레이턴시를 처리하는 고성능 NVMe-oF 환경에서 `dm-multipath`는 세 가지 치명적 병목을 드러냈습니다:
1. **블록 계층 이중화 오버헤드**: 기본 NVMe 블록 드라이버 위에 Device Mapper 가상 장치 계층이 중첩되어 I/O 경로의 CPU 사이클 소모가 증가합니다.
2. **유저스페이스 데몬(`multipathd`) 의존성**: 경로 상태 검사(Path Checking)와 페일오버 처리가 사용자 공간 데몬과의 IPC를 통해 이루어지므로 장애 감지 및 경로 복구에 수백 밀리초에서 수 초의 지연이 발생합니다.
3. **블록 락킹 경합**: 단일 큐 기반의 전통적 락킹 모델이 멀티코어 NVMe 블록 다중 큐(`blk-mq`)의 병렬성을 저해합니다.

이를 극복하기 위해 리눅스 커널 4.15부터 Christoph Hellwig 등에 의해 **NVMe 네이티브 멀티패스(`drivers/nvme/host/multipath.c`, CONFIG_NVME_MULTIPATH)**가 개발되었습니다.

---

## 2. NVMe 서브시스템과 네임스페이스 헤드 구조

NVMe 네이티브 멀티패스는 각 물리 컨트롤러 장치(`/dev/nvme0`, `/dev/nvme1`) 위에 가상의 **네임스페이스 헤드(`nvme_ns_head`)**를 생성하여 단일 블록 디바이스(`/dev/nvme0n1`)로 노출합니다.

```
       /dev/nvme0n1 (Virtual Namespace Head: struct nvme_ns_head)
                         |
      +------------------+------------------+
      |                                     |
      v                                     v
/dev/nvme0c0n1 (Path 1)               /dev/nvme1c0n1 (Path 2)
Controller 0 (PCIe Slot 1)            Controller 1 (PCIe Slot 2)
```

애플리케이션이 `/dev/nvme0n1`로 I/O를 전송하면, 커널의 `nvme_find_path()` 함수가 즉각 활성 경로 중 하나를 선택하여 하위 드라이버 큐로 직접 디스패치합니다.

---

## 3. NVMe 비대칭 네임스페이스 접근 (ANA, NVMe TP 4004)

엔터프라이즈 듀얼 컨트롤러 스토리지 어레이에서 특정 SSD 네임스페이스는 물리적으로 컨트롤러 A의 백플레인에 직접 연결되어 있고, 컨트롤러 B는 내부 PCIe 브릿지를 통해 우회 접근해야 할 수 있습니다.

이러한 하드웨어 비대칭성을 추상화하기 위해 NVMe 표준은 **ANA(Asymmetric Namespace Access)** 프로토콜을 규정했습니다:

- **`OPTIMIZED` (최적 경로)**:
  - 타깃 SSD 미디어에 직접 연결된 로컬 고속 경로입니다. 최대 대역폭과 최소 지연시간을 제공합니다.
- **`NON_OPTIMIZED` (비최적 경로)**:
  - 컨트롤러 간 미러링 링크(Cross-link)를 경유하여 기능적으로는 동작하지만 대역폭이 제한되고 지연시간이 증가한 경로입니다.
- **`INACCESSIBLE` (접근 불가 경로)**:
  - 타깃 링크 단선이나 펌웨어 업데이트 중인 상태입니다. 이 경로로 들어온 I/O는 즉시 실패 처리되거나 보류됩니다.
- **`PERSISTENT_LOSS` (영구 손실 경로)**:
  - 하드웨어 장애로 복구가 불가능한 상태입니다.
- **`CHANGE` (상태 전환 중)**:
  - 타깃 내부 페일오버 등으로 비대칭 속성이 재배치되는 과도기 상태입니다.

## 4. 경로 선택 정책 (I/O Policies)

커널 파라미터 `nvme_core.multipath=Y` 및 시스프스 인터페이스(`/sys/class/block/nvme0n1/queue/iopolicy`)를 통해 경로 선택 알고리즘을 지정할 수 있습니다:

1. **`round-robin` (기본값)**:
   - 가용 `OPTIMIZED` 경로 목록을 순환하며 요청을 균등하게 분산합니다.
   - 모든 `OPTIMIZED` 경로가 두절되면 `NON_OPTIMIZED` 경로 목록으로 순환 대상을 자동 강등(Fallback)합니다.
2. **`queue-depth` (부하 분산 정책)**:
   - 각 경로 컨트롤러의 인플라이트 I/O 개수(`reqs_in_flight`)를 추적하여, 현재 대기 큐가 가장 짧은 경로로 새로운 I/O를 라우팅합니다.
   - 네트워크 혼잡이나 컨트롤러 처리 속도 차이가 있는 이종 패브릭 환경에서 테일 레이턴시(Tail Latency)를 대폭 감소시킵니다.

---

## 5. 투명한 장애 복구 및 재큐잉 (Transparent Failover & Requeue)

I/O 실행 중 컨트롤러나 네트워크 장애가 발생하면, 스토리지 타깃은 `NVME_SC_ANA_INACCESSIBLE` 또는 패브릭 타임아웃 에러를 반환합니다.

전통적인 방식에서는 이 에러가 파일 시스템이나 데이터베이스 애플리케이션으로 전달되어 읽기/쓰기 오류를 일으켰습니다.

반면 NVMe 네이티브 멀티패스는 `nvme_failover_req()`를 호출하여:
1. 에러가 발생한 요청을 애플리케이션에 전달하지 않고 블록 계층의 **`requeue_list`**로 안전하게 회수합니다.
2. 타깃으로부터 비동기 이벤트(AEN)를 수신하여 ANA 상태를 최신화합니다.
3. 살아있는 대체 경로를 즉각 탐색하여 I/O를 재전송합니다.
4. 모든 경로가 일시적으로 단절된 경우, 요청을 큐에 버퍼링하고 경로가 회복(`DRAIN_REQUEUE`)될 때까지 대기합니다.

이와 같은 커널 수준의 완전 자율 페일오버 메커니즘은 99.999% 이상의 고가용성을 요구하는 미션 크리티컬 클라우드 스토리지 인프라의 핵심 초석입니다.
