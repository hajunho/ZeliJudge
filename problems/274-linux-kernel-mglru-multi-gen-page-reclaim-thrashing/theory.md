# 리눅스 커널 6.1+ Multi-Gen LRU (MGLRU) 아키텍처 및 페이지 회수 알고리즘 심층 이론

## 1. 레거시 2-List LRU의 30년 역사와 한계

1990년대 초반부터 리눅스 가상 메모리 관리(VMM) 서브시스템의 중심에 서 있던 **Active / Inactive 2-List LRU** 모델은 페이지 참조 비트(`PG_referenced` 및 하드웨어 MMU PTE Young Bit)를 활용한 2차 기회(Second-chance) 알고리즘을 근간으로 작동해 왔습니다.

```
+-------------------------------------------------------------------+
|                     전통적 2-List LRU 구조                        |
|                                                                   |
| [Active List]   Head (최신) <---> Tail (오래됨)                   |
|                        |             |                            |
|                        | (승격)      | (강등 shrink_active_list)  |
|                        v             v                            |
| [Inactive List] Head (최신) <---> Tail (오래됨) ---> [축출 EVICT] |
+-------------------------------------------------------------------+
```

### 레거시 2-List LRU의 3대 구조적 결함:

1. **글로벌 스핀락 병목 (`lruvec->lru_lock`)**:
   - 페이지를 할당, 접근, 분리, 격리, 축출할 때마다 노드 및 cgroup 단위의 단일 스핀락(`lru_lock`)을 획득해야 합니다.
   - 수백 코어의 현대 멀티소켓 서버에서 `lru_lock` 경합(Lock Contention)은 커널 CPU 사용량의 최대 30~40%를 낭비시키는 주원인이었습니다.

2. **접근 빈도(Frequency) 식별 불가 (단 2-State 추적)**:
   - 페이지는 '참조됨' 또는 '참조되지 않음'의 1비트 상태만을 가집니다.
   - 10만 번 읽힌 핵심 데이터베이스 인덱스 페이지와 방금 전 우연히 2번 읽힌 임시 캐시 페이지가 Active 리스트 내에서 완벽하게 동일한 가중치로 취급됩니다.

3. **순차 스트리밍 스캔에 의한 워킹셋 파괴 (캐시 쓰레싱, Thrashing)**:
   - `tar`, `rsync`, 백업 데몬, 데이터베이스 대용량 풀 테이블 스캔(`FTS`)이 발생하면 수 기가바이트의 스트리밍 페이지가 Inactive 리스트로 진입합니다.
   - 비활성 리스트의 압박이 심해지면 `shrink_active_list()`가 발동하여 Active 리스트 꼬리의 페이지들을 Inactive로 대량 강등시킵니다.
   - 이 강등된 페이지들은 단 한 번 읽히고 폐기될 스트리밍 페이지들에 의해 밀려나 디스크로 즉시 축출됩니다.
   - 이후 실제 비즈니스 트랜잭션이 해당 워킹셋에 접근하면 대량의 메이저 페이지 폴트(Major Page Fault)와 디스크 읽기 I/O 폭풍이 발생하여 시스템이 수 초에서 수 분간 멈추는 쓰레싱 현상이 발생합니다.

## 2. Multi-Gen LRU (MGLRU) 혁신 아키텍처

구글의 Yu Zhao가 설계하고 리눅스 6.1 커널에 공식 병합된 **MGLRU**는 수십 년간 굳어진 2-List 모델을 세대(Generation)와 빈도(Tier)의 다차원 행렬 구조로 전면 재설계했습니다.

```
       세대(Generation) 축: min_seq (오래됨) ---------> max_seq (최신)
      +---------------------------------------------------------------+
Tier 3| [Core Hot WS]      | [Hot Pages]      | [Young Hot Pages]     |
Tier 2| [Frequent Pages]   | [Warm Pages]     | [Young Warm Pages]    |
Tier 1| [Low-Freq Pages]   | [Low-Freq Pages] | [Young Low Pages]     |
Tier 0| [Cold Candidates]  | [Cold Pages]     | [New Allocations]     |
      +---------------------------------------------------------------+
           |                                              ^
           | (Tier 0 페이지만 선별 축출)                  | (Tier >= 1 페이지 구출 승격)
           v                                              |
     [EVICTION DISCARD]                                   +
```

### MGLRU 핵심 기제:

### (1) 세대 시퀀스 번호 (`max_seq` & `min_seq`)
- `max_seq`: 가장 젊은 세대의 번호 (단조 증가). 새로 할당되거나 활발히 참조된 페이지가 배치됩니다.
- `min_seq`: 가장 오래된 세대의 번호. 페이지 회수 시 축출 후보를 탐색하는 기준점이 됩니다.
- 윈도우 크기 `max_seq - min_seq + 1`은 통상 4~7 세대로 제한되어 불필요한 메모리 메타데이터 오버헤드를 방지합니다.

### (2) 다중 빈도 등급 (`nr_tiers`, Generation Tiers)
- 세대 내부에서 각 페이지는 페이지 테이블 엔트리(PTE)의 Accessed 비트 검사 횟수에 따라 4개의 Tier로 분류됩니다:
  - **Tier 0**: 0회 참조 (신규 진입 또는 최근 미참조)
  - **Tier 1**: 1회 참조
  - **Tier 2**: 2회 참조
  - **Tier 3**: 3회 이상 참조 (절대적 워킹셋 코어)

### (3) 선택적 축출과 구출 승격 (Rescue Promotion)
- 메모리 부족 시 MGLRU는 `min_seq` 세대를 스캔합니다.
- 오직 **Tier 0**에 머물고 있는 비참조 페이지만을 축출합니다.
- `min_seq`에 존재하더라도 `tier >= 1`인 페이지는 "살아있는 워킹셋"으로 판정되어 **최신 세대(`max_seq`)로 즉시 승격(Rescue)**됩니다. 이 과정에서 빈도는 점진 감쇠(`max(1, tier - 1)`)되어 다음 세대 주기 동안 다시 평가받습니다.
- 스트리밍 스캔으로 들어온 페이지들은 단 1번만 접근되므로 Tier 0에 머무르며, 워킹셋을 전혀 밀어내지 못하고 Tier 0 리스트 내에서 스스로 소멸(축출)됩니다.

### (4) 락 없는 페이지 테이블 워킹 (`walk_page_range`)
- 기존의 무거운 `lru_lock`을 잡고 rmap(역방향 매핑)을 일일이 순회하는 대신, MGLRU는 프로세스의 페이지 테이블(Paging MMU Table)을 락 없이 직접 순회하여 Accessed 비트를 클리어하고 빈도를 갱신합니다.
- 이를 통해 수백 코어 시스템에서도 선형적인 스케일링 성능을 달성합니다.

## 3. 실측 성능 지표 비교 (MGLRU vs Legacy 2-List)

| 비교 항목 | 레거시 2-List LRU | Multi-Gen LRU (MGLRU) | 개선 효과 |
| :--- | :--- | :--- | :--- |
| **순차 스트리밍 내성** | 취약 (워킹셋 전면 축출) | 완전 보호 (Tier 0만 축출) | **워킹셋 보존율 100% 달성** |
| **kswapd CPU 사용률** | 극심한 `lru_lock` 경합 | 분산 락리스 세대 순회 | **CPU 오버헤드 40~80% 감소** |
| **PSI Memory Stall** | 급격한 스파이크 발생 | 평온하고 일정한 레이턴시 | **메모리 지연 시간 90% 이상 단축** |
| **OOM-Killer 발생률** | 조기 메모리 고갈 오판 | 정밀한 콜드/핫 식별 | **Android/ChromeOS OOM 20~50% 감소** |

MGLRU는 단순한 휴리스틱 캐시 알고리즘 개선을 넘어, 최신 OS 커널 메모리 아키텍처의 패러다임 전환을 상징하는 결정적 기술입니다.
