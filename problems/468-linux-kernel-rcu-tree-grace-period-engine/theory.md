# 리눅스 커널 Tree RCU 및 유예 기간(Grace Period) 아키텍처 이론

## 1. RCU의 기본 원리와 고성능 읽기 임계 구역

리눅스 커널에서 RCU는 읽기 연산의 오버헤드를 극한으로 줄이기 위해 고안되었습니다:
- `rcu_read_lock()`은 단지 현재 태스크의 선점 카운트(`preempt_count`)를 증가시키거나 컴파일러 배리어(`barrier()`)만을 수행합니다.
- 공유 메모리 버스 잠금(Bus Lock)이나 캐시라인 무효화(Cache Invalidation)가 전혀 발생하지 않으므로, 수백 개의 CPU가 동일한 연결 리스트나 라우팅 테이블을 동시에 읽더라도 선형적인 성능을 발휘합니다.

그러나 데이터 구조를 변경하는 쓰기 연산(Updater)은 기존 객체를 메모리에서 즉시 해제할 수 없습니다. 이미 포인터를 들고 읽기 임계 구역을 실행 중인 독자가 존재할 수 있기 때문입니다.
업데이터는 다음 단계를 거칩니다:
1. **제거(Removal)**: 객체의 포인터를 리스트에서 원자적으로 언링크(`rcu_assign_pointer`)합니다. 이제 새로운 독자는 이 객체를 찾을 수 없습니다.
2. **유예 기간(Grace Period)**: 언링크 시점에 이미 객체를 읽고 있던 기존 독자들이 모두 임계 구역을 끝마칠 때까지 기다립니다.
3. **해제(Reclamation)**: 유예 기간이 종료되면 메모리를 안전하게 `kfree()`합니다.

## 2. Tiny RCU vs Tree RCU: 확장성의 한계 극복

- **Tiny RCU**: 단일 코어(UP, Uniprocessor) 임베디드 시스템용. 컨텍스트 스위치만 발생하면 모든 이전 독자가 완료된 것으로 간주되므로 트리가 필요 없습니다.
- **Tree RCU (`kernel/rcu/tree.c`)**: 멀티코어(SMP) 및 거대 NUMA 시스템용.
  전역 카운터를 사용할 경우 모든 CPU가 유휴 상태를 보고할 때마다 단일 캐시라인을 갱신해야 하므로 메모리 버스 병목이 발생합니다.
  Tree RCU는 CPU들을 계층적 트리의 리프 노드에 나누어 배치함으로써, 각 CPU가 오직 로컬 리프 노드의 `rcu_node->lock`과 `qsmask`만을 건드리도록 설계되었습니다.

## 3. 유휴 상태(Quiescent State, QS)와 RCU 임계 구역의 관계

RCU에서 "유휴 상태(Quiescent State)"란 **해당 CPU가 이전 RCU 읽기 임계 구역에 더 이상 머물러 있지 않음을 보장하는 시점**을 의미합니다:
1. **CPU 컨텍스트 스위치 (`schedule()`)**:
   클래식 비선점형 RCU에서는 `rcu_read_lock()` 상태에서 스케줄링이 금지됩니다. 따라서 컨텍스트 스위치가 일어났다는 것은 RCU 임계 구역을 빠져나왔음을 완벽히 보증합니다.
2. **사용자 공간 진입 (`usermode`)**:
   사용자 공간 코드는 커널 RCU 임계 구역을 들고 있을 수 없습니다.
3. **CPU Idle 루프 (`cpuidle`)**:
   CPU가 유휴 상태로 들어간 경우 커널 코드를 실행 중이지 않습니다.

만약 어떤 CPU가 `rcu_read_lock()`을 획득한 채 루프를 돌거나 I/O를 대기하면, 해당 CPU는 QS를 보고할 수 없으며, 결과적으로 전체 트리의 Grace Period 완결이 차단됩니다.

---

## 4. RCU CPU Stall 감지기 (`rcu_stall`)

Grace Period가 수십 초(`CONFIG_RCU_CPU_STALL_TIMEOUT`, 기본 21초) 동안 완료되지 못하면, 커널은 시스템이 멈춘 것으로 간주하고 **RCU CPU Stall Warning**을 콘솔에 덤프합니다:
- 어느 CPU가 QS를 보고하지 못하고 있는지(`rcu_node->qsmask` 분석).
- 해당 CPU가 커널 어느 함수에서 RCU 락을 잡은 채 멈춰있는지 스택 트레이스(`dump_stack`) 출력.

Tree RCU는 고성능 리눅스 서버에서 락 없는 동시성과 메모리 안전성을 동시에 달성하는 가장 정교한 분산 상태 머신입니다.
