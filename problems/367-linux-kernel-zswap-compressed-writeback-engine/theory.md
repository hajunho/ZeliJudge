# Linux Kernel Zswap (Compressed Writeback Cache) 아키텍처 및 2계층 스왑 메모리 관리 심층 분석

## 1. 개요 및 설계 철학

전통적인 가상 메모리 시스템에서 주 메모리(RAM)가 부족해지면, 커널 페이지 회수 데몬(`kswapd`)은 덜 사용된 익명 페이지(Anonymous Pages)를 디스크의 스왑 파티션(Swap Partition)으로 내보냅니다.

그러나 디스크 I/O는 RAM에 비해 수천 배에서 수만 배 느리기 때문에, 스왑이 빈번해지면 시스템이 멈추는 **스왑 쓰레싱(Swap Thrashing)** 현상이 발생합니다.

리눅스 커널의 **zswap(`mm/zswap.c`)**은 세스 제닝스(Seth Jennings)가 주도하여 Linux 3.11에 머지된 기능으로, 페이지를 디스크에 쓰기 전에 CPU의 암호화/압축 가속 엔진을 이용해 실시간으로 압축한 뒤 메모리 내의 작은 압축 풀에 보관합니다.

## 2. zram과 zswap의 핵심 차이

| 특성 | zram | zswap |
| :--- | :--- | :--- |
| **장치 성격** | 독립적인 블록 디바이스 (`/dev/zram0`) | 기존 물리 스왑 디바이스의 전면 캐시 |
| **백킹 디바이스** | 불필요 (순수 RAM 내 RAM-disk) | **필수 (SSD/HDD 스왑 파티션 필요)** |
| **메모리 고갈 시** | OOM-Killer 강제 호출 | **오래된 엔트리를 디스크로 라이트백(Evict)** |
| **적용 환경** | 안드로이드 스마트폰, 임베디드 기기 | **엔터프라이즈 서버, 클라우드 가상화 머신** |

zswap의 가장 위대한 설계적 장점은 **"풀이 가득 차도 시스템이 죽지 않고, LRU 방식으로 디스크로 자연스럽게 방출(Eviction)된다"**는 점입니다.

## 3. 프론트스왑(Frontswap) 훅과 압축 거부(Rejection)

리눅스 커널의 `include/linux/frontswap.h`는 스왑 하위 시스템에 다음과 같은 훅 인터페이스를 제공합니다:
- `frontswap_store(type, offset, page)`: 페이지가 스왑 디스크로 나가기 직전에 zswap이 먼저 가로챕니다.
- `frontswap_load(type, offset, page)`: 스왑 폴트 발생 시 디스크 I/O 전에 zswap 캐시를 먼저 확인합니다.
- `frontswap_invalidate_page(type, offset)`: 페이지가 해제될 때 zswap 캐시 엔트리를 파기합니다.

### 3.1 압축률 필터링 (`zswap_reject_recompress_poor`)
텍스트, 제로 페이지, 코드 데이터는 압축률이 우수(20~50% 수준)하지만, 이미 압축된 이미지(JPEG, PNG)나 암호화된 버퍼, 고엔트로피 바이너리는 압축해도 크기가 거의 줄어들지 않거나 오히려 헤더 오버헤드로 인해 커질 수 있습니다.
zswap은 압축 후 크기가 원본의 임계치(기본 약 80%)를 초과하면 압축을 포기하고 즉시 `return -EINVAL;`을 반환하여 원본 페이지를 디스크로 직행시킵니다.

## 4. zpool 메모리 할당자 및 디스크 라이트백

압축된 페이지들은 크기가 100바이트부터 3500바이트까지 제각각이므로, 표준 버디 할당기(4KB 단위)를 사용하면 심각한 내부 단편화가 발생합니다.
zswap은 다음과 같은 전용 백엔드 할당기(`zpool`)를 사용합니다:
1. **zsmalloc**: 크기별 슬랩 클래스로 패킹하여 높은 압축 밀도 제공.
2. **zbud**: 4KB 물리 페이지 1장에 최대 2개의 압축 청크를 저장 (단순하고 빠름).
3. **z3fold**: 4KB 페이지 1장에 최대 3개의 압축 청크를 저장.

### 4.1 LRU 기반 스왑아웃 라이트백 루프
풀 사용량이 `max_pool_percent`에 도달하면 `zswap_frontswap_store`는 동기식 또는 비동기식으로 가장 오래된 LRU 엔트리를 꺼냅니다:
1. zswap 엔트리에서 압축 데이터를 읽어 원본 4KB 페이지로 압축 해제.
2. 실제 물리 스왑 디바이스의 `(swap_type, swap_offset)` 위치로 비동기 디스크 블록 쓰기(`__swap_writepage`).
3. zpool에서 해당 엔트리의 메모리를 반환하여 새 압축 페이지를 수용할 공간 확보.

본 시뮬레이션 엔진은 프론트스왑 인터페이스, 압축률 거부, zpool 캐시 히트, LRU 디스크 라이트백 및 무효화 처리를 완벽하게 수리적으로 정식화하여 동작합니다.
