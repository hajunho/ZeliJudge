# Problem 212 심층 이론: 분산 교착 상태(Distributed Deadlock) 탐지와 Chandy-Misra-Haas(CMH) 에지 추적 알고리즘 vs 중앙 집중식 WFG 유령 데드락

## 1. 분산 트랜잭션과 교착 상태의 본질

현대 분산 데이터베이스(CockroachDB, Google Spanner, TiDB, Amazon Aurora Global)와 샤딩된 스토리지 환경에서는 엄격한 직렬 가능성(Strict Serializability)과 데이터 일관성을 보장하기 위해 **분산 2단계 잠금(Distributed 2-Phase Locking, 2PL)** 기법을 광범위하게 사용합니다.

단일 노드 데이터베이스에서는 락 매니저(Lock Manager)가 메모리에 단일한 **대기 그래프(Wait-For Graph, WFG)**를 유지하며, $O(V + E)$의 깊이 우선 탐색(DFS)이나 타잔(Tarjan)의 강결합 컴포넌트(SCC) 알고리즘으로 교착 상태(Deadlock Cycle)를 즉시 감지할 수 있습니다.

그러나 데이터가 여러 샤드(물리 노드)로 분산된 환경에서는 개별 노드의 시야만으로는 결코 데드락을 감지할 수 없는 구조적 사각지대가 발생합니다.

```
[로컬 비순환 DAG(Acyclic)의 결합이 전역 분산 사이클을 형성하는 메커니즘]

    Node 1 (Shard A)            Node 2 (Shard B)            Node 3 (Shard C)
+───────────────────────+   +───────────────────────+   +───────────────────────+
│ Resource R1 (Held: T1)│   │ Resource R2 (Held: T2)│   │ Resource R3 (Held: T3)│
│ Wait Queue: [T3]      │   │ Wait Queue: [T1]      │   │ Wait Queue: [T2]      │
│                       │   │                       │   │                       │
│ Local WFG: T3 ──► T1  │   │ Local WFG: T1 ──► T2  │   │ Local WFG: T2 ──► T3  │
│ (단방향, 사이클 없음)   │   │ (단방향, 사이클 없음)   │   │ (단방향, 사이클 없음)   │
+───────────────────────+   +───────────────────────+   +───────────────────────+

===> 각 노드의 로컬 DB 뷰:
     - Node 1: "T3가 T1을 기다림. 사이클 없음!"
     - Node 2: "T1이 T2를 기다림. 사이클 없음!"
     - Node 3: "T2가 T3를 기다림. 사이클 없음!"

===> 클러스터 전역(Global View):
     T1 (Node 1) ──────────대기──────────► T2 (Node 2)
         ▲                                     │
         │                                    대기
        대기                                   │
         │                                     ▼
     T3 (Node 3) ◄─────────────────────────────┘
     ==> T1 -> T2 -> T3 -> T1 전역 순환 대기 형성! 3개 샤드의 모든 후속 트랜잭션 동결!
```

## 2. 중앙 집중식 WFG 코디네이터의 치명적 한계: 유령 교착 상태 (Phantom Deadlock)

이 문제를 해결하기 위해 가장 직관적으로 떠올릴 수 있는 구조는 하나의 **중앙 코디네이터 노드(Central Coordinator)**를 두고, 각 샤드가 로컬 락 획득/대기/해제 이벤트를 코디네이터로 주기적으로 전송하는 것입니다.

그러나 비동기 네트워크 통신 환경에서 이 방식은 시스템을 파멸로 이끄는 두 가지 치명적 결함을 노출합니다:

### 2.1 네트워크 오버헤드와 단일 장애점 (SPOF)
- 클러스터의 샤드 수 $N$과 활성 트랜잭션 수 $M$이 증가함에 따라, 락 상태 변경마다 코디네이터로 쏟아지는 스냅샷 메시지 트래픽이 $O(N \cdot M)$으로 폭증합니다.
- 중앙 코디네이터 노드에 병목과 장애가 발생하면 클러스터 전체의 데드락 감지가 완전히 마비됩니다.

### 2.2 유령 교착 상태(Phantom Deadlock)의 수학적 발생 원리
비동기 네트워크에서는 메시지 도착 순서가 보장되지 않거나 네트워크 지연(Jitter, Delay)이 발생합니다.
- 시각 $t_1$: 트랜잭션 $T_1$이 $T_2$를 대기 시작 (`ADD_EDGE(T1, T2)` 메시지 발송, 지연 $60\,\text{ms}$)
- 시각 $t_2$: 트랜잭션 $T_2$가 $T_1$을 대기 시작 (`ADD_EDGE(T2, T1)` 메시지 발송, 지연 $60\,\text{ms}$)
- 시각 $t_3$: 트랜잭션 $T_2$가 타임아웃 또는 애플리케이션 로직에 의해 락을 정상 해제함 (`RELEASE_LOCK`, `DEL_EDGE(T2, T1)` 발송, 지연 $60\,\text{ms}$)
- 시각 $t_4$: 코디네이터의 주기적 그래프 검사 틱 도래 ($t_4 = 100\,\text{ms}$)
  - 코디네이터는 이미 도착한 `ADD_EDGE(T1, T2)`와 `ADD_EDGE(T2, T1)`를 그래프에 반영함.
  - 그러나 시각 $t_3$에 발송된 `DEL_EDGE`는 네트워크 지연으로 인해 $t = 130\,\text{ms}$에야 도착함!
  - 코디네이터는 **실제로는 이미 해소되어 존재하지도 않는 가짜 사이클($T_1 \leftrightarrow T_2$)을 감지**하고, 무고한 정상 트랜잭션을 강제 중단(`ABORT`)시킵니다!

이처럼 과거의 왜곡된 스냅샷으로 인해 멀쩡한 트랜잭션이 억울하게 희생되는 현상을 **유령 교착 상태(Phantom Deadlock)**라고 부릅니다.

## 3. Chandy-Misra-Haas(CMH) 에지 추적(Edge-Chasing) 분산 알고리즘

1983년 K. Mani Chandy, Jayadev Misra, Laura M. Haas가 발표한 분산 에지 추적(Edge-Chasing) 알고리즘은 중앙 코디네이터 없이, 오직 노드 간의 국소적 메시지 교환만으로 전역 교착 상태를 100% 정확하게 감지해냅니다.

```
[Chandy-Misra-Haas 프로브 전파 및 사이클 탐지 메커니즘]

1. T1이 Node 2의 T2가 쥔 락을 대기하며 차단(BLOCKED)됨:
   => Node 1이 프로브 생성: probe(init: T1, sender: T1, rec: T2)

2. Node 2가 프로브 수신:
   - 수신자 T2의 상태 확인:
     * 만약 T2가 ACTIVE (작업 중): 프로브 폐기! (교착 상태 없음)
     * 만약 T2가 BLOCKED (Node 3의 T3를 대기 중):
       => 프로브를 대기 에지 방향으로 전진 전파!
          probe(init: T1, sender: T2, rec: T3)

3. Node 3이 프로브 수신:
   - T3가 BLOCKED (Node 1의 T1을 대기 중):
     * T3가 대기 중인 대상 == 프로브의 최초 발신자(initiator: T1)!
     * "자신에게서 출발한 프로브가 닫힌 순환로를 돌아 자신에게 도달했다!"
   ===> 분산 교착 상태(DISTRIBUTED DEADLOCK) 100% 증명 완료!
   ===> Victim Selection 정책에 따라 T3 강제 롤백 및 자원 즉각 해제!
```

### 3.1 프로브 메시지 구조
CMH 알고리즘에서 노드 간에 교환되는 메시지는 3개의 원소로 구성됩니다:
$$\text{probe}(\text{initiator}, \text{sender}, \text{receiver})$$
- **$\text{initiator}$ ($T_i$)**: 락을 얻지 못하고 차단되어 프로브 추적을 최초로 시작한 트랜잭션.
- **$\text{sender}$ ($T_j$)**: 프로브를 다음 노드로 중계 전달한 트랜잭션.
- **$\text{receiver}$ ($T_k$)**: 현재 프로브를 수신하여 대기 여부를 평가받는 트랜잭션.

### 3.2 3대 핵심 규칙 (Rules of Operation)

1. **프로브 개시 (Initiation Rule)**:
   - 트랜잭션 $T_i$가 자원을 요청했으나 $T_j$가 락을 쥐고 있어 대기 큐에 진입할 때:
   - $T_i$의 호스트 노드는 $T_j$의 호스트 노드로 `probe(T_i, T_i, T_j)`를 발송합니다.

2. **프로브 전파 및 단락 (Propagation & Termination Rule)**:
   - 노드 $Q$가 `probe(T_i, T_j, T_k)`를 수신했을 때:
   - 만약 수신자 $T_k$가 현재 **실행 중(`ACTIVE`)**이거나 이미 커밋/롤백되어 대기 중이 아니라면:
     - **프로브를 즉시 폐기(Discard)**합니다. (해당 경로를 통해 작업이 진행되고 있으므로 교착 상태가 아님)
   - 만약 수신자 $T_k$가 여전히 다른 트랜잭션 $T_m$을 기다리며 **차단(`BLOCKED`)** 상태라면:
     - 만약 $T_m == T_i$ 라면: **교착 상태 사이클 감지!**
     - 그렇지 않고 $T_m$이 방문 경로에 없다면:
       - `probe(T_i, T_k, T_m)`을 $T_m$이 위치한 노드로 전진 중계합니다.

3. **유령 데드락 면역성 (Immunity to Phantom Deadlocks)**:
   - 프로브는 매 홉(Hop)을 건널 때마다 **현재 시점의 트랜잭션 활성 상태를 직접 확인**합니다.
   - 중간 트랜잭션이 락을 해제하고 진행 중이라면 프로브가 그 자리에서 폐기되므로, 중앙 코디네이터 방식과 같은 과거 잔여 메시지로 인한 가짜 데드락 오판정이 발생하지 않습니다.

## 4. 희생자 선정(Victim Selection) 및 연쇄 해소

교착 상태가 감지되면 사이클을 끊기 위해 연루된 트랜잭션 중 하나를 희생자(`Victim`)로 지정해야 합니다:

1. **`YOUNGEST` (가장 늦게 시작된 트랜잭션)**:
   - 시작 시각(`start_time`)이 가장 큰 트랜잭션을 선택합니다.
   - 가장 적은 작업(Undo Log)을 수행했을 가능성이 높아 롤백 비용이 최소화됩니다.
2. **`LOWEST_PRIORITY` (최저 우선순위 트랜잭션)**:
   - 비즈니스 중요도가 낮거나 SLA 우선순위 번호(`priority`)가 큰 트랜잭션을 롤백시킵니다.

### 희생자 롤백 후 자원 승계
- 희생자가 보유하던 모든 물리 노드의 락이 즉시 해제(`RELEASE`)됩니다.
- 해당 자원의 대기 큐(Wait Queue)에서 대기하던 후속 트랜잭션이 락을 즉각 승계받아 `ACTIVE` 상태로 전환되며, 전체 클러스터의 파이프라인이 정상 흐름을 되찾습니다.

## 5. 아키텍처 비교 요약

| 비교 항목 | 중앙 집중식 WFG 코디네이터 | Chandy-Misra-Haas 에지 추적 |
| :--- | :--- | :--- |
| **아키텍처 구조** | 중앙 전역 그래프 서버 (SPOF) | 완전 분산 피어투피어 (P2P) |
| **메시지 전송 방식** | 모든 노드가 락 상태마다 주기적 스냅샷 보고 | 대기 발생 시에만 활성 경로를 따라 타겟 프로브 전송 |
| **유령 데드락 취약성** | **극도로 취약** (메시지 지연 시 정상 트랜잭션 오폭) | **면역 (Immune)** (홉마다 실시간 활성 검증) |
| **탐지 지연시간** | 코디네이터 검사 주기(`interval`)에 종속 (수백 ms) | 프로브 네트워크 전파 지연 (수 ms) |
| **네트워크 트래픽** | $O(N \cdot M)$ 지속적 브로드캐스트 | 데드락 사이클 경로 $O(\text{Cycle Length})$ 국소 메시지 |
| **실제 적용 사례** | 소규모 클러스터 연구용 프로토타입 | CockroachDB, TiDB, 분산 2PL 스토리지 엔진 |
