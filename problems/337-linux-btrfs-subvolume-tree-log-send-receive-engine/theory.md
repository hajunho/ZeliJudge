# 리눅스 Btrfs 파일시스템 (fs/btrfs): CoW B-Tree, Tree-Log 및 Send/Receive 이론

## 1. Btrfs 아키텍처와 Copy-on-Write (CoW) 패러다임

리눅스 커널의 **Btrfs(B-Tree Filesystem)**는 오라클의 크리스 메이슨(Chris Mason)에 의해 제안되었으며, ZFS의 스토리지 풀 및 볼륨 관리 개념을 리눅스 기본 GPL 라이선스로 완벽히 구현한 차세대 파일시스템입니다.

전통적인 ext4나 XFS는 블록을 덮어쓰는 제자리 업데이트(In-Place Update) 방식을 취하며, 일관성을 보장하기 위해 JBD2와 같은 별도의 저널링 블록 장치에 이중 쓰기(Double-Write)를 수행합니다.
반면 Btrfs는 모든 수정이 **Copy-on-Write(CoW)** 원칙에 따라 이루어집니다:
- 블록이 수정될 때 기존 블록을 절대 덮어쓰지 않고, 새로운 여유 블록에 수정본을 기록합니다.
- 해당 블록을 가리키는 상위 B-Tree 노드 포인터 또한 CoW되어 새로운 노드로 기록되며, 이 과정이 루트 노드(`root node`)까지 거슬러 올라갑니다.
- 최종적으로 최상위 루트 포인터가 원자적으로 새 위치를 가리키게 됨으로써, 크래시 발생 시에도 파일시스템은 언제나 일관된 이전 상태를 유지합니다.

## 2. 핵심 서브시스템 분석

### (1) 서브볼륨(Subvolume)과 $O(1)$ 스냅샷
Btrfs의 서브볼륨은 독립된 파일시스템 루트 트리를 가집니다:
- 일반 디렉터리처럼 마운트하거나 접근할 수 있지만, 고유한 inode 공간과 파일 트리(`FS_TREE`)를 보유합니다.
- **스냅샷(Snapshot)**은 원본 서브볼륨 트리의 루트 포인터를 복제하는 것에 불과합니다.
- 원본과 스냅샷은 물리 디스크 상의 모든 데이터 블록과 메타데이터 노드를 100% 공유합니다.
- 원본이나 스냅샷 어느 한쪽에 쓰기가 발생하면, 수정된 블록만 분기(CoW Divergence)되어 새로운 블록을 차지하므로 스냅샷 생성 비용은 디스크 I/O 없이 $O(1)$ 시간에 완료됩니다.

---

### (2) Tree-Log (Log Tree): fsync 지연 시간 최소화 (`fs/btrfs/tree-log.c`)
CoW 파일시스템의 치명적인 단점은 단 1바이트를 수정하더라도 트리 루트까지 상향 전파되어 슈퍼블록 플러시까지 이어지는 '커밋 증폭(Commit Amplification)'입니다. 데이터베이스(PostgreSQL, SQLite)나 메시지 큐(Kafka)처럼 빈번하게 `fsync()`를 호출하는 애플리케이션에서는 전체 트랜잭션 커밋을 수행할 경우 초당 수천 개의 트랜잭션을 감당할 수 없습니다.

이를 해결하기 위해 Btrfs는 **Tree-Log(Log Tree)**를 도입했습니다:
1. 파일이 수정되고 `fsync()`가 호출되면, 전체 트랜잭션을 커밋하지 않고 서브볼륨에 할당된 가벼운 임시 트리인 Tree-Log에 해당 파일의 변경 내역(inode 항목, 수정된 익스텐트 참조)만을 기록합니다.
2. Tree-Log의 루트 블록만 디스크에 안전하게 플러시하고 `fsync()`는 즉시 반환됩니다.
3. 시스템이 정상 운영되는 동안 일정 주기(기본 30초)마다 거대한 본 트랜잭션 커밋(`btrfs_commit_transaction`)이 실행되며, 이때 모든 변경 사항이 본 트리에 영구히 흡수되고 Tree-Log는 폐기됩니다.
4. 만약 본 트랜잭션 커밋 전에 전원이 차단되면, 다음 마운트 시 `btrfs_recover_log_trees`가 실행되어 Tree-Log의 엔트리를 본 트리로 신속하게 재생(Replay)함으로써 무손실 내구성을 보장합니다.

---

### (3) Send / Receive: B-Tree 차분 기반 증분 백업 (`fs/btrfs/send.c`)
기존의 파일 백업 도구(`rsync`, `tar`)는 수백만 개의 파일을 순회(`stat`)해야 하므로 파일시스템 탐색에만 수십 분이 소요됩니다.
Btrfs의 **Send/Receive**는 파일 메타데이터 탐색을 건너뛰고 **B-Tree의 세대 번호(Generation)와 키 순서**를 직접 비교합니다:
- 부모 스냅샷 $S_1$과 자식 스냅샷 $S_2$가 주어졌을 때, Btrfs 커널 드라이버는 두 트리를 동시에 순회하면서 차이가 있는 B-Tree 리프 노드만을 신속히 찾아냅니다.
- 변경 사항을 바이트 단위 TLV(Type-Length-Value) 명령 스트림으로 직렬화합니다:
  - `BTRFS_SEND_CMD_WRITE`: 새로 쓰여진 데이터 블록.
  - `BTRFS_SEND_CMD_CLONE`: $S_1$에 이미 존재하는 블록을 그대로 재사용하라는 지시 (네트워크 전송량 제로).
- 수신자(`btrfs receive`)는 이 스트림을 실행하여 원격지 스토리지에 바이트 단위로 동일한 스냅샷을 초당 수 기가바이트 속도로 복원합니다.
