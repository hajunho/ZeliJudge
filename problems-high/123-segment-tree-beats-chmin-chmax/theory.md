# 상한을 두들겨 구간을 길들여라! 세그먼트 트리 비츠 (Segment Tree Beats)

## 핵심 개념 및 알고리즘 개요
- **태그**: 자료구조, 세그먼트 트리 비츠(Segment Tree Beats), 구간 chmin, 구간 합, 역사적 최댓값, $O((N+Q) \log N)$
- **핵심 요약**: 구간 내 모든 원소를 $A_i = \min(A_i, x)$로 갱신하는 구간 chmin 질의와 구간 합 질의를 로그 시간에 처리합니다.

---

### 세그먼트 트리 비츠 (Segment Tree Beats / Ji Driver's Segment Tree)

일반적인 Lazy Propagation으로는 "구간의 모든 원소에 대해 $A_i = \min(A_i, x)$ 취하기"와 같은 비선형 갱신을 효율적으로 다룰 수 없습니다.
**세그먼트 트리 비츠(Segment Tree Beats)**는 각 노드에 최댓값과 두 번째 최댓값을 유지하여 불필요한 분기를 상각 로그 시간에 쳐내는 기법입니다.

1. **노드에 관리하는 정보**:
   - `max1`: 서브트리의 최댓값
   - `max2`: 서브트리에서 `max1`보다 엄격히 작은 값들 중 최댓값 (없으면 $-\infty$)
   - `cnt_max`: `max1`의 개수
   - `sum`: 서브트리의 원소들의 합

2. **구간 chmin(x) 갱신 조건**:
   - **Case 1 ($x \ge max1$)**: 구간 내 모든 원소가 이미 $x$ 이하이므로 아무 작업도 하지 않고 즉시 리턴(Pruning).
   - **Case 2 ($max2 < x < max1$)**: 오직 최댓값(`max1`)들만 $x$로 변경되고 나머지 원소들은 영향을 받지 않음!
     - `sum += (x - max1) * cnt_max`
     - `max1 = x`
     - 자식 노드로 내려가지 않고 Lazy 태그를 걸어 즉시 리턴.
   - **Case 3 ($x \le max2$)**: 최댓값뿐만 아니라 두 번째 최댓값 이하의 원소들도 변경되므로, 두 자식 노드로 재귀 분기(Recursion).

3. **복잡도 증명**:
   - Case 3으로 분기할 때마다 구간 내의 서로 다른 원소 값의 개수가 최소 1개씩 감소합니다.
   - 전위 순회 상각 분석을 통해 $Q$개의 쿼리를 처리하는 총 시간 복잡도는 **$O((N + Q) \log N)$**임이 증명되어 있습니다.

---

## 복잡도 분석
- **시간 복잡도**: 본문 이론 및 구현 참조
- **공간 복잡도**: $O(N)$ 또는 $O(V + E)$
